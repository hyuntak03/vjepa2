## 3-1. 고친 것 (사용자 2026-10-25 "경사면 끝이 지면이랑 붙어 있는 경우도 … 점프대가 살짝 어색")

  ramp_kicker 는 경사 윗면 35~50 % 자리에 붙은 쐐기 (경사에 대해 22~40°, 길이 0.5~0.8 m). 위로 꺾인 판 + 받침 상자 (어색했던 것) 는 지웠다.

## 3-4. 가림 4 종 (사용자 2026-10-25 "고정된 가림막을 물체가 통과 · 더 큰 물체가 작은 물체 앞으로 지나감 · 가림막이 올라갔다 내려옴 · 가림막이 움직여서 가려짐 … 가림막도 다양하게")

어느 시나리오에나 얹는 층 (`PHYS3D_OCC=fixed|front_object|rise_lower|sweep|random|none`, 기본 none). 가림막은 충돌이 없어 물리가 같다 —
가림 없이 시뮬한 궤적에서 주 물체가 화면 안에 있는 시각 t* 를 고르고 (fixed 는 움직이는 시각만) 카메라 → 물체 선이 가림 평면과 만나는 자리에 놓은 뒤 보임만 다시 잰다.

| 모드 | 무엇 |
|---|---|
| fixed | 바닥에 선 판 (발 둘) 이 t* 의 물체 앞에 내내 서 있다. 폭 = 보이는 물체 폭 × 1.3~3.2 (0.35~2.8 m), 20 % 는 좁고 높은 기둥 |
| front_object | 큰 물체 (크기 0.6~1.0 × 1.6 m, 모양 · 색은 물체 분포) 가 카메라 쪽 길 (y = −2.3) 을 등속 0.8~4 m/s 로 화면 밖 → 화면 밖. 둥근 것은 굴러가는 각도까지 |
| rise_lower | 판이 바닥 밑에서 4~8 장에 올라와 8~30 장 서 있다 내려간다 (t* 를 덮게) |
| sweep | 판이 화면 한쪽 밖에서 다른 쪽 밖으로 0.6~3 m/s (로그 균등) 로 지나가며 t* 에 물체 앞 |

- 가림막 겉: 한 색 35 % · 체크 25 % · 줄무늬 20 % · 어두운 판 20 % (채도 0~0.35), 두께 0.04~0.16 m.
- 검사: 안 보임 (vis ≤ 0.3) 연속 ≤ 36 장 (3 장마다 1 장에서 잼) · 최소 3 장 가려짐 · 끝나기 전 다시 보임. 실패하면 다른 t* 로 10 번.
- ⚠️ 정정 — front_object 를 처음엔 rigid body (마찰 0) 로 굴렸는데 옆벽에서 되튕겨 왔다 갔다 하거나, 충돌 묶음을 바꾸니 멈추거나 위에서 떨어졌다 →
  키프레임 등속 이동 (rigid body 없음, 다른 물체와 닿지 않는 길) 으로 바꿨다. 라벨에는 물체로 들어간다 (`role = front`, mass 0).
- 샘플 48 편 (모드 4 × 시나리오 6 × 2, GPU): `/workspace/dataset/training_data/phys3d_multi_occ_samples_v0/<모드>/<시나리오>/*.mp4`, 미리보기 `sheets/<모드>__<영상>.png`
  (영상 전체를 16 칸으로). 가려진 장 (hidden 라벨) 비율: fixed 12.5 % · front_object 7.6 % · rise_lower 14.2 % · sweep 9.0 %, 영상당 중앙 4~10 장.
- ⚠️ 첫 미리보기는 앞 64 장만 보여 줘 front_object 가 안 지나가는 것처럼 보였다 (라벨로 확인: 59~85 장에 지나감). 미리보기를 영상 전체로 고쳤다.

## 3-7. 문맥 끝 고정 · 4 fps 64 장 (generate2, 기본) — 사용자 2026-10-25

> "3 stride 로 샘플링 … 문맥 C · 예측 K ∈ {2, 4, 8, 16, 32} … 문맥 C 마지막에 가려지도록 … 가려지는 타이밍이 … 분포 균등 … 사건의 시작 (ledge 등) 도 문맥 끝에" ·
> "애초에 4 fps 로 64 프레임" · "C 가 2 나 4 면 그냥 넘어가야지. 대신 문맥 진행 중에도 가려지는 거" · "절반은 사건 근처로 … 이후 사건이 어떻게 진행됐는지는 보이도록" ·
> "충돌 같은 건 이전에 일어나도 되는데 context 8, 16, 32 에선 가려지는 걸 넣던가 … 여러 단계 코스도 괜찮고 … 최대한 fair 하고 make sense 하게"

- 영상 = 저장 64 장 (4 fps = 렌더 192 장을 3 장마다, `frame_step 3`). 물리 · 사건 검출은 12 fps (120 Hz 부분 단계). 라벨은 저장 장에서 속도를 다시 미분 (단위 = 저장 장당).
- 영상마다 C* — **작업 k 로 층화** `C_SET[k mod 5]` (시나리오마다 모든 C 가 같은 수 → C 별 시나리오 구성이 같다). 앵커 (문맥 끝):
  - C* ≤ 4: `event` (사건이 저장 장 C* = 예측 첫 장) · `occ_event` (문맥 마지막 장 C*−1 에 가려지기 시작, 가려진 동안 사건, 사건 뒤 다시 보임) · `occ_any` 1/3 씩
  - C* ≥ 8: `occ_event` · `occ_any` 반반 — 충돌 같은 사건은 문맥 안에서 먼저 일어나도 된다. occ_event 를 못 하면 occ_any (meta `anchor_asked` 에 원래 뜻)
- 앞을 넉넉히 시뮬 (330 장) 한 뒤 영상 시작을 (앵커 − 3 C*) 로 잘라 맞춘다 — 첫 장부터 이미 움직인다 (공중 붙잡기 없음).
- C* ≥ 8 이면 50 % 로 **문맥 진행 중 가림** 하나 더 (C*−3 장 전에 끝남, 앵커 경계 그대로).
- 공정성 (모든 C 같게): 앵커 때 주 물체가 움직이는 영상 80 % · 멈춘 것 20 % (`want_move`, 멈춘 것은 고정 판 말고 다른 가림) · 문맥 안 장면 정지 ≤ 50 %.
- 장면을 길게: **나중에 들어오는 물체** (`arrivals`) — 영상의 60 % 에 1~3 개가 화면 위 밖 (z 6.5) 에서 기다렸다가 아무 시각에 놓여 떨어져 들어온다 (놓는 장 unpred). 코스 4 개 (marble_run · course · half_pipe · billiards).
- 행: 앵커 행 (boundary C*, ctx_start 0, `anchor`, `pred_min` = 다시 보일 때까지 필요한 예측 장) + 그 밖 사건 행 (저장 장 단위).
- 실측 (첫 판, 공정성 조건 전, 라벨 310 편): C 2 → 32 에서 앵커 때 움직임 100 → **7 %**, 문맥 속력 중앙 2.29 → **0.11 m/s**, 정지 55~64 %, occ_event 요청의 88 % 가 occ_any 로.
  물리만 잰 표 (29 시나리오 × 24): 문맥 끝에 사건이 올 수 있는 비율 C 2 / 4 / 8 / 16 / 32 = 46 / 32 / 13 / **2 / 0 %** — 장면이 대부분 2~10 초에 멈춘다.
  → 공정성 조건 · arrivals · 코스 4 개를 넣었다 (§3-8 에 다시 잰 결과).
