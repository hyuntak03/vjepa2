# 결과 정리 — IntPhys2 위반 라벨 평가 · post-FT · 상태 판독기 진단 (2026-10-22 ~ 10-24)

> **질문** 블록 AR 은 왜 움직이는 물체를 옮겨 그리지 못하나, 무엇을 붙이면 VOBench · IntPhys1 · IntPhys2 가 같이 오르나.
> **답 (지금까지)** 입력에는 속도가 담겨 있지만 굴린 예측에서는 사라지고, 물체는 마지막으로 본 자리에 머문다. 보조 판독기 손실은 영속은 올리지만 운반은 만들지 못했다.
> **다음** 운반을 직접 겨냥한다 — 합성 batch 에서 정답 물체 칸의 latent 손실 가중 · 칸 이동 복사 출력.

## 용어

| 용어 | 뜻 |
|---|---|
| 블록 | 연속 프레임 2 장. 블록 AR 은 블록 단위로 미래를 예측한다 |
| 정답 토큰 | 블록 하나를 고정 encoder 에 넣고 LN 한 것, shape (256, 1280). 블록 AR 의 입력이자 채점 타깃 |
| 예측 토큰 | predictor 가 만든 미래 블록, shape (256, 1280) |
| TF 한 걸음 | 정답 과거를 모두 보고 다음 블록 하나만 예측한 것 |
| 굴린 예측 | 자기 예측을 되먹여 여러 블록을 이어 예측한 것 (채점과 같은 방식) |
| 운반 이득 | 예측 물체 변위 ÷ 실제 변위. 1 = 정확히 옮김, 0 = 제자리. 파라미터 없는 읽기 (마지막 문맥 물체 모양과 cosine) |
| 상태 판독기 (head) | 블록 토큰에서 물체 정체 · 위치 · 속도를 읽는 작은 attention 모듈 (query 1 개 → 1280 차원 → 선형 3 개) |
| 옛 자리 | 문맥 마지막 블록에서 물체가 있던 칸 |
| 위반 시작 | IntPhys2 불가능 영상에서 사람이 표시한 위반이 시작되는 프레임 |

## 1. IntPhys2 위반 라벨 평가 (16 / 16)

**왜** IntPhys2 공식 채점은 고정 창이라 위반 시점과 문맥 경계가 맞지 않는다. 위반 직전까지를 문맥으로 주면 predictor 가 실제로 위반을 잡는지 볼 수 있다.

**어떻게** 사람이 단 위반 시작 d 로 문맥 = [0, d−1] 균일 16 장, 미래 = [d, 끝] 균일 16 장. 라벨 시트 값 − 10 프레임, continuity · SphereFallingDown pair 1 의 7 개는 프레임을 보고 직접 정했다 (시트 값이 40~100 프레임 늦었다). pair 둘 다 라벨이 있으면 각자, 하나만 있으면 공유. 500 쌍. 원본 mp4 에서 프레임 번호로 바로 읽는다.

**결과** [측정] (쌍 정확도, 우연 50)

| 모델 | 전체 500 쌍 | permanence | immutability | continuity | solidity |
|---|---:|---:|---:|---:|---:|
| release | 51.8 | 53.3 | 55.1 | 49.2 | 50.0 |
| AR | 51.4 | 46.7 | 51.7 | 51.7 | 54.9 |
| AR + 3D 감독 | 52.0 | 49.2 | 50.0 | 54.2 | 54.2 |
| release + VOBench post-FT (20 ep) | 54.0 | 59.2 | 51.7 | 57.5 | 48.6 |

- 라벨 −10 전 (원래 값) 은 release 54.6 · AR 53.2 · 3D 감독 55.2 였다. 늦은 라벨은 가능 영상 문맥에 물체가 이미 다시 나와 점수를 부풀린다 [추측]
- mp4 직독과 PNG 판은 축소 방식 차이로 500 쌍 중 67 쌍이 뒤집힌다 → **±1 점은 잡음**

## 3. 진단 — 속도는 어디서 사라지나

### 3-1. 문맥에서 배운 속도 판독기를 예측에 씌운다 [측정]

phys3d 검증 (학습에 안 쓴 3D 합성), 블록마다 속도 (vx, vy) 를 선형으로 읽는다. R², 시험 clip 163 개.

| 학습 → 시험 | 물체 자리 3×3 | 화면 전체 |
|---|---:|---:|
| 문맥 → 문맥 | 0.79 | 0.59 |
| 문맥 → 실제 미래 (대조군) | 0.65 | 0.14 |
| 문맥 → 굴린 예측 | −0.20 | −0.66 |
| 굴린 예측 → 굴린 예측 (자기 판독기) | **0.05** | 0.00 |
| TF → TF (자기 판독기) | 0.40 | 0.17 |

입력에는 속도가 있는데 굴린 예측에는 거의 없다. 3D 감독 모델도 같다.

### 3-2. 기존 감독 판독기는 예측에만 맞춰진 코드를 읽었다 [측정]

예측 토큰에서 함께 학습한 attention 판독기를 정답 토큰에 씌우면 위치 오차 102~110 px (예측에서는 7~14 px). 굴린 예측에서 판독기는 정답 물체 칸을 보지 않았다 (attention ×256 = 0.0).

### 3-3. 정답 토큰으로 학습한 판독기 [측정]

학습 clip 400 개의 정답 토큰 (문맥 + 미래, 보이는 블록 7,416 개) 으로 학습 → 처음 보는 clip.

| 입력 | 보임 | 다시 나타남 | 가림 |
|---|---|---|---|
| 정답 토큰 | 20 px · 물체 칸 ×2.7 | 21 px | 40 px (못 읽음) |
| AR 굴린 예측 | 118 px | 109 px | 103 px |
| 3D 감독 굴린 예측 | 72 px | 74 px | 66 px |

판독기는 목표로 쓸 만하고, AR 예측은 그 방식으로 상태를 담지 않는다. 가려진 블록은 정답 토큰에도 정보가 없다 [이론] → 손실은 보이는 블록에만.

### 3-4. 물체 자리만 채점 [측정] (AR / 2D 감독 / 3D 감독)

| | 3×3 | 5×5 | 9×9 | 화면 전체 | 먼 배경 |
|---|---:|---:|---:|---:|---:|
| VOBench late (우연 50) | 57.6 / 58.3 / 58.8 | 58.3 / 59.5 / 60.0 | 69.7 / 67.6 / 66.4 | 76.4 / 75.0 / 73.8 | 74.3 / 73.8 / 72.7 |
| VOBench gravity (우연 37) | 25.0 / 27.8 / 32.4 | 31.5 / 31.5 / 36.6 | 17.6 / 19.9 / 23.6 | 15.3 / 13.9 / 16.2 | 9.7 / 9.3 / 13.0 |

late 는 물체 칸만으로는 우연 근처, gravity 는 물체 칸으로 좁힐수록 오른다 (배경이 정답을 가린다). 3D 감독이 gravity 에서 가장 높다.

### 3-5. AR 이 같은 칸을 베끼는 이유 (기록: `CTXT_VS_BLOCK_MECHANISM_2026-10-21.md`)

새 자리 query 가 자기 칸에 attention 0.42, 옛 자리 0.09 → 마지막 블록을 칸별로 베낀다. 운반 이득 첫 걸음 0.29. 3D 합성만으로 학습하면 같은 구조가 0.72 를 옮긴다 → **못 옮기는 게 아니라 자연 영상 L1 이 옮기기를 거의 보상하지 않는다** (문맥 움직임을 이어 가도 L1 이득 0.2~0.5 %, auto_research) [측정 + 추측].

## 4. 학습 시도

### 4-1. 평균 풀링 판독기 (중단, epoch 57/70)

판독기 모으기만 attention → 블록 토큰 평균. VOBench late 72~75 로 기존 3D 감독과 같은 범위 [측정]. 사용자 결정으로 중단.

### 4-2. 정답 토큰 판독기 (gthead, 학습 중)

**왜** 판독기가 예측 쪽 코드를 따로 배우는 우회를 막는다.

**어떻게** 판독기는 정답 토큰에서만 학습 (판독기만 갱신), predictor 는 고정된 그 판독기로 자기 예측에 손실 (predictor 만 갱신), 보이는 블록만. 나머지는 3D 감독과 같다 (scratch 70 epoch).

**결과** [측정]

| epoch | 8 | 9 | 10 |
|---|---:|---:|---:|
| 3D 감독 VOBench late | 67.4 | 68.8 | 69.2 |
| gthead | 57.9 | 62.7 | 66.2 |

- 영속은 따라잡았다 (e10 realistic 90.3 vs 88.9). 모양 · 색은 55~57 그대로
- 학습 중 같은 판독기 위치 오차: 정답 토큰 16 px · TF 16 px · 굴린 예측 18 px
- **epoch 8 판독 검사 (1 칸 넘게 움직인 블록)**: 굴린 예측에서 판독기 attention 최대 칸이 **옛 자리에서 11~12 px**, 정답 자리에서 38 px, 8 걸음 내내 그대로 → **물체를 마지막 자리에 유지하고 옮기지 않는다**. 운반 이득 0.09
- ⚠️ **정정** — epoch 4 검사에서 "굴린 예측에서 판독기가 물체가 아닌 곳에 적힌 코드를 읽는 우회" 라고 썼다. 정답 칸만 보고 내린 해석이었고, 옛 자리를 같이 보니 판독기는 제자리에 남은 물체를 정상적으로 읽고 있었다. **철회**
- 위치 손실이 predictor 에 거의 안 닿는다: 위치 손실 0.044 × 가중 0.05 = 0.002 vs latent L1 1.145. 학습 창 대부분은 물체가 거의 안 움직여 제자리 예측도 오차가 작다
