# 합성 학습셋 설계 원칙 (2026-10-25)

> **상위 문서 (2026-10-26)**: `z_training/docs/DATA_DESIGN_PRINCIPLES_2026-10-26.md` — 데이터가 최적을 정한다 (물리적인 흐름이 그 상황의 흔한 결과가 되는 데이터 · 초 단위 지속률 검사). 이 문서는 장면을 만드는 세부 규칙과 그 근거로 남는다.

predictor 를 synthetic 물리 영상으로 학습할 때 데이터를 어떻게 만드는가. **새 합성 학습셋 (phys2d · phys3d · 그 다음) 을 만들 때 먼저 이 문서를 본다.**
각 원칙에 어디서 나왔는지 (사용자 지시 · 실측) 를 붙였다. 원칙을 바꾸면 지우지 말고 `⚠️ 정정 —` 으로 남긴다.

사용자 (2026-10-25): "이런 거 다 training set 설계 원칙으로 해서 좀 기록을 해 줘".

## 1. 장면이 물리적으로 말이 되어야 한다

| 원칙 | 근거 |
|---|---|
| **물체가 받침 없이 공중에 떠 있으면 안 된다.** 놓기 전 붙잡아 두는 구간은 면 위에 놓거나 · 바닥에서 던지거나 · 보이는 막대로 매단다 | phys3d_single_v2 train 의 drop_* · shelf_land · ramp_roll 86~91 % 가 12 장 넘게 떠 있었다. 사용자 "처음에 왜 공중에 떠 있음…? 이상하잖아" (2026-10-23) → v3 (`PHYS3D_SINGLE_V3_DATASET_2026-10-23.md`) |
| 선반 · 탁자 · 공중 블록에는 다리 · 받침, 진자 축은 보이는 보에 건다. **받침이 카메라에서 보이는지** 렌더로 확인한다 (카메라 쪽을 향한 팔은 안 보여 축이 떠 보였다) | phys3d_multi (2026-10-25) |
| 경사로는 끝이 바닥에 붙은 것과 떠서 받침 있는 것 둘 다 | 사용자 "경사면 끝이 지면이랑 붙어 있는 경우도 있어야지" (2026-10-25) — 50 % (ramp_kicker 60 %) |
| 점프대는 회전한 판이 아니라 쐐기 (삼각 단면) | 사용자 "점프대가 살짝 어색하네" (2026-10-25) |
| **가림막도 공중에 뜨지 않는다** — 바닥에 서 있거나 (발) 바닥 밑에서 올라온다. 장면 안 물체를 가리는 큰 물체는 화면 밖에서 들어와 화면 밖으로 나간다 | phys3d_multi 가림 (2026-10-25) |
| 사라짐 · 순간이동 같은 비물리 사건을 장치로 쓰지 않는다 (받침을 없앨 때도 화면 밖으로 빼거나 보이게 움직인다) | v3 막대는 놓는 순간 위로 빠져 3 장 안에 화면 밖 |
| 예측 못 하는 개입 (놓기 · 가림막 출발) 은 `unpred` 에 넣어 예측 구간이 넘지 않게 한다 | phys3d_single v2 · v3 |

## 2. 보여 줄 게 있어야 한다 — 정지 · 안 보임은 상한을 둔다

| 원칙 | 근거 |
|---|---|
| 장치가 움직이기 전 대기 (수레 출발 등) 도 짧게 — 0~5 장 | moving_platform 0~24 장 대기는 정지 17~65 % |
| **장면 전체가 멈춘 장 비율이 높으면 안 된다.** 멈춘 뒤 1 초 (12 장) 만 남기고 자르고, 4 초보다 짧으면 다시 만든다 | 사용자 "정지해 있는 프레임 비율이 너무 높아선 안 돼" (2026-10-25). phys3d_multi 샘플: 50.3 % → 15.5 % (`PHYS3D_MULTI_DATASET_2026-10-25.md` §3-2). v2 · v3 single 은 64.5 · 57.9 % 로 높았다 |
| 물체가 오래 안 보이는 구간 (가림 · 화면 밖) 에 상한. **상한은 학습이 실제로 보는 장 (stride 를 적용한 장) 에서 잰다** | v1 single 은 상한이 없어 59 장 내리 가려진 영상 (사용자 "처음부터 다 가려져 있는데 뭘 맞춰야 돼"). v2 는 12 fps 로 쟀는데 3 장마다 보면 끊김이 빠져 상한이 샜다 (v3 문서 §2-1) |
| 문맥이 통째로 안 보이는 창을 만들지 않는다 (C16 문맥 전부 안 보임 ≈ 0 %) | v3 시험 0.0 % |
| 거르기는 창 단위가 아니라 영상 단위로 — 창 단위는 블록 자리 편향을 만든다 | phys3d_single_v1 거르기 (`PHYS3D_SINGLE_DATASET_2026-10-19.md` §4-1): 창 단위는 문맥 18 % · 예측 끝 28 % 가림 |

## 3. 사건이 예측 구간에 오게, 그리고 영상 곳곳에

| 원칙 | 근거 |
|---|---|
| 전환 (충돌 · 이탈 · 가려짐) 은 **예측 구간 첫머리** 에 — 문맥이 사건 직전에서 끝난다 | 2026-10-18 결정, 사용자 2026-10-21 "event transition 을 prediction start 구간으로" |
| 가려짐 행은 문맥 끝이 가려진 채 끝나고 예측 안에서 다시 나와야 한다 (`pred_min`) | 사용자 2026-10-21 |
| 문맥 C · 예측 K 를 자연 영상과 같게 (2 · 4 · 8 · 16 · 32, stride 3 = 4 fps) 쓸 수 있게 길이를 잡는다 | 사용자 2026-10-21. ⚠️ 정지 장을 잘라 영상이 짧아지면 긴 창 (C32 + K32 = 렌더 192 장) 은 줄어든다 — 창 크기와 같이 정할 것 |
| 사건 시각이 영상 첫머리에 몰리지 않게 | v1 single 은 stride 3 에서 C16 사건 창 ≤ 110 · K32 0 |

## 4. 다양성 — 축을 넓게, 단 한 축이 다른 축과 얽히지 않게

| 축 | 지금 범위 (phys3d_multi) | 근거 |
|---|---|---|
| 모양 | 18 종 (sphere · cube · cuboid · cylinder · disc · cone · pyramid · tetra · hex_prism · icosa · ellipsoid · torus · tri_prism · pent_prism · octa · capsule · rounded_cube · bicone) | 사용자 "모양이나 색은 더 많이 해도 괜찮을 것 같아" |
| 색 | HSV 연속 (s 0.3~1, v 0.35~1) + 8 % 무채색 · 30 % 두 색 무늬 (체크 · 줄무늬) | 같음 |
| 크기 | 로그 균등 0.27~0.8 (× 1.6 m), 256 px 에서 약 15~45 px | 사용자 "작은 것도" → 첫 최소 0.18 의 1.5 배로 (사용자 지시) |
| 속도 | 초속도 × 0.6~2.2 (로그 균등) | 사용자 "빠른 것도 있어야 됨" |
| 중력 | 2~16 m/s² (로그 균등) | 사용자 "천천히 떨어지는 거 빨리 떨어지는 거" |
| 포물선 꼭대기 | 오르는 높이 0.2 m ~ 화면 위 근처 고르게 (세로 초속도 = √(2gh), 속도 배율은 수평에만) | 사용자 "최고점 높은 거랑 낮은 거 … 범위 넓게" |
| 질량 · 마찰 · 반발 | 밀도 0.5~2 배, 마찰 · 반발 무작위 | — |
| 물체 수 | 1~5 | 사용자 "물체 2 개 또는 다중 물체가 충돌" |

- **축이 많아질수록 서로 얽히지 않는지 본다** (사용자 "지금 벌써 축이 엄청 많은 거 같은데"). 예: 가림 비율이 속력 · 정지 여부와 얽히면 "가려짐 = 멈춤" 지름길이 생긴다 — audit 의 속력별 P(가려짐) 를 본다 (v2 시험에서 고정 판 + 상한 → 멈춘 장 3.6 % 만 가려짐).
- 정체 (모양 × 색) 는 시나리오에 고르게 — 정체를 층화하고 실패하면 같은 정체로 seed 만 바꾼다 (single v1~v3).
- 표본이 작은 시험에서 정체 · 모양별 차이가 크게 나오면 먼저 표본 효과를 의심한다 (v2 시험 모양 폭 36~50 % → train 34.7~38.3 %).

## 5. 시나리오

- **상황을 최대한 많이** (사용자 2026-10-25 "training set 에서 상황 엄청 많이 넣으려고") — 이전 세트 (phys3d_single · v1) 의 상황도 빠짐없이 옮긴다. 요청된 사건 유형을 하나씩 시나리오로 (phys3d_multi 23 개, 처음 16 개: ledge · 자유 낙하 · 포물선 · 평면 등속 · 감속 · 경사 내리막 (가속) · 오르막 (감속) · 평면 점프대 ·
  경사 점프대 · 경사 → 벽 · 경사 위 충돌 · 선반에 멈춤 · 2 개 충돌 · 다중 충돌 · 계단 · 탁자 → 선반; 더한 7 개: 진자 · 통 · 장애물 튕김 · 위로 던짐 · 벽 튕김 · 쌓기 무너짐 · 도미노; 다시 더한 6 개: 블록 쌓기 · 탑 무너짐 · 시소 · 구덩이 · 진자 둘 · 움직이는 받침 — 모두 29 개).
- 가림막 없는 판을 먼저 만들고, 가림은 그 위에 얹는다 (사용자 2026-10-25 "일단 가림막 없는 버전으로").
- 충돌 시나리오는 실제로 닿았는지 검사하고, 아니면 다시 만든다. **검사는 그 시나리오의 사건 자체를 본다** — 시소처럼 장치를 거쳐 주고받으면 "닿음" 이 아니라 "떠오름" 으로 (처음엔 닿음으로 걸어 평균 10.8 번 다시 만들었다). 다시 만드는 횟수가 크면 검사가 사건과 안 맞는다는 신호다
- 가림은 시나리오 위에 얹는 층 4 종 (고정 판 통과 · 앞으로 큰 물체가 지나감 · 판이 올라왔다 내려감 · 판이 지나감). 가림이 실제로 일어났는지 (최소 3 장) · 끝나기 전 다시 보이는지 검사한다.
- 미리보기는 영상 전체를 덮게 뽑는다 — 앞부분만 보면 잘못 판단한다 (front_object 를 안 지나간다고 볼 뻔했다).

## 6. 만드는 순서와 비용

| 원칙 | 근거 |
|---|---|
| **샘플 몇 편을 뽑아 경로를 알려 주고, 눈으로 본 다음** 대량 생성 | 사용자 2026-10-25. v2 는 단서로 적어 둔 "떠 있음" 을 그대로 16 시간 렌더했다 |
| 라벨만 시험 (렌더 생략, 몇 분) 으로 분포를 먼저 재고, 렌더 시험으로 속도를 잰다 | v2 · v3 · multi |
| **학습이 쓰는 장만 렌더한다** (stride 3 이면 3 장마다 1 장, 저장도 4 fps) | 사용자 "렌더 시간 왜 이리 오래 걸려" → v3 2.2 배 빠름 (영상당 고정 비용 ~130 초 때문에 3 배는 안 됨) |
| CPU 와 GPU 를 같이 쓴다. GPU (Cycles OptiX) 는 편당 1 분 안 | 사용자 "cpu 랑 gpu 많이 써서" (2026-10-25). ⚠️ 다른 작업이 GPU 를 쓰는 중이면 그 작업을 늦춘다 — 대량 생성 전에 알린다 |
| 승인한 작업은 끝까지 한다 — "진행해" 는 대량 생성까지 | v3 에서 시험 뒤 다시 묻느라 하루를 버렸다 (2026-10-24) |
| **요청한 모든 축 (가림 종류 · 시나리오 · 배경) 이 실제 산출물에 나오는지 audit 표로 센다** — 검사가 특정 종류를 조용히 버릴 수 있다 | phys3d_multi v1 첫 완성본에 front_object 가림 0 개 (검사가 앞 물체의 화면 밖을 실패로 셈) — 19,800 편을 다시 만들었다 |
| 장면 안 장치 (가림 물체 · 수레 · 판) 는 주 물체용 검사 (화면 밖 · 방 밖 · 접촉) 에서 뺀다 | 같음 |
| 대량 생성은 라벨 (CPU) 과 렌더 (GPU, 오래 사는 워커 몇 개) 를 나눈다. 시도마다 무거운 설정 (렌더 장치 조회) 을 하지 않는다. 느리면 먼저 cProfile | multi v1: 분당 13.6 → 라벨 17 분 + 렌더 ~50 분 |
| 재현: 같은 seed → 같은 라벨 (표본 점 순서 정규화), val 지문을 기준으로 저장 | single v1 sphere 표본 점 비결정성 수정 (2026-10-19) |
