# 영상 문맥 vs 블록 문맥 — predictor 의 어디서 운반이 갈리나 (2026-10-21)

> 사용자 질문: "context video 와 context block 의 차이가 뭐고, 학습된 predictor 가 어디서 어떻게 달라서 다른 behavior 를 내나.
> 속도가 그냥 읽히는 것 말고 잘 쓰이도록 하는 구조가 있을 수도 있다."
> 대상: 블록 AR `natural_ar_vw_state` vs 영상 문맥 `natural_ar_vw_state_ctxt_video` (둘 다 latest, 정답 = 블록별 LN(target_encoder)).
> 학습 없음, forward 만. 10-17 진단 (`z_research/VOBench_v1/Archive/DIAG_CTXT_VIDEO_VS_AR_2026-10-17.md`) 과 겹치지 않는 것만 쟀다.
> 수치는 `ctxt_vs_block_mechanism.py --report` 산출물에서 옮겼다. 측정과 추측을 나눈다 (추측 = **[추측]**).

## 0. 결론 (한 문단)

**두 predictor 모두 블록 입력에서는 물체를 한 걸음에 실제의 약 30 % 만 옮긴다** (정답 과거를 다 보여 줘도, AR 0.27 · ctxt 0.35).
영상 문맥 모델이 첫 걸음에 0.59 를 옮기는 건 **문맥이 영상으로 인코딩된 토큰일 때뿐**이고, 같은 모델에 블록 관측을 넣으면 블록 AR 과 거의 같아진다.
즉 차이는 "predictor 가 속도를 쓰는 법을 배웠나" 보다 **"입력 토큰에 운동이 어떤 형태로 들어 있나"** 에서 나온다.
predictor 내부에서도 갈린다 — 영상 문맥은 중간층에서 물체의 **새 자리** query 로 속도 정보가 모이고 (R² 0.17 → 0.32), 블록 AR 은 새 자리는 평평하고 (0.15)
옛 자리의 속도 정보는 층을 지나며 사라진다 (0.32 → 0.05).

## 1. 데이터 · 방법

- phys3d_single_v1 **val** (두 모델 모두 학습에 안 쓴 3D 합성, 물체 1 개, 라벨 위치 · 속도), 96 장 clip, 창 시작 raw 0 · 2, 간격 3 → 문맥 16 장 (블록 0..7) · 미래 블록 8..15.
  문맥 끝에 물체가 보이는 창 412 개 (clip 216).
- **위치 읽기 (파라미터 없음)**: 템플릿 = 마지막 문맥 블록 정답 토큰의 물체 중심 3×3 평균. 예측 블록 256 칸과 cosine → 최대 칸 주변 3×3 cos 가중 중심.
- **운반 이득** = (d_pred · d_true) / |d_true|². 1 = 정확히 옮김, 0 = 제자리. 실제 변위가 16 px (1 칸) 넘고 그 블록에 물체가 보이는 경우만.
  rollout 은 문맥 끝 위치 기준 (누적), **TF (정답 과거를 다 본 한 걸음) 는 직전 정답 블록 위치 기준**.
- 층별 속도: 문맥 마지막 블록 자리 (첫 예측을 내는 query 들) 의 층별 은닉 (384), 물체 옛 자리 3×3 · 첫 예측의 새 자리 3×3 평균 → ridge, clip 단위 반반.
- attention: 같은 자리에서 새 자리 query 가 준 질량 (헤드 평균). 영상 문맥의 문맥 토큰은 encoder 가 이미 시간을 섞은 것이다.

- **갈림은 첫 걸음에서 이미 있다** — 굴리며 쌓이는 문제가 아니다. 블록 AR 은 정답 과거를 줘도 (TF) 한 걸음에 0.27 만 옮긴다
- **영상 문맥 모델도 블록 관측을 입력으로 받는 TF 에서는 0.35** — 블록 AR 과 거의 같다. 0.59 는 영상으로 인코딩된 문맥에서 바로 나올 때만
- 영상 문맥의 rollout 은 걸음 4 까지 0.45 를 유지하다 걸음 6 부터 무너진다 (그림에서 "2~4 블록 따라가다 사라짐" 과 맞다)

|---|---|---|
| 1 | 0.086 / **0.420** / 0.006 / 0.49 | 0.045 / 0.157 / 0.004 / 0.80 |
| 3 | 0.155 / 0.353 / 0.006 / 0.49 | **0.227** / 0.106 / 0.012 / 0.66 |

## 3. 메커니즘 가설 [추측]

1. **predictor 는 마지막 블록을 거의 칸별로 사상한다** — 새 자리 query 의 질량 대부분이 마지막 블록 (자기 자리 · 이웃) 에 있고 앞 블록은 안 본다 (§2-3, 10-17 §3 의 "마지막 블록 0.65" 와 같다).
   그러면 첫 예측의 새 자리 출력은 **그 자리 입력 토큰과 바로 옆 옛 자리 토큰** 이 결정한다.
2. 블록 토큰의 새 자리는 그냥 배경이고 속도는 옛 자리에만 있다 (어제 probe: 블록 토큰 속도는 물체 칸에만, 화면 평균 0.57 vs 영상 0.69).
   새 자리에 물체를 그리려면 옛 자리 → 새 자리로 "속도만큼 떨어진 칸" 에서 가져와야 하는데, 이 위치 의존 경로를 L1 학습이 30 % 정도만 만든다.
3. 영상 encoder 는 32 장 창을 시간 양방향으로 섞어 **운동이 주변 칸까지 번진 토큰** 을 준다 → 같은 칸별 사상으로도 물체가 움직인 출력이 나온다 (§2-2 새 자리 R² 상승).
   그래서 영상 문맥 모델도 블록 관측 위에서는 다시 30 % 로 돌아온다 (§2-1 TF).
4. 한 걸음 0.27–0.35 의 "위축" 은 자연 영상에서 운동 외삽이 불확실해 L1 이 조건부 중앙값 (제자리 쪽) 으로 당긴 결과일 수 있다 (10-17 §5 의 크기비 0.3–0.5 와 같은 크기).
   이 3D 합성은 운동이 결정적이라 불확실성이 없는데도 위축이 그대로다 → 학습 분포에서 굳은 습관.

## 4. 블록 입력을 유지하면서 운동을 쓰게 하는 구조 후보

| 후보 | 무엇 | 겨냥 (§3) | 근거 · 걱정 |
|---|---|---|---|
| **A. 블록 위 시간 섞기층 (motion mixer)** | predictor 앞에 최근 L 블록 토큰을 칸 · 시간 양방향으로 섞는 작은 층 → 영상 encoder 처럼 "운동이 번진" 토큰을 만든 뒤 predictor 에 넣는다. 예측 블록에도 그대로 걸 수 있어 planning 과 맞다 | 3 | 영상 문맥의 이점이 입력 형태에서 왔다는 §2-1 이 직접 근거. 걱정: 학습 신호가 L1 하나라 섞기층도 같은 위축을 배울 수 있다 |
| **B. 오프셋 가져오기 출력 (warp / pointer)** | 칸마다 오프셋 (흐름) 과 게이트를 예측하고 출력 = 게이트 · (마지막 블록을 오프셋만큼 옮겨 쓴 토큰) + 잔차. gating (같은 칸 복사) 의 "다른 칸 복사" 판 | 1 · 2 | 운동을 "칸 하나 옮겨 쓰기" 라는 싼 연산으로 만든다. 걱정: gating 은 정지 장면에 기대는 쪽으로 갔다 — 흐름이 0 으로 붕괴할 수 있다 |
| C. 블록 차이 입력 | Δ = h_b − h_{b−1} 를 같이 넣기 | 2 | **약하다** — 어제 probe 에서 블록 차이는 블록 하나보다 속도를 더 담지 않았고, 차이는 "어디로 갈지" 가 아니라 "어디서 왔는지" 를 표시한다 |

우선순위: **A** (§2-1 이 가장 직접적인 근거) → B. 둘 다 학습이 필요하다.

## 5. 단서

- 표본: 첫 걸음 비교는 1 칸 넘게 움직인 **60 창** 뿐 (구간이 안 겹칠 만큼은 갈렸다). 3D 합성 val 이 두 모델의 학습 분포 (자연 영상) 밖이다
- 위치 읽기 바닥이 걸음 1 에서 0.78 (정답 블록도 1 이 안 나온다) — 이득은 모델끼리 상대 비교로 읽는다. 위치 오차 절대값 (13–15 px) 은 느린 물체에서 읽기 해상도 (1 칸 16 px) 에 묻힌다
- 층별 probe 는 384 차원 · train 약 200 창이라 R² 절대값이 낮다 (어제 1280 차원 · 6,148 표본 probe 의 0.6–0.7 과 직접 비교 금지). 모델 사이 · 층 사이 상대 비교만
- 영상 문맥의 "옛 자리 / 새 자리" 토큰은 encoder 가 시간을 섞은 것이라 블록 AR 의 같은 이름 토큰과 의미가 다르다
- 두 run 은 문맥 인코딩 외에도 TF 범위 · 문맥 attention · 샘플링이 다르다. §2-1 의 "같은 영상 문맥 모델이 블록 관측에서 30 %" 는 그 혼동을 일부 피한 비교다 (같은 가중치, 입력 형태만 다름) — 다만 블록 관측 자리는 학습 때도 TF 자리라 "학습한 역할" 자체가 다르다는 반론이 남는다
