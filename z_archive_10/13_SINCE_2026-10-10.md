## 0. 용어표 (이 장 전체에서 이 말만 쓴다)

| 용어 | 뜻 |
|---|---|
| **VOBench** | 2026-10-10 에 개설한 통제 testbed. 720 block × 4 변이 = 2,880 clip, **matched 쌍 1,440** (가능 · 불가능의 문맥 16 장이 픽셀 단위로 같음). 요인: 물체 집합 2 (기하 6 종 = **primitive** · 실물 메시 6 종 = **realistic**, 따로 기록) × 위반 3 (영속 = 물체가 빈 장면으로 / 모양 바꿈 / 색 바꿈) × 운동 6 (정지 · 등속 · 가속 · 감속 · 경사 내려감 · 올라감) × 배경 2 × 가림 (없음 · 문맥 앞 · 문맥 가운데 · **문맥 끝** × 길이 k 1–3). 96 프레임 30 fps 512 px, 가능 · 불가능의 갈림은 48 번째 프레임 |
| **late** | VOBench 의 "문맥 끝 가림" 조건. 가림막이 바꿈 (갈림) 을 가린 채 문맥이 끝난다. 문맥 앞 · 가운데 가림 (early · mid) 은 바꿈이 보인다 — 같은 세트 안의 대조군 |
| **표준 채점** | 03 장의 것 그대로: surprise = mean \|predictor(문맥) − LN(target encoder(32 장))[미래]\| (latent L1), matched 쌍, 문맥 16 · 미래 16, chance 50 |
| **복사 기준선** | 문맥 마지막 튜블릿의 표현을 미래 8 슬롯 전부에 그대로 둔 "예측 없는" 점수. 릴리즈 predictor 는 창 단위 공간, 자기회귀 계열은 **블록별 공간** 에서 각자 잰다 (두 공간의 surprise 크기는 비교하지 않고 **쌍 정확도만** 비교) |
| **릴리즈 predictor** | V-JEPA 2 ViT-H 공개 predictor. 문맥 16 장을 한 창으로 인코딩하고 mask token 으로 미래 8 블록을 한 번에 낸다 (양방향 attention) |
| **자기회귀 predictor (AR)** | Ariel 이 관측만으로 (action 없이) 자연 영상에서 학습한 predictor, 40 epoch 판. 문맥을 2 장 블록마다 따로 인코딩하고 다음 블록을 예측해 그 **출력** 을 다시 입력에 붙인다 (블록 인과) |
| **상태 되먹임 AR** | 위와 같되 출력 대신 그리기 전 내부 상태 (384 차원) 를 되먹이는 판. Ariel 40 epoch 판과 **vast 70 epoch 판** (다른 데이터 · 예산 · 4 fps · 가변 창) 둘. ⚠️ 이름의 "상태" 는 되먹이는 텐서의 종류이지 라벨 감독이 아니다 |
| **vast 판** | 사용자가 외부 GPU 에서 처음부터 (encoder 동결) 학습한 predictor 들을 레포로 들여온 것 |
| **post-FT** | 릴리즈 (또는 AR) predictor 를 특정 데이터의 **가능 영상만** 으로 이어 학습한 것. encoder 는 동결 |
| **분포 안 / 밖** | post-FT 학습 데이터와 같은 생성기 · 같은 요인 설계 = 안 (VOBench 의 held-out 절반도 **안**). IntPhys 1 · 2 · GRASP · InfLevel = 밖 |
| **고른 미래** | 중력 판에서 과거 하나에 후보 미래 여럿을 붙여, predictor 출력에 L1 로 가장 가까운 후보. 진짜 운동 · 등속 · 높이 유지 · N 프레임 뒤 멈춤 등 |
| **자 (readout)** | predictor 출력 토큰에서 위치 + 정체 (+ 없음) 를 읽는 작은 attentive 모델. 모델마다 그 모델의 출력으로 학습. held-out 정밀도를 같이 적는다 (03 장 §5 규칙) |
| **anchor 이식** | 마지막 문맥 블록 (프레임 14 · 15) 의 **픽셀만** 바꾼 (멈춤 · 되돌림 · 두 배) 문맥을 넣고, 미래가 원래 궤적과 바뀐 블록 중 어느 쪽을 따르는지 재는 개입. 따름 지수 0 = 원래 궤적, 1 = 바꾼 블록의 등속 |
| **역사 절단** | 문맥을 8 블록에서 4 · 2 · 1 블록으로 줄였을 때 복사 대비 이득 중 잃는 몫 |
| **presence without placement** | 가려진 물체가 "있다" 는 맞히되 그 **자리** 에는 놓지 않는 것. 영속 점수는 배경 토큰에서 나온다 |
| **상태 보조 head** | predictor 출력 토큰을 attention pooling 해 매 장 존재 · 위치 · 속도를 내는 보조 손실. 라벨은 시뮬레이터가 준 **특권 정보** (관측만이 아니다) |
| **2D 물리 학습셋** | 2D 강체 시뮬레이터로 만든 가능 영상 (중력 · 영속 · 고체성 17–20 시나리오, 4 fps 256 px). 상태 라벨 동반 판이 따로 있다 |
| **EK100 축소 훈련셋** | EK100 action anticipation probe 학습용 부분집합: 지표 action 클래스마다 ≤ 16 clip (전체의 1/5.9), 검증은 공식 전수. **전체 훈련 기준 35.34 와 비교 금지** |
| **등급** | 확정 (적대 검증 통과) · 1 차 (검증 전) · 시사 · 철회 · ★ 미실행 — 원 문서의 표기를 따른다. 10-10 이후 문서는 대부분 등급을 안 적었으므로 **표기 없음 = 1 차** 로 읽는다 |
| **근거 표시** | [측정] 산출물에서 읽은 수치 · [이론] 정의 · 규칙에서 따라오는 것 · [추측] 문서가 가설로 둔 것 · [설계안] 미실행 설계 |

## 2. 새 testbed VOBench — P2 (leakage) · P3 (ii) 안 보이는 것

### 2-1. 왜 했나
v11 의 핵심 결과 ("문맥 끝 가림만 무너진다 · vanish A 0 / B 100") 가 물체 집합 · 운동 · 배경에 무관하게 재현되는지, 그리고 **복사 기준선** 을 처음부터 표에 넣어 "예측 없이 풀리는 칸" 과 "복사로 안 풀리는 칸" 을 같은 세트 안에서 가르기 위해.

### 2-2. 무엇을 어떻게
용어표의 VOBench. 표준 채점 그대로. 가림 세 시점 중 **late 만 바꿈을 가린다** — 그래서 보이는 칸 (가림 없음 · 앞 · 가운데) 은 leakage 의 대조군이고 late 가 copy-hard 칸이다. 통계: block 부트스트랩 95 % CI · 쌍 단위 McNemar. 칸 크기: 가림 없음 위반당 24 쌍 · 앞/가운데/끝 위반당 72 쌍 · late × 운동 × 위반 12 쌍 (방향당 6).

### 2-3. 결과

**릴리즈 predictor 는 복사 기준선을 넘지 못한다** [측정, 확정 — 1,440 쌍, 산출물에서 재계산]

| 물체 집합 | 모델 | 복사 | Δ [CI] | late (문맥 끝 가림) | late 복사 |
|---|---:|---:|---|---:|---:|
| primitive | **71.7** [69, 75] | 73.8 | −2.1 [−5.4, +1.1] | **57.9** (A 45 / B 70) | 56.5 |
| realistic | **81.9** [79, 85] | 81.9 | 0.0 [−2.8, +2.8] | **65.7** (A 48 / B 83) | 61.1 |

- 바꿈이 보이는 칸은 복사만으로 77–96 % — IntPhys 1 (복사 85) 과 같은 구조 [측정].
- late 의 복사 대비 Δ 는 +1.4 / +4.6 으로 CI 가 0 을 포함한다 [측정]. late 복사가 chance 보다 조금 높은 이유 (61 %) 는 미분석 [미결].
- **late 영속의 비대칭은 v11 과 같고 물체 집합에 무관하다**: 움직이는 네 운동 × 두 집합 = 8 칸 전부 **사라짐 A 0 % / 나타남 B 100 %** (방향당 6 쌍, 일관성으로 읽음); 정지 물체 83/50 · 67/100 [측정]. late 는 가림 길이 k 1–3 에 평평 (54/54/58 · 62/62/58) [측정].
- **창을 밀어 가능 미래에서 물체가 첫 샘플부터 보이게 해도 바뀌지 않는다** (56.5 → 56.9 · 66.7 → 65.7, 이동 영속 0/100 그대로) [측정]. → 실패는 "가림 너머를 예측해야 해서" 가 아니라 **마지막 관측에 물체가 안 보여서** 다 [측정 기반 해석].
- 물체 자리 토큰만으로 채점하면 보일 때는 오르고 (primitive 모양 · 색 63–75 → 90–96) late 는 두 모델 모두 chance 이하 (48–53) [측정] — 배경 토큰이 신호를 묽히는 것은 보일 때뿐이고, late 는 실제 자리에 어느 미래도 없다.

**다른 world model 도 late 에서 같은 비대칭** [측정]

| 모델 | 전체 (prim / real) | 복사 | late 영속 "있는데 → 있는" / "없는데 → 없는" |
|---|---|---|---|
| DINO-Foresight (프레임 DINOv2 + unroll) | 84.9 / 84.7 | 81.7 / 82.9 (Δ +3.2 · +1.8) | 25 / 19 (움직이는 운동 0–33) · 89–97 |
| VideoMAEv2-g (픽셀 복원 오차) | 51.5 / 52.5 | 없음 | 가림 없음조차 17 / 83 — 전 칸 chance |
| 영상 타깃 predictor (vll7, 문서 없음) | 71.7 / 83.6 | 없음 | 19 / 78 · 19 / 97 (late 전체 50.9 / 61.6) |

### 2-4. 해석
- P2: **새 testbed 에서도 "예측 없이 풀리는 칸" 이 점수의 대부분이고, predictor 는 복사를 넘지 못한다** [측정]. leakage 그림 (복사 x · 모델 y) 에 VOBench 24 칸이 더해진다.
- P3 (ii): "**마지막 관측에** 안 보이면 못 한다" 가 같은 세트 안의 대조군 (문맥 가운데 가림은 처리) 과 창 밀기 검사로 더 단단해졌다 [측정]. "context 에서 안 보이면" (전부로) 은 여전히 금지.
- 아직 모르는 것: 문맥 앞 가림에서 모델이 복사보다 **낮은** 칸 (primitive 모양 −12.5 · realistic 영속 −6.9) 의 원인 [미결].

## 3. 중력 판 — P3 (iii) 없는 것 (3a 꼭대기 · 3b 낙하)

### 3-1. 왜 했나
v11_realistic 의 선반 낙하 (0/120) 와 포물선 (미래 다섯 중 고르기) 을 VOBench 장면 · 실물 메시로 다시 내고, "불가능 미래가 복사와 다른 방향으로 움직이는" 다중 미래 설계 (정본 §2-3 iii 조건 1) 를 갖추기 위해. 예측 길이가 원인인지도 가른다.

### 3-2. 무엇을 어떻게
216 block: **선반 (ledge)** 144 block = 낙하 (가능) vs 같은 높이 직진 (2 지선다, chance 50) · **포물선 (arc)** 72 block = 미래 9 개 중 **고른 미래** (chance 11 %). 문맥 끝이 오르는 중 · 꼭대기 · 내려가는 중의 세 시점. 10-11 재렌더판 (옛 판은 중력 상수가 달라 섞어 읽지 않는다). 예측 길이는 16 → 8 → 4 → 2 로.

### 3-3. 결과

| 모델 | 선반 낙하 (쌍 정확도) | 포물선: 진짜 운동을 고른 block | 고른 미래 |
|---|---:|---:|---|
| 릴리즈 | **0.0** (복사도 0.0 → 못 가름) | **0 / 72** | 진짜 운동을 11–15 프레임 잇다 **공중에서 멈춘** 미래 92–100 % (문맥 시점 무관) |
| 자기회귀 AR | 9.7 / 0.0 (복사 12.5 / 1.4, CI 0 포함) | 내려가는 중 **0 / 24** (꼭대기 3 / 24) | 멈춤 후보 0 — 대신 **등속 · 높이 유지** 후보 (오르는 중 포물선 83 / 75 는 등속 규칙과 같은 후보라 중력의 증거가 아님) |
| 릴리즈 + VOBench·중력 post-FT (분포 안 held-out) | 36 / 36 | 18 / 18 · 14 / 18 | 고른 미래 0 → **100 / 92.6** |

- 꼭대기 문맥에서 릴리즈는 **앞 튜블릿부터** 갈린다 (올라감 31 / 69 %, 진짜 포물선 3 %) [측정].
- **예측 길이를 줄여도 창의 끝에서 진짜 운동을 떠나 정지 쪽으로 간다** — 같은 3–4 번째 샘플이 긴 창에서는 100 % 진짜 쪽인데 짧은 창 끝이면 8–42 % [측정]. 공 자리 토큰만 보면 창 끝 효과가 없다 → 창 끝 효과는 배경 · 그림자 토큰 [측정]; 기제 (target encoder 의 전역 attention 추정) 는 미검증 [추측].
- post-FT 뒤 자로 본 운동: 등속은 따라가되 (속도 비 0.6–0.8) 가속은 덜 반영 (t15 −3.0 칸) [측정, 1 차].

### 3-4. 해석
- 릴리즈는 꼭대기에서 되돌아오는 미래 (3a) · 낙하하는 미래 (3b) 를 만들지 않는다 [측정]. 쓸 문장: "진짜 운동을 몇 샘플 이은 뒤 **공중에서 멈춘** 미래에 가장 가깝다" — "15 프레임 뒤 멈춘다" 는 후보 상한이라 쓰지 않는다.
- 자기회귀 AR 은 멈추지는 않으나 **등속 · 높이 유지** 미래를 고른다 — 가속 (중력) 을 미래에 넣지 않는 것은 같다 [측정].
- 선반은 복사도 0 → VoE 쌍 하나로는 "낙하를 안 만든다" 와 "머문다" 를 못 가른다 (H23 단서 재확인). 이 판의 다중 미래 (포물선 9 갈래) 가 그 단서에 답하는 설계다 [이론].
- 분포 안에서는 post-FT 가 거의 다 푼다 — "이 18 셀의 궤적을 다른 물체 · 배경으로도 낸다" 까지이고, 다른 testbed 에서 재야 한다 [측정 + 단서].

### 4-1. 왜 했나

### 4-2. 무엇을 어떻게
(a) 영상 32 장 전체의 encoder 토큰을 시공간 평균한 벡터 위 가능/불가능 **선형 probe** (장면 단위 5-fold, 라벨 섞기 대조) — 쌍 정확도. (b) 가림 없는 튜블릿의 target encoder 표현으로 학습한 **정체 head** 를 encoder 가림 튜블릿 · predictor 보임 · predictor late 에 적용. (c) **문맥 안 상태 자** — 과거 16 장만 본 문맥 encoder 위 작은 자로 "마지막 본 위치 · 속도". (d) target encoder 토큰 **하나** 로 물체 위치 회귀 (물체로부터 거리별).

## 5. 자기회귀 predictor 의 행동 — "있다" 는 맞히고 "어디" 는 못 한다

### 5-1. 왜 했나
08 · 09 장의 Ariel 세 팔 중 AR 팔이 v11 late 를 "presence without placement" 로 넘었다는 단서 (09 장 §2) 를 새 testbed · 벤치 · 자로 확인하고, 상태 되먹임 판이 다른지 본다.

### 5-2. 무엇을 어떻게
AR (Ariel 40 epoch) · 상태 되먹임 AR (Ariel 40 · vast 70) 을 VOBench · 중력 · IntPhys 1 · 2 에서 표준 채점 (블록별 공간, 쌍 정확도만). 토큰별 오차 차 (파라미터 0) 로 영속 점수가 어느 토큰에서 나오는지. 자 (held-out 정체 95.2 · 중심 1.00 칸; 참 미래 천장 98.6 · 0.41 칸) 로 위치 · 정체 · '있다'.

### 5-3. 결과

| 판 | 릴리즈 | AR (40 epoch) | 상태 되먹임 AR | 한 줄 |
|---|---|---|---|---|
| IntPhys 1 (180 쌍) | 88.9 (복사 85.0, Δ +3.9 CI 0 포함) | **92.8** (블록 복사 83.3, **Δ +9.4 [+5.0, +13.9]**) | 91.1 (+7.8) · vast 90.0 | predictor 몫이 0 이 아닌 **첫 사례** — 이득은 사라짐 · 연속성 블록 |
| IntPhys 2 Main (506 쌍) | 54.3 (복사 55.5) | 52.6 | 51.2 · vast 51.8 | 셋 다 chance |
| VOBench 전체 (prim / real) | 71.7 / 81.9 | **81.9 / 86.4** (블록 복사 77.6 / 81.4) | 81.5 / 85.4 · vast 81.5 / 85.3 | AR 은 복사를 넘는다 |
| VOBench late | 57.9 / 65.7 | **75.0 / 78.2** (복사 55.1 / 55.6) | 74.5 / 77.8 | +20 — 거의 전부 영속 |
| late 영속 (있는데 → 있는 / 없는데 → 없는) | 19 / 92 · 22 / 100 | **100 / 97 · 100 / 100** | 97 / 96 | ✅ "있다" 를 이어 간다 |
| late 모양 · 색 (이동 물체) | 54–74 | **59.7–70.8** (chance 근처) | 61–75 | ❌ 정체는 이어 가지 못한다 |
| 정지 물체 모양 · 색 | 보이면 높음 | **92–100** (가림 시점 무관) | — | 정지 물체는 자리 계산이 필요 없다 |

⚠️ 09 장 §4-1 의 "AR IntPhys 1 90.56" 은 18 epoch 판, 이 장의 92.8 은 40 epoch 판 — 다른 체크포인트다.

- **영속 점수는 물체 자리에서 나오지 않는다** [측정, 두 방법 일치]: late 이동 영속에서 물체 자리 토큰의 차가 양수인 쌍 **0 %**, 배경 토큰 **100 %**; 물체 자리만 채점하면 98.6 → **56.9** (A 100 → 16.7 = 릴리즈와 같음). 마지막 관측 자리에는 잔상이 남는다 (빈 문맥 대비 +19 → +55).
- 자로 보면 [측정]: late 이동 물체 "있다" 81 → 55 % (빈 문맥 대조 57 → 17) 이나 "있다" 중 정체 10–15 % (chance 2) — **무언가 있다는 남고 무엇인지는 거의 없다**. 보일 때 정체 유지는 t12 까지 (early 이동 t15 98 → 70). 위치는 등속도 t15 에 −2.3 칸 뒤짐, 빨라짐 −3.8 (등속 외삽 오차 2.7 보다 더 뒤) — "가속을 반영하지 않을 뿐 아니라 문맥 끝 속도도 다 유지하지 못한다".
- **속도 감쇠는 "마지막 관측 뒤 몇 번째 블록" 에 묶여 있다** [측정, 1 차]: 속도 150–300 cm/s · 문맥 4–12 블록을 바꿔도 걸음 k 로 줄 세우면 같은 곡선 (k4 0.70–0.74 · k5 0.55–0.62). 릴리즈의 "거리" 결론 (04 장) 과 같은 방법으로 비교한 적은 없다 [미결].
- 상태 되먹임 AR 은 AR 과 **구분되지 않는다** (McNemar p 0.65 / 0.09; vast 70 epoch 도 같음) [측정] — 단 데이터 · 예산도 같이 달라 되먹임 하나의 효과로는 못 읽는다.
- 예측을 8 프레임으로 줄여도 AR 의 late 이동 모양+색은 59 → 65 뿐, 릴리즈는 62.5 → 75.0 [측정] — AR 의 late 실패는 "길게 예측해서" 가 아니라 **재등장한 물체의 정체를 처음부터 못 이어 가서** 다.

### 5-4. 해석
- 목표 (09 장) 의 Ariel 반례가 더 정확해졌다: AR 은 **영속의 "있음"** 만 풀었고 (복사 대비 +20, IntPhys 1 +9.4), **자리 · 정체 · 가속** 은 릴리즈와 같다 [측정]. "AR 이 가려진 물체를 미래에 둔다" · "AR 이 물리를 더 안다" 는 쓰지 않는다.
- 이것이 §6 의 질문을 만든다: 왜 "있음" 만 이어지고 "어디" 는 안 이어지나.

### 6-4. 해석
- 세 predictor 공통 [측정 기반 해석]: **"무엇 (있음 · 정체) 은 역사로 지속되지만, 어디 (자리 · 속도) 는 마지막 관측의 보이는 내용에 묶여 있다."** 보일 때 2–3 블록 맞는 것 · late 에서 처음부터 못 놓는 것 · AR 이 흐려진 자기 출력을 다시 읽어 점점 멈추는 것 · 가속 (블록 사이 속도 변화 = 과거가 필요한 양) 을 반영하지 않는 것이 한 설명으로 묶인다.
- 원인 후보 (측정됐으나 확정 아님) [추측]: (a) 목표가 "어디" 를 작게 본다 (표적 비국소 §4, 정적 토큰 73–87 %) · (b) 학습 분포에서 역사의 값이 1–3 %. 이 둘을 가르는 것이 §8 의 학습 팔이다.
- 쓰지 않는 문장: "predictor 는 속도를 모른다 / 운동 정보를 잃는다" · "속도를 위치로 적분하지 못한다" (전편 그대로) · "역사를 전혀 쓰지 않는다" (anchor 하나로는 증명 안 됨 — 멈춤 · 튕김은 물리적으로 가능) · "물체를 기억한다" (memory 프레임) · "목적함수 때문이다" (단정).
- ⚠️ 정본 (10-08) 과 결과 로그의 **머리 blockquote 는 철회 전 문장** ("속도는 은닉에 있는데 위치로 적분하지 않는다" · "운동 · 외형 분리") 을 그대로 두고 있다 — 표 행에만 철회가 있다. 갱신 필요 [문서 어긋남].
