# permanence_wrop — 공개 WROP 로 첫 실험 A · B · C (+ D)

> **3줄 요약**
> - **질문** — 가림 장면이 많은 관찰 영상 (WROP, Blender 90 과제) 으로 릴리즈 predictor 를 이어 학습하면, 영속 (가려져도 있다 · 없던 건 안 나온다) 이 배운 적 없는 가림 계열과 다른 벤치마크 (IntPhys2 · 실제 영상) 로 넘어가나.

> - **다음 할 일** — (1) seed 2 개 더로 VOBench 신호를 굳힌다. (2) IntPhys2 · 실제 영상이 안 움직이는 이유를 학습 없이 먼저 잰다. (3) WROP 위반 영상 (빼 둔 그릇 계열의 사라짐 · 생김) 은 Blender 4.4 결정 뒤에 만든다.

## 용어

| 용어 | 뜻 |
|---|---|
| WROP | 공개 물체 영속 데이터 (Blender, 150 과제 × 1 만, 1280×720 · 24 fps, 문맥 60 장 → 정답 60 장). 과제는 여섯 계열로 나뉜다 |
| 가림 계열 (op1 · op2 · op3) | op1 Baillargeon 가림 (움직이는 물체가 가림막 뒤로, 26 과제) · op2 정지 물체 가림 (가림막이 움직여 덮었다 걷힘, 29) · op3 그릇 (물체가 그릇에 담겨 옮겨짐, 35). 계획의 "OP-1 · 2 · 3" |
| 비영속 계열 (s1 · s2 · s3) | 가로막기 (20) · 떨어짐 (21) · 충돌 (19). 영속이 과제의 핵심이 아닌 같은 엔진 장면 |
| 경계 | WROP 의 문맥 / 정답이 갈리는 프레임 (사건 시작 무렵). 재등장은 경계 뒤에 온다 |
| 32 장 클립 | 경계 앞에서 균일 16 장 (문맥) + 경계 뒤에서 균일 16 장 (미래). IntPhys2 violation-uni 채점과 같은 규칙 |
| post-train | encoder 는 고정, 릴리즈 predictor 에서 시작해 같은 latent L1 손실 (문맥 16 장 → 미래 16 장 토큰, 정답 = LN(target encoder)) 로 이어 학습. 라벨 · 보조 head · 불가능 영상 없음 |
| 방향 A / B | 채점 쌍의 종류. A = 문맥에 물체가 있음 (계속 있어야 맞음, 사라지면 위반) · B = 문맥에 물체가 없음 (안 나와야 맞음, 생기면 위반) |
| 같은 쌍 비교 | 릴리즈와 같은 쌍에서 틀림 → 맞음 / 맞음 → 틀림 을 센다 (McNemar p) |

## 1. 왜 했나

- 계획의 주장: 관찰 영상만으로, 공백을 넘는 예측을 많이 보면 permanence 가 생기고 일반화된다.
- 이 기계의 앞선 결과는 이 주장에 불리하다 [측정]:
  - VOBench 로 post-train (`z_training/docs/AUX_PERMANENCE_2026-10-31.md` §5): VOBench held-out 75.7 → 91.7 인데 real_bench 47.5 → 45.0, IntPhys2 54.6 → 52.8. **같은 생성기 안에서만 오른다.**
  - 블록 AR 에 WROP 150 과제를 10 % 섞은 판 (`natural_ar_vw_state_op`, `z_training/VARIANTS.md`): IntPhys1 +2.8, GRASP +4.1, **IntPhys2 그대로 (51.8)**.
  - 그 문서의 결론은 "막힌 곳은 구조가 아니라 데이터" 였다. VOBench 는 경로가 21 가지뿐이라 외워서 풀린다는 추측 [추측].
- 그래서 이 실험이 가르는 것: **다양한 가림 데이터 (WROP 55 과제, 무작위 카메라 · 조명 · 속도) 면 넘어가나.**
  - 넘어가면 (C > D ≈ B, 외부 세트에서) → 다양성이 병목이었다. 계획의 다음 단계 (부재 클립 · tuning curve · 실제 영상 합성) 로.
  - 안 넘어가면 (C ≈ D ≈ B, 외부) → 다양한 합성 가림 데이터 + 같은 L1 로도 안 된다. 병목은 데이터 다양성이 아니라 목적 · 구조 · 도메인 쪽이다 (계획의 "C ≈ B → predictor 구조 변경" 줄).
  - 어느 쪽이어도 다음 행동이 정해진다.

## 2. 무엇을 어떻게 했나

### 2-1. 판 (같은 시작점 · 같은 step · 같은 일정 · 같은 aug, 학습 데이터만 다르다)

| 판 | 학습 데이터 | 계획의 칸 | 분리하는 효과 |
|---|---|---|---|
| A | 없음 (릴리즈 predictor) | A | 출발점 |
| B | SSv2 100 % | B | 이어 학습 자체 |
| C | SSv2 50 % + WROP 가림 op1 · op2 50 % (79,750 편) | C (아래 단서) | 가림 경험 |
| D | SSv2 50 % + WROP 비영속 s1 · s2 · s3 50 % (79,800 편) | (추가) | 같은 Blender 엔진에 익숙해진 효과 |

- **D 를 더한 이유** — C 가 WROP held-out 에서만 오르면 B 로는 "가림을 배웠다" 와 "Blender 장면에 익숙해졌다" 를 못 가른다. D 는 같은 엔진 · 같은 클립 수 · 영속이 핵심이 아닌 과제다. 계획의 반론표 "그냥 더 학습해서 좋아진 것 아니냐" 를 한 단계 더 막는다.
- **C 는 계획의 "C − 부재" 다** — 공개 WROP 에는 부재 클립 (물체 없이 같은 장면) 이 거의 없다. 그래서 방향 B (생기면 위반) 가 안 오르면 계획의 "부재 불균형 shortcut" 줄에 해당한다.
- **그릇 계열 (op3) 을 학습에서 뺐다** — 계획: "C 는 OP 계열 하나를 leave-one-out 으로 빼 두고 시작". 그릇은 "물체가 그릇과 함께 옮겨진다" 는 다른 운동 타입이라 이식 시험으로 가장 멀다. 외부 벤치마크 (가림막 뒤 재등장) 와 가장 가까운 op1 · op2 는 학습에 남겼다.
- SSv2 를 C · D 에 반씩 섞은 이유 — 계획의 "원본 SSv2 = 일반 능력 유지" 와, 합성만으로 학습하지 않는다는 이 레포 원칙 (`z_training/docs/DATA_DESIGN_PRINCIPLES_2026-10-26.md`).

### 2-2. 학습 설정

| 항목 | 값 |

| 과제 | 32 장 = 문맥 16 → 미래 16, latent L1 (채점과 같은 꼴) |
| WROP 클립 | 경계 앞 균일 16 + 뒤 균일 16 장. 81 % 는 60 + 60 장이라 약 6.1 fps (3.9 장 간격, 경계에서만 1 장 간격) · 문맥 2.5 초 + 미래 2.5 초 |

### 2-3. 채점

| 세트 | 쌍 | 무엇을 보나 | 학습과 관계 |
|---|---:|---|---|
| WROP held-out 예측 L1 (계열별) | 과제당 20 클립 | C 가 가림 계열에서 예측이 나아졌나 · 빼 둔 그릇 계열로 넘어가나 · D 와 비교 | 같은 생성기, 다른 표본 |

| IntPhys2 violation-uni | 500 | IntPhys2 (조건별: 영속 · 불변 · 연속 · 고체) | 학습에 안 씀 |

## 3. 결과

세 판 모두 4,000 step 을 끝냈다 (B 11-01 01:10, C · D 01:26 KST). 표의 수치는 채점 산출물 (쌍별 surprise) 에서 다시 계산했다 [측정].
비교 칸의 "x / y" = 같은 쌍에서 틀림 → 맞음 x 개 / 맞음 → 틀림 y 개, p = McNemar.

### 3-1. 한눈에 (정확도 %, chance 50)

| 세트 | 쌍 | A 릴리즈 | B SSv2 | C +가림 | D +비영속 | C 대 B | C 대 D |
|---|---:|---:|---:|---:|---:|---|---|
| VOBench held-out 전체 | 720 | 75.7 | 78.5 | **79.7** | 73.1 | 39 / 30 · p 0.28 | **55 / 7 · p < 0.01** |
| └ 방향 A (사라지면 위반 등) | 360 | 68.3 | 72.8 | **77.2** | 65.8 | **27 / 11 · p 0.01** | **41 / 0 · p < 0.01** |
| └ 방향 B (생기면 위반 등) | 360 | 83.1 | 84.2 | 82.2 | 80.3 | 12 / 19 · p 0.21 | 14 / 7 · p 0.13 |
| IntPhys1 late | 180 | 68.3 | 68.9 | **72.2** | 65.6 | 16 / 10 · p 0.24 | **18 / 6 · p 0.01** |
| └ O1 영속 | 60 | 70.0 | 68.3 | **76.7** | 65.0 | 6 / 1 · p 0.06 | **7 / 0 · p 0.01** |
| IntPhys2 violation-uni | 500 | **54.6** | 52.8 | 53.6 | 53.4 | 16 / 12 · p 0.45 | 15 / 14 · p 0.85 |
| └ 영속 | 120 | **58.3** | 50.0 | 55.0 | 56.7 | 8 / 2 · p 0.06 | 5 / 7 · p 0.56 |
| real_bench (실제 영상) | 40 | **47.5** | 42.5 | 42.5 | 42.5 | 0 / 0 | 0 / 0 |

- [측정] real_bench 는 B · C · D 의 40 쌍 정오가 전부 같다. 쌍별 surprise 값은 판마다 다르다 (캐시 재사용 아님). 40 쌍 중 릴리즈와 갈린 쌍은 판마다 4 쌍 (1 / 3) 뿐이다.
- [측정] IntPhys2 는 세 판 모두 릴리즈보다 낮다. B (SSv2 만) 가 영속 칸을 58.3 → 50.0 으로 떨어뜨리고 (10 / 20, p 0.07), C · D 는 그 일부를 되돌릴 뿐이다. C 와 D 는 차이가 없다 (5 / 7).

### 3-2. VOBench 영속 칸 — 가림 시점 × 방향

VOBench 영속의 방향 A = 문맥에 물체가 있고 가려짐 → 불가능은 "사라짐". 방향 B = 문맥이 빈 장면 → 불가능은 "생김". 가림 시점 late = 가림이 문맥 끝에 걸림 (이 레포에서 가장 어려운 칸).

| 칸 | 쌍 | A 릴리즈 | B | C | D | C 대 B | C 대 D |
|---|---:|---:|---:|---:|---:|---|---|
| late · 방향 A (사라짐) | 36 | 13.9 | 13.9 | **41.7** | 11.1 | **11 / 1 · p < 0.01** | **11 / 0 · p < 0.01** |
| late · 방향 B (생김) | 36 | 94.4 | 91.7 | 91.7 | 88.9 | 1 / 1 | 1 / 0 |
| mid · 방향 A | 36 | 86.1 | 97.2 | 100.0 | 88.9 | 1 / 0 | 4 / 0 · p 0.05 |
| early · 방향 A | 36 | 91.7 | 100.0 | 100.0 | 94.4 | 0 / 0 | 2 / 0 |
| early · 방향 B | 36 | 100.0 | 100.0 | 91.7 | 97.2 | 0 / 3 · p 0.08 | 0 / 2 |

- [측정] late · 방향 A 의 오름은 두 물체 집합에서 같다: primitive 16.7 → 50.0, realistic 11.1 → 33.3 (B → C).
- [측정] 그러나 오른 곳이 chance 근처다. 쌍 차이 (불가능 − 가능 surprise) 의 중앙값이 primitive −0.0067 → +0.0002, realistic −0.0056 → −0.0008 이다. **0 % 근처의 편향이 0 근처로 줄었지, 확실히 맞히게 된 건 아니다.**
- [측정] 같은 칸의 방향 B (빈 문맥 → 생기면 위반) 는 91.7 그대로다. C 가 "가림막 뒤에는 뭔가 나온다" 쪽으로 기울었다면 이 칸이 떨어졌어야 한다.
- [측정] 색 · 모양 위반은 엇갈린다: 모양은 C 가 B 보다 높고 (78.8 vs 73.3, 19 / 6), 색은 낮다 (71.7 vs 76.7, 7 / 19).

### 3-3. WROP held-out 예측 L1 (계열별, 낮을수록 좋음)

과제당 20 클립. 차이의 괄호 = 과제 단위 bootstrap 95 % 구간.

| 계열 | 과제 | A 릴리즈 | B | C | D | C − B | D − B |
|---|---:|---:|---:|---:|---:|---|---|

| op2 정지 물체 가림 (C 학습) | 29 | 0.610 | 0.594 | **0.526** | 0.593 | −0.068 [−0.072, −0.064] | −0.001 [−0.004, +0.002] |
| **op3 그릇 (둘 다 안 봄)** | 35 | 0.617 | 0.601 | **0.587** | 0.599 | **−0.013 [−0.018, −0.009]** | −0.002 [−0.006, +0.002] |
| s1 가로막기 (D 학습) | 20 | 0.593 | 0.577 | 0.554 | **0.525** | −0.023 | −0.053 |

- [측정] 학습한 계열에서 L1 이 0.05–0.07 내려간다 (C 의 op1 · op2, D 의 s1–s3).
- [측정] 빼 둔 그릇 계열은 C 에서 0.013 내려가고 D 에서는 거의 안 움직인다 (0.002).
- [측정] 그러나 C 가 안 본 비영속 계열 s1 에서도 0.023 내려가고, D 가 안 본 op1 에서도 0.022 내려간다. **그릇 계열로 넘어간 양 (0.013) 은 안 본 계열로 보통 넘어가는 양 (0.001–0.023) 안에 있다.** 이 지표로는 영속에 특별한 이식을 말할 수 없다.

## 4. 해석

### 4-1. 가설에 대해 말하는 것

| 계획의 판정 줄 | 이번 결과 | 해당? |
|---|---|---|
| C > B, held-out 타입에서도 우세 → 데이터 설계가 곧 method | 다른 엔진 (VOBench) · IntPhys1 영속에서는 C > B · D. IntPhys2 · 실제 영상에서는 아니다 | **부분** |
| C > B, 학습한 타입에서만 우세 → 패턴 암기 | WROP 밖으로 넘어간다. 순수 암기는 아니다 | 아님 |
| C > B 인데 appear 쪽 안 오름 → 부재 불균형 shortcut | 생김 위반 (방향 B) 은 오르지도 내리지도 않았다. 이미 90 % 이상이라 이 줄로 가를 수 없다 | 판정 불가 |
| C ≈ B → 데이터만으로는 부족 | IntPhys2 · real_bench 에서는 이쪽이다 | **외부 세트에서는 예** |

- **가림 내용이 효과의 원인이다 (엔진 익숙함이 아니다)** [측정]. 같은 엔진 · 같은 양의 D 는 VOBench 를 릴리즈보다 낮추고 (75.7 → 73.1), C 는 올린다. C 대 D 가 방향 A 에서 41 / 0 이다.
- **앞선 VOBench post-train 보다 한 단계 멀리 간다** [측정]. 그때는 같은 생성기 안에서만 올랐다. 이번에는 Blender (WROP) 에서 배운 것이 Unreal (VOBench) 과 IntPhys1 에서 보인다.
- **그러나 IntPhys2 · 실제 영상에서 멈추는 것은 앞선 결과와 같다** [측정]. 다양한 합성 가림 데이터 + 같은 L1 로는 이 두 세트까지 못 간다.
- **오른 칸도 chance 를 넘지 않는다** [측정]. late · 방향 A 는 41.7 % 이고 쌍 차이 중앙값이 0 근처다. 사라짐에 대한 "싼 빈 장면" 편향을 줄였을 뿐, 가려진 물체를 미래에 확실히 그리게 된 것은 아니다.

### 4-2. 아직 모르는 것

- **seed 하나다.** VOBench late · 방향 A 의 11 / 0 은 36 쌍짜리 칸이다. 학습 중 감시 (late 216 쌍) 에서도 C 만 epoch 2 부터 앞서 우연일 가능성은 낮다고 본다 [추측]. seed 를 늘려야 말할 수 있다.
- **IntPhys2 · 실제 영상이 왜 안 움직이나** — 후보 셋, 전부 [추측]:
  1. 물체 크기 · 장면 복잡도. WROP · VOBench 물체는 화면의 작은 일부이고 배경이 단순하다. IntPhys2 · real_bench 는 장면이 복잡하다.
  2. 위반의 꼴. IntPhys2 영속 위반은 시간 위치 · 꼴이 다양하고, 문맥이 가능 · 불가능에서 픽셀 동일하지 않다 (중앙 |Δ| 3.9).
  3. 평가 단위. real_bench 는 40 쌍이고 판마다 4 쌍만 갈린다. 지금 크기로는 ±8 pt 아래의 변화를 못 본다 [이론].
- **기억인가 prior 인가** — 방향 B 가 그대로인 것은 prior 쪽을 약하게 반박할 뿐이다. 계획의 평가 ③ (문맥에서 물체를 지운 영상) 이 있어야 가른다.
- **빼 둔 그릇 계열의 영속 판별** — WROP 위반 영상이 있어야 잰다 (§아직 못 한 것).
