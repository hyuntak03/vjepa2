# 가림 합성 데이터 생성 파이프라인 — 계획과 진행 기록 (2026-10-31)

> **질문** — SSv2 · K400 영상에 가림막을 자동으로 합성하고 amodal mask 를 같이 뽑는 일이 사람 손 없이 되는가?
> **답** — 합성 배관은 된다. 원 계획 §2.2 방식 (첫 프레임 자동 분할 + 면적 · 움직임 거르기) 으로는 쓸 만한 물체가 거의 안 나온다: **SSv2 0 / 40, K400 2 / 40 (둘 다 사람 몸)** [측정] (§5.4).
> **다음 할 일** — 물체 고르는 방법을 사용자가 정한다 (§6). 보고 페이지: https://claude.ai/artifact/SbJvWfigiVP61idv4XWnJP (비공개)

원 계획: `PLAN_2026-10-31.md` §2 (데이터 파이프라인), §9 진행 순서 1 · 2.

## 용어

| 용어 | 뜻 |
|---|---|
| 창 (window) | 학습 · 채점에 쓰는 연속 프레임 묶음. 길이 `M` 장 = 문맥 `T_ctx` 장 + 예측 `T_pred` 장 |
| 물체 mask | 원본 (가림 합성 전) 영상에서 SAM2 로 뽑은 대상 물체의 프레임별 이진 mask, shape (M, 256, 256) |
| amodal mask | 가림막이 있어도 물체가 차지하는 전체 영역. 이 파이프라인에서는 = 원본 영상의 물체 mask |
| 가림막 (occluder) | 다른 이미지에서 잘라 낸 물체 조각. 합성 영상에서 대상 물체 위에 붙인다 |
| 덮임 비율 c(t) | 프레임 t 에서 물체 mask 중 가림막에 덮인 비율 = \|물체 ∩ 가림막\| / \|물체\| |
| 완전 가림 프레임 | c(t) ≥ 0.95 인 프레임 |
| 재등장 프레임 | 완전 가림 뒤 처음으로 물체가 다시 충분히 보이는 프레임 (보이는 비율 기준은 §4 결정) |

### S5 가림 일정 — 제약 (원 계획 §2.4)
- 물체가 창 앞쪽 `k_vis` 장 이상 보인다 (c(t) ≤ 0.05)
- 완전 가림이 `d_occ` 장 이어진다
- 완전 가림은 문맥 안에서 시작하고, 재등장은 예측 구간 안이다
  - 이 조건이 기존 v11 결과의 실패 조건과 같다: "가림이 문맥 경계에 걸리면 predictor 출력의 미래에는 처음부터 물체다운 토큰이 없다" [측정] (CLAUDE.md §5-5)
- 배치는 탐색으로 정한다: 방식 · 시작 시각 · 가림막 크기 · 속도를 바꿔 가며 실제 mask 로 c(t) 를 계산하고, 제약을 만족하는 것 중 하나를 고른다. 공식으로 위치를 계산하지 않는다 — 물체 mask 모양이 매 프레임 바뀌기 때문이다
- 기록할 통제 변수: 방식, 가림막 폭, `d_occ`, 물체 속도, 가림 시작 · 재등장 프레임

### 저장 (파일럿)
클립 하나당 폴더 하나: 합성 영상 · 원본 영상 (uint8), 물체 mask · 가림막 mask (bit-pack), 메타 (원본 경로 · 프레임 번호 · 통제 변수). 대량 생성 때 형식은 다시 정한다 (영상 압축을 쓰면 가림막 밖 픽셀이 원본과 달라진다).

### 5.2 가짜 물체로 돌린 S5 결과 [측정]

가짜 물체 = 반지름 16–34 px 타원 (면적 1.5–5 %), 속도 SSv2 5–9 · K400 2–4 px/프레임, 벽에서 튕김.
**실제 물체의 움직임 분포가 아니므로 아래 비율은 배관 점검일 뿐, 실제 통과율이 아니다.**

| | SSv2 (16 장) | K400 (48 장) |
|---|---|---|
| 일정을 찾은 클립 | 40 / 40 | 40 / 40 |
| 방식 (정지 / 이동) | **2 / 38** | 13 / 27 |
| 완전 가림 길이 d_occ | 2–6 장 (중앙 4) | 4–20 장 (중앙 12) |
| 재등장 − 문맥 끝 | 1–7 장 | 1–23 장 |
| 문맥 마지막 장이 완전 가림 | 40 / 40 | 40 / 40 |
| 가림막 면적 (최대 프레임) | 중앙 0.14 · 최대 0.29 | 중앙 0.18 · 최대 0.33 |

- **SSv2 16 장에서는 정지 가림막이 거의 안 된다.** 탈락 이유 1 위가 "첫 3 장에 물체가 보여야 한다" (정지 시도 4,076 번).
  정지 가림막은 물체가 [자기 폭 + 가림막 폭] 만큼 1.3 초 안에 움직여야 성립한다 [이론]. 실제 SSv2 물체가 가짜보다 느리면 더 드물어진다 [추측].
  → 원 계획 "두 방식을 섞는다" 의 비율은 SSv2 에서 데이터가 정한다. 진짜 물체로 다시 잰다
- 문맥 마지막 장이 언제나 완전 가림인 것은 설계다 (완전 가림 구간 [t_s, t_e] 가 문맥 끝을 포함하도록 뽑는다)

### 5.4 SAM2 로 진짜 물체 (GPU 5, 2026-10-31) [측정]

| 단계 | SSv2 (40) | K400 (40) |
|---|---:|---:|
| 첫 프레임에 조건 맞는 후보 없음 | 23 | 22 |
| 후보는 있으나 모두 탈락 | 17 | 15 |
| 물체 통과 | **0** | 3 |
| 가림 일정까지 성립 | **0** | 2 |

| 후보 탈락 이유 | SSv2 (후보 29) | K400 (후보 39) |
|---|---:|---:|
| 카메라 뺀 이동 < 20 px | 15 | 3 |
| 면적 변화 (> 2.5 배, 한 프레임 > 1.6 배) | 7 | 9 |
| 추적 중 사라짐 | 6 | 23 |
| 중심 튐 | 1 | 0 |
| 통과 | 0 | 4 |

- 첫 프레임 후보 단계에서 SSv2 는 면적이 맞아도 화면 가장자리에 걸친 것이 77 개로 가장 많이 빠졌다 (작음 133, 큼 36; 후보 없던 23 클립 합계)
- **⚠️ 정정 — 움직임 거르기.** 처음에는 화면 좌표 경로 합 ≥ 24 px 로 쟀다. 그때 SSv2 7 개가 통과했는데, 열어 본 5 개 중 4 개가 정지 물체 · 배경이었다 (천 무늬 · 담뱃갑 · 쓰레기통 스티커 · 잎). 카메라 흔들림으로 통과한 것이다. 위상 상관으로 잰 카메라 궤적을 빼자 이 넷의 이동은 1–2 px 였다. 지금 규칙은 "카메라 뺀 이동 ≥ 20 px" 다
- SSv2 에서 실제로 움직이는 물체 (지우개 · 자석 · 테이프) 는 손에 쥐어져 있어 면적이 변하거나 손과 한 mask 로 섞인다 → §3 의 위험 "amodal GT 가 실제로는 modal" 이 실제로 나타났다
- K400 은 48 장 (8 초) 창에서 추적이 끊긴다 (23 / 39). 통과한 2 개는 버거를 든 팔과 손, 춤추는 사람 전체다. 후자는 가림막이 화면의 28 % 까지 커졌다
- 속도: SAM2 base_plus, 40 클립에 SSv2 37 초 · K400 57 초 (GPU 한 장)
- ⚠️ 환경: torchvision 0.27.1+cu129 의 NMS 에는 sm_120 (Blackwell) 커널이 없다 (`no kernel image`). S1 은 SAM2 자동 분할의 NMS 만 CPU 로 돌린다
