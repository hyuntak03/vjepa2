## 0. 한 줄

> **Ariel AR 은 "가려진 물체가 아직 있다" 는 잘 맞힌다 (release 는 못 함). 그러나 그 물체를 "어디에" 놓는지는 release 와 똑같이 못 한다.**
> **이유: 미래의 자리 · 속도를 마지막 문맥 블록에 보이는 것에서만 가져온다.**

## 1. 모델 셋 — 구조와 학습

### 1-1. 공통

- **encoder 는 전부 frozen V-JEPA 2 ViT-H** (공개 체크포인트). 학습한 것은 predictor 뿐이다.
- encoder 는 둘이다 (같은 체크포인트 안):
  - **context encoder** (`encoder`) = 문맥을 보는 쪽
  - **target encoder** (`target_encoder`, EMA) = 정답 표적을 만드는 쪽
- predictor 크기는 셋 다 같다: depth 12 · 폭 384 · head 12. 입출력은 encoder 공간 (1280-d).

### 1-2. 셋을 한 표로

| | **release** (V-JEPA 2 공개) | **AR** (Ariel `ar_future_1e_5`, ep40) | **AR-state** (Ariel `ar_state_future_1e_5`, ep40) |
|---|---|---|---|
| 문맥 입력 | **context encoder** 가 문맥 16 장을 **한 창으로** 인코딩 | **target encoder** 가 **2 장 블록마다 따로** 인코딩 (LN) | AR 과 같음 |
| 미래를 만드는 방식 | 미래 자리에 mask token 을 놓고 **8 블록을 한 번에** (full attention) | **한 블록씩 자기회귀**: 다음 블록을 예측하고 **그 출력 (1280-d) 을 다시 입력에 붙여** 다음 걸음 | 한 블록씩 자기회귀, 단 출력 대신 **그리기 전 상태 (384-d) 를 되먹임** (관측 / 상태를 type embedding 으로 구분) |
| attention 규칙 | 전부 서로 봄 | 블록 인과 (앞 블록만 봄) | 블록 인과 |
| mask token | 있음 | 없음 | 없음 |
| 학습 목표 | V-JEPA 2 사전학습 (가려진 시공간 토큰 예측) | **L = TF + rollout** · TF: 참 블록들을 넣고 매 위치에서 다음 블록 예측 (teacher forcing) · rollout: 문맥 C 블록에서 자기 출력을 되먹이며 R = min(K, 8) 블록 예측 · 둘 다 블록별 target encoder 표적과의 L1 | AR 과 같은 TF + rollout (rollout 은 상태 되먹임) |
| 데이터 | VideoMix22M (사전학습) | SSv2 + K400 @ 12 fps, 48 장 창 · 문맥 {2, 4, 8, 16} × 예측 {1, 2, 4, 8} 블록 | K400 fps 6 + SSv2 1:1, 32 장 창 · 문맥 {2, 4, 8} × 예측 {4, 6, 8} 블록 |
| 예산 | — | 35,840 step · batch 28 / GPU × 6 · lr 3e-4 cosine | 11,760 step · global batch 504 · lr 5.2e-4 cosine |
| action | 없음 | **없음 (관측만)** — V-JEPA 2-AC 레시피에서 action 만 뺀 것 | 없음 |

### 1-3. 그림으로

```
release:   [context encoder( f0 … f15 한 창 )] + [mask × 8 블록]  ──predictor──▶  미래 8 블록 한 번에

AR:        [h(f0,f1)] [h(f2,f3)] … [h(f14,f15)]  ──▶ p1 ──붙임──▶ p2 ──붙임──▶ … p8
            └ h = target encoder 를 2 장마다 따로 돌린 것 (V-JEPA 2-AC 와 같은 관례: AC 는 1 장마다 따로)

AR-state:  위와 같되, 붙이는 것이 p (1280) 가 아니라 p 를 그리기 직전 상태 s (384)
```

**알아 둘 점**
- AR 과 release 는 **규칙 하나만 다른 게 아니다.** 인코딩 단위 (창 vs 블록) · 문맥 encoder (context vs target) · 생성 방식 (한 번 vs 자기회귀) · 학습 목표 · 데이터가 다 다르다.
- **채점 공간도 다르다.** AR 의 VoE 점수는 블록별 target encoder 표적, release 는 창 단위 표적이다. 그래서 **쌍 정확도만** 비교하고, 복사 기준선도 각자의 공간에서 따로 잰다.

### 2-2. 위치 자로 미래를 읽으면 (AR)

- 처음 2–3 블록은 문맥 끝 속도를 그대로 잇는다.
- **가속은 반영하지 않는다.** 빨라짐 / 느려짐 영상에서도 문맥 끝 속도를 이어 간다.
- 속도는 **4–5 번째 예측 블록에서 절반**이 된다. 물체 속도와 문맥 길이에 상관없이 '마지막 관측 뒤 몇 번째 블록인가' 에 묶여 있다.
- late 에서는 "무언가 있다" 는 남지만 **무엇인지 · 어디인지는 거의 없다.**
- **permanence 를 맞히는 근거는 물체 자리가 아니라 배경 토큰이다** (late 이동 permanence: 물체 자리에서 이긴 쌍 0 %, 배경에서 이긴 쌍 100 %) — "presence without placement".

### 2-3. 그래서 AR 은 release 대비 무엇이 좋아졌나 — 지금 아는 것과 모르는 것

**아는 것 (측정됨)**
- AR 은 late 에서 **과거 블록을 쓴다.** 문맥을 마지막 1 블록 (가림막만 보이는 블록) 으로 자르면, 복사 대비 이득의 **46–53 %** 가 사라진다 → "물체가 있었다 · 무엇이었다" 를 과거에서 가져온다.
- 그 정보는 **화면 전체 토큰 (전역 성분)** 으로 미래에 실린다. 그래서 permanence 점수는 오르지만 자리는 없다.
- 정지 물체는 자리를 계산할 필요가 없다. 과거에 보인 그 자리에 그대로 다시 놓으면 되니 정체가 맞는다 (92–100). **이동 물체는 옮겨 놓아야 해서 못 한다.** 아래 §3 의 "어디는 마지막 블록에서만" 과 맞는다.

**모르는 것 (가설)**
- 왜 release 는 late 에서 '있다' 를 못 이어 가나. 후보는 셋이고 **안 갈렸다**:
  - (i) 문맥 표현: release 는 문맥 16 장을 한 창으로 섞어 인코딩하고, AR 은 블록마다 따로라 가리기 전 블록이 깨끗하게 남는다.
  - (ii) 학습 목표: AR 은 '미래만 · 블록별 표적 · rollout' 이라 전역 '무엇' 코드를 이어 가는 데 손실이 크게 걸린다. 표적 차이의 95 % 가 전역이다 (§3 B9).
  - (iii) 채점 공간: 블록별 표적. 단, 같은 공간의 복사가 55 % 라 공간만으로는 설명되지 않는다.
- ✅ (10-13 추가) **release 도 late 에서 과거를 쓰지만 AR 보다 훨씬 덜 쓴다.** 문맥을 마지막 1 블록으로 자르면 잃는 이득: release 12–28 % vs AR 46–53 % (k2–k8). 마지막 2 블록까지 남기면 release 2–7 % vs AR 12–21 %.
  - → AR 은 가리기 전 블록에서 '있음 · 무엇' 을 더 많이 끌어온다. 후보 (i) · (ii) 와 맞는 방향이다.
  - ⚠️ 각자의 표적 공간 (release = 창 단위 target encoder, AR = 블록별) 에서 잰 몫이라 크기 비교는 대략적이다. (i) 과 (ii) 중 무엇 때문인지는 여전히 안 갈렸다.

**B13 을 읽는 법과 단서.**
- ⚠️ **정정 (2026-10-14).** AR 에서 블록 C+r 을 만드는 query 는 **위치 C+r−1 의 토큰**이다. 그래서 k1 의 '마지막 문맥 블록 0.61–0.71' 은 **query 가 자기 블록 (t8) 을 보는 몫**이고, k≥2 의 '가장 새 블록' 도 자기 블록이다.
  - 자기 블록을 떼면 AR k1 은 남은 질량 0.30–0.35 를 **전부 t1–t7 에** 준다.
  - k2–k8 에서는 자기 블록 0.37–0.56 · t1–t7 0.19–0.36 · t8 0.08–0.29 · 다른 생성 블록 0.10–0.20 이다.
  - 그래서 위 ① 의 "내용과 무관한 고정된 최근 편향" 은 **'자기 블록 편향'** 으로 고쳐 읽는다. 과거 문맥을 안 본다는 근거는 되지 않는다. 다른 근거는 ② (물체 query 의 과거 물체 자리) 와 B8 · B11 이다.
- **AR 과 릴리즈는 query 가 다르다.**
  - AR 은 block-causal 이고 한 걸음씩 만든다. query = 앞 블록 (문맥 끝 블록 또는 앞 걸음 출력) 의 토큰으로, 내용을 이미 가진다.
  - 릴리즈는 양방향이고 one-shot 이다. query = mask token 이다. 0 층에서는 8 블록 모두 같은 `mask_tokens[0]` 이고 위치는 RoPE 로만 다르다. 내용은 층을 지나며 문맥과 다른 mask 에서 모은다.
  - 릴리즈 그림의 행 t9 … t16 은 **같은 한 번의 forward 의 다른 query 블록**이다. 시간 순서로 이어진 걸음이 아니다.
- **간접 경로는 릴리즈가 더 넓다.** 문맥도 양방향이다 (t6 ↔ t8 이 서로 본다). 미래 mask 끼리도 서로 본다. 그래서 블록 6 의 정보는 t7 · t8 토큰이나 다른 mask 를 거쳐 들어올 수 있다. 직접 attention 이 작다고 해서 '안 쓴다' 는 결론은 나오지 않는다. 문맥 query 가 mask 를 보는 몫 (문맥 → 미래) 은 재지 않았다.
- attention 질량은 정보 사용량이 아니다 (value 크기 · residual 경로를 안 쟀다). 인과 쪽 증거는 B8 (블록 6 조작 효과 ≤ 0.06 칸) · B11 이고, B13 은 그 내부 모습이다.
- 거울 대조 = 물체 자리를 query 자리 기준으로 뒤집은 자리 (query 와 거리 같음). RoPE 공간 국소성만으로는 물체 = 거울이어야 한다. 물체 이동이 짧아 물체와 거울이 3 칸 미만으로 붙는 clip 은 뺐다.
- late 의 블록 6 물체는 가림막에 반쯤 걸렸을 수 있다 (라벨은 '보임'). 그래도 거울 대비 1.6–2.3 배로, visible 의 5–8 배보다 작다.
- vast AR-state 는 **4 fps** 로 학습했고 VOBench 는 10 fps 다 (Ariel AR 12 fps · AR-state 6 fps). 블록당 이동이 학습보다 작다.
- 옛 예시 지도 (`fig_ar_attention_maps`, 지금 `_superseded/`) 에서 query 는 과거 블록마다 **자기 자리 근처**를 보고, 물체가 있던 자리는 보지 않는다 — 예시 한 clip 의 관찰이고 '같은 자리' 몫은 따로 세지 않았다.

**B9 와 B12 를 같이 읽으면.**
- 물체가 **무엇인지 · 있는지**가 바뀌면 화면 전체 토큰이 바뀐다 (B9).
- **정확히 어디인지**는 물체 토큰과 그 이웃에 쓰여 있다 (B12).
- 그래서 전체 토큰 L1 은 '무엇' 을 크게 보상하고, 국소적인 '어디' 는 작게 보상한다.

## 4. 지금 결론과 다음

**결론 (세 predictor 공통)**
> 미래의 **"어디 (자리 · 속도)"** 는 마지막 문맥 블록에 보이는 것을 옮겨서 정한다. 과거로 이어 가지 않는다.
> - visible 은 그래서 2–3 블록 맞는다.
> - late (마지막에 안 보임) 는 처음부터 못 놓는다.
> - AR 은 흐려진 자기 출력을 다시 읽어 점점 멈춘다.
> - 가속 (중력) 은 블록 사이 속도 변화 = 과거가 필요한 양이라 반영되지 않는다.
>
> AR 이 나아진 것은 **"무엇 · 있음"** 을 과거에서 이어 가는 부분뿐이다.

**원인 후보 (측정됨, 확정 아님)**
- 목표가 '어디' 를 작게 본다 (B9 · B4).
- 학습 데이터에서 과거의 값이 작다 (B11).

**다음 학습 (사용자 실행)**
- A0 = AR 그대로
- A1 = + 문맥 끝 블록 가리기 (dropout)
- A2 = + 공간 대조 손실 (자기 자리 토큰과 가장 닮게)
- A3 = A1 + A2
- 판정: anchor 실험 · late 위치 · 복사 Δ · IntPhys 1 · 2

**열린 것**
- release 의 late 역사 의존 (실행 중)
- anchor 실험의 학습 없는 교차검증 (공 토큰 최근접 자리 찾기) — 미실행
- 가려진 물체를 encoder 가 따라가는지 — 지금 데이터로 못 잼 (가림막 교락)
