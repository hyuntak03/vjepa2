> 궤적 단위 split (`scripts/h1c_traj_split.py`) 과 같은 (v_T, x_T) 에서의 p 검정 (`scripts/h1d_p_side_v3.py`) 으로 다시 쟀다. 옛 → 새:
> 1. 제목 "가속은 입력 (z) 에 있다: 전이 실패는 읽기 실패가 아니다" → 위 제목. 결론 "전이 ◐ 의 '가속 미반영' 은 입력 부족이 아니라 predictor 미래 계산의 실패다" → **철회** (§0).
> 2. C32 r8 held-out R² "z 0.77 / encoder 최고 0.84 / predictor 문맥 L11 0.64" → 궤적 단위, 법칙당 12 궤적 학습: **z 0.76 [0.62, 0.84] / L24 0.83 [0.74, 0.87] / pctx L11 0.58 [0.34, 0.70]**.
>    법칙당 7 궤적 학습 (20 split) 이면 z **0.12 ± 0.32, 중앙값 −0.01** — 읽기가 학습 궤적 수에 묶여 있다 (§4-2).
> 3. r8 "C16 z 0.62 · C8 0.33" → **C16 0.51 [0.25, 0.65] · C8 0.01 [−0.22, 0.13]**. "문맥이 길수록 더 담는다" 는 방향만 남고 C8 은 0 이다.
> 4. 국소 가속 a 열 "C32 z 0.60 / C16 0.47 / C8 0.19" → **C32 0.33 [−0.05, 0.52] / C16 −0.03 / C8 −0.02**. a 열은 궤적 암기였다 (중간층 C32 만 0.45–0.47, CI 하한 0.12–0.16).
> 5. 속도 맞춤 법칙 분류 "C32 z 92.4 % vs 참 상태 59.9 %, chance 33 %" → 궤적 단위 **z 80.6 %** vs 유연한 상태 기준선 61.1 % · 입장 시각 기준선 84.7 % · 구간별 최빈 법칙 **45.8 %** (chance 33 % 가 아니다).
> 6. 대조 "참 상태 poly2 의 잔차 R² ≈ 0" → **정의상 0** 이다 (같은 poly2 로 잔차화했다). 대조로 쓰지 않는다. 유연한 상태 커널 (B_state) r8 0.09 [−0.08, 0.20] 와 섞음 ≈ 0 으로 바꿨다.
> 7. 설계 서술 "장면이 같고 운동 윤곽만 다르다 / 끝 속도를 맞춘 / 문맥 창 안에서 물체가 화면 안" → 끝 속도 중앙값이 7.05 / 8.2 / 9.68 px/튜블릿 (a / v / d) 로 **다르고**,
>    같은 속도에서 x_T 가 flat_v 보다 **+18.9 px (a) / −24.3 px (d)** 떨어져 있으며, **C32 에서는 83 % clip 이 문맥 도중에 화면에 들어온다** (C8·C16 은 전부 창 시작부터 화면 안).
> 8. 단서 5 "참 상태 대조 (60 %) 가 법칙 외 단서 몫의 상한" → **철회.** 궤적 단위 속도 맞춤 구간에서 상태 커널 61 %, 입장 시각을 더하면 85 %, 창 시작 위치를 더하면 75–96 % (전 속도로는 상태만으로 73 %).
> 9. p 쪽 "flat_a 슬롯 6–9 진실 칸 적중 0.45/0.62/0.43/0.17 vs 등속 칸 0.71/0.87/0.89/0.50 → p 는 가속을 따르지 않는다" → 이 대비는 약하다: p 는 flat_v 에서도 진실보다 12–36 px 뒤처지고 (공통 지연),
>    적중 규칙 (Chebyshev ≤ 1) 에서 flat_a 의 진실 칸과 등속 칸은 슬롯 6–9 에서 100 % 같거나 이웃이다 (같은 칸 29–64 %). 슬롯 6–9 합치면 (C16 L11) flat_a 진실 칸 0.42 = 귀무 (같은 법칙 다른 궤적) 0.42, 등속 칸 0.74.
>    대신 **같은 (v_T, x_T) 기준 모형**으로 재면 p 의 물체 자리 효과 / 참 가속 효과 = **flat_a −0.04 [−0.36, 0.13], flat_d 0.23 [0.00, 0.48]** (C16 L11, 슬롯 3–9, §4-4). 속도만 맞추면 flat_a 0.18 · flat_d 0.46 — 그 차이가 x_T 교락이다.
> 10. 해석 "미래 토큰이 그것을 쓰지 않는다 / 병목은 [P] 미래 쪽" → **철회.** 첫 판은 미래 토큰을 재지 않았다. 재 보니 마지막으로 본 자리의 p 미래 토큰 (L11) 에서 r8 잔차가 **C32 0.46–0.59** (같은 자리 z 0.76), **C16 0.12–0.18** (z 0.52) 로 읽힌다 (§4-5).
> 11. "a ≈ 0.05 px/프레임², r8 ≈ 7 px" → flat_a **+0.058** / flat_d **−0.075** px/프레임², 법칙별 r8 평균 **+8.4 / −10.7 px** (flat_v −0.01).
> 12. "속도는 모든 층에서 R² 0.99 (encoder L0 도 0.95)" → 출처는 `h1_v3.json` (6 법칙 2D, clip split): encF 0.99–1.00, pctx L11 0.98–0.99, **encoder L0 0.93–0.95**. 궤적 단위 (평지 3 법칙, |v_T|) 로는 z 0.98, encoder L0 0.78.
> 13. "encoder 최고층 L22–24" → **짝수 층 + L31 만** 훑었고 test 성능으로 골랐다 (선택 편향). 정정판도 같은 층 집합이다.
> 14. RollOutV2 (flat_a p 28 ≈ 등속 28, 진실 49) · RollOutV3 (flat_a 뒤처짐 −14 ~ −20 px) 를 지지 근거로 든 것 → **"일관되나 교락"** 으로 내린다. V2 flat_a 는 정지 출발 (a ∝ v, §7 에서 스스로 부적합이라 한 세트) 이고 49 px 은 거리 한계 구간 (40–60 px, CLAUDE.md §5-5) 이다. V3 수치는 flat_v 지연을 옆에 두지 않고 인용했었다 — 이 문서의 v3 argmax (C16 L11, 슬롯 5·7) 로는 flat_a 지연 −16 ~ −25 px 중 flat_v 공통 지연이 −12 ~ −20 px 이고 추가분은 4–5 px 다 (속도·x_T 미통제).

## 0. 결론

**처음 보는 궤적으로 재면, 등속 외삽이 못 맞히는 8 튜블릿 뒤 잔차 r8 은 문맥이 길 때만 z 에서 일부 읽힌다.**
법칙당 12 궤적으로 학습한 궤적 단위 R² (95 % CI, 궤적 bootstrap): **C8 0.01 [−0.22, 0.13] · C16 0.51 [0.25, 0.65] · C32 0.76 [0.62, 0.84]**.
법칙당 7 궤적 학습이면 C16·C32 의 z 도 중앙값 ≈ 0 이라 읽기가 학습 궤적 수에 묶여 있고, 국소 가속 a_T (마지막 3 튜블릿) 는 C8·C16 에서 어느 표현에서도 ≈ 0 이다.
r8 잔차는 사실상 **법칙 정체** (법칙 안 SD 0.2–2.0 px vs 법칙 평균 0 / +8.4 / −10.7 px) 라 "가속을 표현한다" 와 "창 시작 위치·입장 시각 같은 역사를 기억한다" 를 이 설계로 못 가른다 — 창 시작 위치 하나를 (x_T, |v_T|) 에 더한 기준선이 C16 0.97 이다.

**p 쪽: 같은 (v_T, x_T) 에서 p 의 물체 자리 (L11 argmax) 는 가속 효과를 보이지 않고 감속 효과는 일부만 보인다** —
참 효과 대비 flat_a −0.04 [−0.36, 0.13], flat_d 0.23 [0.00, 0.48] (C16, 슬롯 3–9); C8·C32 도 flat_a ≤ 0.07, flat_d 0.00–0.46 (모형 의존).
한편 C32 에서는 마지막으로 본 자리의 **p 미래 토큰에서도 r8 잔차가 0.46–0.59 로 읽힌다** (같은 자리 z 0.76).
→ **첫 판의 "입력 부족이 아니라 predictor 미래 계산의 실패" 는 철회한다.** 말할 수 있는 것은 기술까지다: 긴 문맥에서는 법칙·역사 정보가 입력에 일부 있고 (C32 는 p 미래 토큰에도 일부), p 의 물체 자리에는 가속 쪽 효과가 거의 없다. 원인이 predictor 의 미래 계산인지는 개입 없이 말할 수 없다.

## 1. 왜

09-19 성적표의 전이 ◐ ("방향·속도는 이어 가고 가속도는 반영 안 함") 는 predictor 탓으로 적혀 있지만,
**z 에 가속이 없으면 그건 읽기의 실패**다. 그 기준이 서 있지 않았다 — RollOut_v2 는 flat_a 가 정지 출발이라 a ∝ v,
ramp_a 는 경사가 장면 단서라 무효였다 (ctxenc 실험 2-1). 또 predictor 는 최종층 z 만 보므로, 중간층에만 있는 정보는 인터페이스에서 잃는다.
정정판은 여기에 두 질문을 더한다: (i) 그 정보가 **처음 보는 궤적**에도 읽히는가 (궤적 42 개뿐), (ii) 입력에 있다면 **p 의 물체 자리**와 **p 의 미래 토큰**에는 나타나는가 (같은 창에서).

## 3. 방법

- 데이터: **RollOut_v3 평지 세 법칙** (flat_v / flat_a / flat_d, 가능 clip) 1,176 clip = **궤적 42 개** (법칙마다 primary 6.0–10.5 의 7 속도 × secondary ±1) × 28 복사본 (모양 7 × 환경 4).
  모두 왼쪽으로 가고 y 는 152 px 로 같다. **법칙은 끝 속도·위치와 교락되어 있다**: |v_T| 는 flat_a 5.15–9.0, flat_v 6.0–10.45, flat_d 7.1–12.4 px/튜블릿,
  같은 속도에서 x_T 는 flat_v 대비 +18.9 px (a) / −24.3 px (d). 물체가 화면에 드는 프레임은 0–16 이라 **C32 문맥 [0, 32) 에서는 83 % clip 이 도중에 들어오고**, C8·C16 문맥에서는 전부 처음부터 화면 안이다.
  가속 크기: flat_a +0.058 / flat_d −0.075 px/프레임² (2 차 적합), r8 법칙 평균 +8.4 / −10.7 px (< 1 칸 18 px).
- 창 = 문맥 [32−C, 32), C ∈ {8, 16, 32}. 특징: 문맥 마지막 3 튜블릿의 **진실 물체 칸 3×3 창 평균** 을 이어 붙인 것 (3×D) — encoder 블록 l (**짝수 + L31**, LN), z (= encoder 최종 = predictor 입력),
  문맥 프레임만 넣은 target encoder, predictor 블록 l 의 문맥 토큰 (384 차원). 추출물은 첫 판과 같다 (`v3_h1`).
- 표적 (진행 방향 부호 정렬): v_T = x_T − x_{T−1},  a_T = x_T − 2x_{T−1} + x_{T−2},  r_k = x_{T+k} − x_T − k·v_T (k = 4, 8).
  a · r4 · r8 은 **train 에서만 맞춘** poly2(x_T, |v_T|) OLS 로 잔차화한다 (첫 판과 같음). |v_T| 는 원값으로 따로 잰다.
- **split (정정)**: group = `law|primary|secondary` (궤적). **split 과 λ-CV fold 모두 궤적 단위**, 법칙 층화.
  - **xfit (주 수치)**: 법칙마다 14 궤적을 7 fold (fold 당 법칙별 2 궤적) → 법칙당 **12 궤적 학습**, out-of-fold 예측을 모은 pooled R², 반복 3 회 평균. 95 % CI = 궤적 bootstrap (법칙 층화, 1,000 회).
  - **half (흔들림)**: 법칙마다 7 궤적 학습 / 7 궤적 test, 20 split. 평균 ± SD, 중앙값, 5–95 백분위.
  - **학습 곡선**: 법칙당 학습 궤적 7 / 9.3 / 12 / 13 (K = 2 / 3 / 7 / 14 fold), 반복 2 회.
- ridge: dual (Gram) + 고윳값 분해로 λ ∈ {1e-2 … 1e6} 경로. 특징 표준화는 전 clip 평균·SD (라벨 무관), 중심화는 train 안에서. half split 은 λ 가 격자 끝에 걸리는 비율이 특징에 따라 24–86 % (z 55–65 %) 다 (상수 예측으로 무너지는 경우가 많다).
- **기준선 (같은 ridge · 같은 split)** — [RBF(σ) + 선형] 커널, σ 와 λ 를 inner CV 로 함께 고른다 (일부러 유연하게 = 보수적 비교):
  - `B_state` (x_T, |v_T|): 잔차화 poly2 가 못 뺀 위치·속도 몫 — **법칙 × x_T 교락**이 여기서 잡힌다.
  - `B_entry` (x_T, |v_T|, t_entry): 입장 시각 (C32 만; C8·C16 은 모든 clip 0).
  - `B_xfirst` (x_T, |v_T|, x_first [, t_first]): 창 안에서 처음 보인 위치 (와 시각) — **관측 가능한 역사 1–2 개 수**.
  - `B_kin3` (x_T, |v_T|, a_T 참값): 특징 창 3 튜블릿의 국소 운동 상태를 완벽히 담았을 때의 천장 (a_T 는 CSV 0.1 px 반올림 잡음이 있다).
  - `shuffle`: z 행을 clip 단위로 섞음.
- 법칙 3-way 분류: one-hot ridge (λ 는 세 열 합 MSE). 전 속도 / 속도 맞춤 구간 (|v_T| 5 분위 중 세 법칙 모두 ≥ 10 clip — 구간 1–3, 672 clip, 24 궤적).
  사전 기준선 = 구간별 최빈 법칙 (전체 clip 기준) **45.8 %**.
- **p 쪽 (§4-4)**: `v3_h23` 의 자 없는 위치 읽기 (템플릿 = h_t 진실 칸 토큰, p^(L)_t 256 토큰과 cos → argmax 칸, 18 px), C8/C16/C32 × P32, L11 (주) · L6.
  슬롯 t (= T 뒤 k = t+1 튜블릿) 마다 D_true = dir·(x_{T+k} − x_T), D_p = dir·(x̂_p − x_T), D_cv = |v_T|·k, **참 효과 = D_true − D_cv = r_k**.
  궤적마다 28 복사본 평균 → **flat_v 14 궤적으로 기준 모형 D_p ≈ f(|v_T|, x_T)** 를 맞추고, 효과_p = D̄_p − f 를 flat_a · flat_d 궤적에서 잰다. **비율 = Σ효과_p / Σ참 효과** (슬롯 3–9 합침).
  f: 주 = [1, |v|, x_T]; 민감도 = [+ |v|·x_T], [1, |v|, |v|², x_T] (속도 포화 = 거리 한계 흡수), **공통 지지** (flat_v 의 (|v|, x_T) 범위 안 궤적만 — flat_a 4 · flat_d 6 궤적), 대조 = [1, |v|] (x_T 통제 없음).
  95 % CI = 궤적 bootstrap (flat_v · flat_a · flat_d 궤적 각각 복원 추출, 2,000 회).
- **p 미래 토큰 probe (§4-5)**: `v3_h23` vec, 같은 창 (C16/P32, C32/P32), 1 튜블릿 × 1280 (3×3 평균). 누수 없는 비교만 해석한다:
  LN(z)_T@W_T (문맥 끝 z, 마지막으로 본 자리) vs p^(L0/L6/L11)_t@W_T (같은 자리의 미래 토큰, 슬롯 3 → r4, 슬롯 7 → r8). 자리 W_T 는 문맥으로만 정해진다. 표적·split 은 위와 같다.

## 5. 해석

- **입력**: 긴 문맥 (C16, C32) 의 문맥 표현에는 처음 보는 궤적의 r8 을 (x_T, |v_T|) 너머로 맞히는 정보가 일부 있다 — 단 readout 을 법칙당 12 궤적 이상으로 학습할 때.
  C8 에는 없다. 그 정보가 "가속" 인지 "창 시작 위치 · 입장 시각 같은 역사" 인지는 이 설계에서 같은 것이다 (r8 잔차 ≈ 법칙 정체, (x_T, |v_T|) 에 역사 수 1–2 개를 더한 기준선이 0.90–0.97).
  → 능력 칸으로는 **"1 읽기 (가속) ◐ — 긴 문맥에서만, 국소 가속은 아님"**.
- **p**: 같은 (v_T, x_T) 에서 p 의 물체 자리에는 가속 효과가 없고 감속 효과는 일부 (창·모형 의존). 공통 지연 (flat_v 도 12–36 px 뒤처짐) 은 따로 있다.
- **입력과 p 의 사이**: C32 에서는 정보가 p 의 미래 토큰 (마지막 자리) 까지 선형으로 닿는데 (0.46–0.59) 물체 자리에는 가속 쪽 효과가 안 나타난다 — "정보는 있고 배치에 안 나온다" 는 **기술**은 가능하다.
  C16 에서는 미래 토큰의 그 자리에서도 약하다 (0.12–0.18, 같은 자리 z 0.52) — 이 자리 하나로는 정보가 줄었는지 다른 자리로 갔는지 모른다.
- 첫 판의 "병목 자리: [E] 가 아니라 [P] 미래 쪽" 과 "인터페이스 손실은 작다 (−0.07)" 는 **철회**. 궤적 단위로는 C16 에서 encoder 중간층 → z → predictor 문맥 토큰으로 가며 0.65 → 0.51 → 0.21 로 줄어드는 경향이 보인다 (CI 겹침, 차원 다름). 원인 자리를 말하려면 개입이 필요하다.

## 6. 못 하는 주장 (결론과 같은 비중)

1. **궤적이 42 개뿐이다.** 유효 n 은 clip (1,176) 이 아니라 궤적이다 — xfit 의 CI 는 궤적 bootstrap 이고 폭이 0.2–0.4 다. readout 이 학습 궤적 수에 묶여 있어 (§4-2) 법칙당 7 궤적 split 의 ≈ 0 과 12 궤적의 0.5–0.8 이 둘 다 참이다. **"z 에 가속이 있다/없다" 를 한 숫자로 말하지 않는다.**
2. **r8 잔차는 사실상 법칙 정체 (3 값)** 다 (법칙 안 SD 0.2–2.0 px, 법칙 평균 0 / +8.4 / −10.7). "가속을 표현한다" · "법칙을 알아본다" · "역사 (창 시작 위치 · 입장 시각) 를 기억한다" 를 이 설계로 못 가른다. 창 시작 위치 기준선 (B_xfirst) 이 C16 0.97, 입장 시각 기준선 (B_entry) 이 C32 0.90 이다.
3. **C32 는 입장 사건 교락**이 있다 (83 % clip 이 문맥 도중에 들어옴). C16 → C32 이득을 가속 표현으로 읽지 않는다. C32 에서 끝까지 화면 안인 clip 만 (a 29 % · v 14 % · d 7 %) 으로는 궤적 수가 모자라 재지 않았다.
4. **법칙은 끝 속도 · x_T 와 교락**되어 있다 (같은 속도에서 x_T +18.9 / −24.3 px). 잔차화 (poly2) 가 못 뺀 몫은 B_state (0.09) 로만 가늠했다.
5. **ridge 는 하한**이다 (선형 readout). 특징 창을 **진실 물체 칸**에 뒀다 — "정보가 어디 있는지 알면 읽힌다" 이지 "predictor 가 그 자리를 찾는다" 가 아니다.
6. **층 선택**: 짝수 층 + L31 만 훑었고 최고층은 test 로 골랐다.
7. **p 위치 읽기 (§4-4)**: 템플릿이 **진실 시각 · 진실 칸의 h 토큰**이라 argmax 가 진실 칸 쪽으로 끌릴 수 있다 (크기 미측정) — flat_a 효과가 ≈ 0 이라 크지 않아 보이지만 flat_d 의 일부 효과가 이 편향일 가능성은 남는다.
   기준 모형은 flat_v 14 궤적으로 맞추고 x_T 로 최대 10 px (a) · 13 px (d), 속도로 최대 2 px/튜블릿 **외삽**한다 (공통 지지 모형은 flat_a 4 · flat_d 6 궤적). 18 px 칸 양자화, 슬롯 3–9 에서만 합쳤다.
   **flat_d 의 부분 효과 (0.00–0.46) 는 모형·창에 따라 흔들려 확정하지 않는다.**
8. **p 미래 토큰 probe (§4-5)** 는 마지막으로 본 자리 (W_T) 하나다 — 물체가 떠난 자리라 **하한**이다. C16 의 약한 값은 "미래 토큰에 없다" 가 아니다 (CLAUDE.md §6: "p 에 정보가 없다" 는 probe 가 98–100 % 읽어 철회된 적이 있다).
   진실 미래 자리 (W_t) 의 p 는 자리 누수가 있고 깨끗한 자리 대조가 없어 해석하지 않았다.
9. **원인 귀속 금지**: "predictor 의 미래 계산이 가속을 반영하지 않는다" · "미래 토큰이 그것을 쓰지 않는다" 는 개입 없이 말할 수 없다. 이 문서의 p 쪽 문장은 전부 argmax 배치와 선형 probe 의 **기술**이다.
10. v3 평지 가속은 작다 (flat_a +0.058 / flat_d −0.075 px/프레임², r8 평균 +8.4 / −10.7 px < 1 칸). 참 효과가 작아 p 쪽 비율의 CI 가 넓다.
11. RollOutV2 · RollOutV3 결과는 **일관되나 교락**이다 (V2: 정지 출발 a ∝ v, 49 px 은 거리 한계 구간 / V3: flat_v 공통 지연이 대부분).
12. 법칙 **안** 회귀는 무의미하다 (가속이 법칙 안에서 거의 일정 → 잡음). 첫 분석 (`h1_analyze_v3.py`) 의 within R² 음수는 그 때문이다 — 다시 시도하지 말 것.
