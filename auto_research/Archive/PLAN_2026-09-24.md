**한 줄**: 출력 (p) 에서 "못 한다" 는 여러 자로 확인됐다. **빠진 것은 (i) 입력에 재료가 있는지의 공정한 기준 (가속도), (ii) predictor 안에서 어디서 끊기는지, (iii) 더 시간을 주거나 되먹여도 안 되는지, (iv) 외부 벤치마크 점수가 같은 짧은 조회로 설명되는지** 다.

## 1. 병목 지도 — 가설을 놓을 자리

```
픽셀 ─[E] encoder 블록 0..31 ─ z (최종, affine LN) ─[I] predictor_embed 1280→384
     ─[P] predictor 블록 0..11 (문맥 토큰 2048 + 미래 mask 토큰 2048) ─[O] norm+proj ─ p ─[S] 채점 |p − LN(h)|
```

| 자리 | 그 자리가 병목이면 보일 것 | 가설 |
|---|---|---|
| [E] | 상태 변수 (속도·**가속**·정체성) 가 z 에서 약하거나 중간층에만 있다 | **H1** |
| [I]·[P] 문맥 쪽 | predictor 안 문맥 토큰에서 속도가 사라진다 | H1 (predictor 문맥 토큰 층별) |
| [P] 미래 쪽 | 미래 토큰에 물체가 (a) 어느 층에서도 안 생긴다 / (b) 생겼다가 뒤층에서 사라진다 / (c) 옛 자리에 생긴다 | **H2** |
| [O]·출력 기하 | p 의 미래가 진실 궤적을 안 따라가고 옛 상태 또는 평균으로 간다 | **H3** |
| 사용 방식 | 시간을 더 달라고 해도 (단일 슬롯 질의) · 되먹여도 (자기회귀) 안 된다 | **H4 · H5** |
| [S] 벤치마크 | IntPhys 1 점수가 문맥 끝 바로 뒤 사건에서만 난다 | **H6** |

## H1. 읽기의 공정한 기준 — 가속도는 z 에 있는가 (encoder 층별)

**왜.** "전이 ◐ (가속 미반영)" 은 predictor 탓으로 쓰고 있지만, **z 에 가속도가 없으면 그건 읽기의 실패**다.
그 기준이 한 번도 서지 않았다 (RollOut_v2 는 flat_a 가 정지 출발이라 a ∝ v, ramp_a 는 경사가 장면 단서 — ctxenc 실험 2-1 무효).
또 predictor 는 **최종층 z 만** 본다. 물리 변수가 중간층에서 가장 잘 읽힌다는 보고 (Joseph 2026, 조사 에이전트 인용 — 원문 미확인) 가 있어
**최종층이 중간층보다 잃는다면 그 자체가 인터페이스 병목**이다.

**가설.** H1a: z (최종층) 에서 문맥 끝 속도·가속도가 선형으로 읽힌다 (가속 R² ≥ 0.5).
**대립.** H1b: 가속은 중간층에만 있고 최종층에서 약해진다 (인터페이스 병목) · H1c: 어느 층에서도 안 읽힌다 (읽기 실패).

| 결과 | 해석 | 논문에서 |
|---|---|---|
| H1a | 재료는 입력에 있다 → 전이 실패는 predictor 의 것 | 전이 ◐ 판정이 공정해진다 (가장 강한 근거) |
| H1b | 최종층이 가속을 버린다 | 병목 = encoder→predictor 인터페이스. frozen 에서 중간층을 predictor 에 넣는 개입이 다음 |
| H1c | 가속을 못 읽는다 | 전이 주장을 "속도까지" 로 줄인다. 지속·영속은 그대로 선다 |

**실험.**
- 데이터: **IntPhys 1 train** (vll5 `/local_datasets/world/IntPhys1`, 3,751 영상 × 100 프레임, 전부 가능; `status.json` 에 프레임마다 물체 3D 위치·**속도**·모양·재질, `masks/` 로 2D 위치·가시성) — 중력 낙하·굴림·정지·충돌이 섞여 가속이 속도와 독립적으로 변한다. 보조: RollOut_v2 (속도만).
- 표현: 문맥 encoder (online, 문맥 16 장 마스크 입력) 블록 l = 0..31 출력, predictor_embed 출력, predictor 블록 0..11 의 **문맥 토큰** — 모두 물체 3×3 창 평균, 튜블릿 T−2, T−1, T (T = 문맥 마지막). 천장 = target encoder 최종층 (32 장 전부 봄).
- 표적: `v = x_T − x_{T−1}`, `a = x_T − 2x_{T−1} + x_{T−2}` (튜블릿 중심 프레임의 물체 위치; 2D 화면 px 와 3D 둘 다), 모양 (3 종).
- probe: ridge (닫힌 해, λ 는 train 안 5-fold), **영상 단위 반반 split**, held-out R² / 정확도. 입력은 세 튜블릿 창을 이어 붙인 것 (3×D).
- 검증: (1) 위치만 준 지름길 (x_{T−2..T} 다항식 → a 는 정확히 계산되므로 "창 위치 정보" 가 새는지 대조: 창 내용 대신 창 좌표를 섞은 셔플 대조), (2) 공중/바닥 국면으로 층화 (가속이 "공중에 있다" 는 장면 단서로만 읽히는지), (3) target encoder 천장.
- 비용: GPU 추출 (문맥 encoder 32 층 hook, 창 평균만 저장 ≈ 250 KB/clip) 약 30 분 @ 4 GPU. 학습 없음 (ridge 는 CPU 초 단위).

**못 하는 주장 (미리).** 선형으로 안 읽힌다 ≠ 없다 (ridge 는 하한). IntPhys 1 의 가속은 대부분 중력 (방향 고정) 이라 "가속 크기" 와 "공중 여부" 가 얽힌다 → 층화로만 부분 분리.

**next.** H1a 면 H5 (되먹임) 로 가속 반영을 다시 본다. H1b 면 "중간층 z 를 predictor 입력에 섞는" frozen 개입 (범위 안) 을 설계한다.

## H2. predictor 안에서 미래 물체는 어느 층에서 생기고 어디서 사라지나

**왜.** 지금까지 predictor 는 **출력 p 로만** 봤다. knockout 은 "L8 의 문맥 조회가 결정적" (단일층 −14.4) 이라 하고,
attention 은 "층 0 은 자기 자리 기둥, 물체 궤적 조회는 층 5~6 최대" 라 한다. 둘을 잇는 **"미래 토큰의 내용이 층을 따라 어떻게 변하나"** 가 비어 있다.
사용자가 요청한 layer-wise predictor probing 의 핵심이고, 병목 층을 직접 가리킬 수 있는 유일한 측정이다.

**가설 (분기).**
- H2a **생성 실패**: 먼 슬롯의 진실 자리에는 어느 층에서도 물체가 안 생긴다 (조회가 첫 단계부터 못 찾음)
- H2b **생성 후 소실**: 중간층에서 진실 자리에 생겼다가 뒤층에서 흐려진다 (뒤층이 평균 쪽으로 당김)
- H2c **옛 자리 생성**: 미래 토큰이 물체를 마지막 관측 자리에 만든다 (복사)

**기호·공식 (파라미터 0 개 — 모델 자신의 머리를 쓰는 렌즈).**
```
q_t^(l)      predictor 블록 l 출력 중 미래 슬롯 t 의 토큰들 (384-d)
p_t^(l)    = predictor_proj(predictor_norm(q_t^(l)))        렌즈: 층 l 에서 멈추면 나올 예측 (L11 이면 p 와 비트 동일 — 검증됨)
h̄_t        = clip 평균 LN(h)  (토큰 자리·슬롯별)             "무조건 평균 미래"
W_t        = 슬롯 t 진실 물체 자리 3×3 토큰,   W_T = 문맥 마지막 튜블릿의 물체 자리 3×3

도착 (arrive)  A_t^(l) = cos( p_t^(l) − h̄_t ,  h_t − h̄_t )   on W_t      (진실 자리에 진실 물체가 있나)
머묾 (stay)    S_t^(l) = cos( p_t^(l) − h̄_t ,  h_T − h̄_t )   on W_T      (옛 자리에 옛 물체가 남았나; W_t 와 겹치지 않는 슬롯만)
```
평균을 빼고 cos 을 쓰므로 **p 의 크기 수축 (토큰 std 0.6) 에 무관**하다. 천장: h 자신 (A=1). 바닥: 다른 clip 의 p (셔플).

| A 높음 · S 낮음 | 진화 (진실 자리로 옮김) |
|---|---|
| A 낮음 · S 높음 | 옛 자리에 남김 (H2c) |
| A 낮음 · S 낮음 | 사라짐/흐려짐 |
| 층을 따라 A 가 올랐다 내려감 | H2b (뒤층 소실) |

**검증.** (1) 렌즈 L11 = p (비트 동일, 통과). (2) 렌즈가 중간층에서 무의미할 수 있다 (logit lens 의 알려진 한계) → 문맥 토큰에 같은 렌즈를 걸었을 때 LN(h) 와 얼마나 닮는지를 층별 "렌즈 신뢰도" 로 같이 보고, 신뢰도가 낮은 층은 읽지 않는다.
(3) 학습 자 없는 교차: 기존 `rollout2_distance_decay.py` 의 h 템플릿 argmax 적중을 L11 에서 재현해야 한다.
(4) 보조 probe: 층별 토큰 단위 선형 "물체다움" 판별기 (385 파라미터) 를 **문맥 토큰** 으로 학습 → 미래 토큰에 적용 (같은 층 같은 공간). 문맥 held-out 정밀도를 먼저 보인다.

**데이터·비용.** RollOut_v2 가능 clip (flat_v/a/d, arc, ramp_a/d; 6,272) — 1 칸 = 18 px = 1 패치, 위치 라벨 32 샘플. v11 visible/late 는 H3 뒤에.
GPU 1 회 추출 (문맥 enc + target enc + predictor 12 층 렌즈, 창만 저장 ≈ 4 MB/clip → 약 25 GB) 약 20 분 @ 4 GPU.

**못 하는 주장.** 렌즈는 "그 층에서 멈췄다면" 의 반사실이다 — 층이 정보를 **가졌다/안 가졌다** 가 아니라 **최종 머리로 읽히는 형태로** 가졌는지다 (보조 probe 가 그 차이를 메운다).

**next.** H2a 면 "조회 도달 범위" (H4 의 시간 질의 · 층 제한 knockout) 로, H2b 면 뒤층 개입 (렌즈 출력으로 채점 — frozen), H2c 면 H3 의 머묾 곡선으로.

## H3. 잠재 궤적 — p 는 h 의 궤적을 따라가나, 멈추나, 평균으로 가나

**왜.** 행동을 자 (학습된 위치 readout) 로만 읽어 왔고, 자는 물체가 없으면 기본값을 낸다 (하루를 잘못 읽은 적이 있다).
**잠재 공간에서 직접, 파라미터 없이** p 의 미래가 어디로 가는지를 재면 자의 교란이 없다. 또 "사라지나 / 옛 자리에 남나" 가 여기서 갈린다.

**가설.** p_t 는 슬롯이 멀어질수록 (i) 진실 궤적에서 멀어지고 (A_t↓), (ii) 옛 상태에 남지는 않으며 (S_t 낮음), (iii) clip 사이 다양성이 줄어 평균 미래로 간다 (D_t↓).
**대립.** (a) 진실 궤적을 끝까지 따라감 (진화) · (b) 옛 상태에 머묾 (복사).

**공식 (H2 의 L11 값 = p 에 더해).**
```
다양성 비   D_t = Σ_tok tr Cov_clip[p_t] / Σ_tok tr Cov_clip[h_t]          (슬롯 t 에서 clip 사이 퍼짐 — 1 이면 h 만큼 다양)
             → 수축 계수 s (토큰 std 0.6) 로 생기는 상수배와, 슬롯에 따른 감소를 가른다: D_t / D_0
진행 속도   V_t = ‖p_{t+1} − p_t‖₁ / ‖h_{t+1} − h_t‖₁                    (W 창 또는 전 토큰)
```
**읽는 규칙.** D_t 의 절대값은 수축 때문에 1 보다 작다 — **슬롯에 따른 변화 (D_t/D_0)** 만 읽는다. 거리 (마지막 관측 자리에서 진실 자리까지 px) × 슬롯 두 축으로 나눈다 (RollOutV2 §4 와 같은 칸).

**데이터·비용.** H2 추출과 같은 pass (추가 비용 0).

**못 하는 주장.** 평균 쪽 수축은 L1 학습의 조건부 중앙값 성질과 구분이 안 된다 — **원인 (목적함수) 으로 쓰지 않는다** (CLAUDE.md, discussion 한 문단).

## H4. 시간 조건 — 더 먼 미래를 물으면 예측이 그만큼 바뀌나

**왜.** "지속" 한계의 변수가 **거리 (v2)** 인지 **튜블릿 수 (v3)** 인지 모순이다. 또 한 번에 8 슬롯을 같이 넣는 방식이 미래 토큰끼리 영향을 줄 수 있다 (채점엔 −1.4 뿐이지만 예측은 42 % 움직인다).
**미래 슬롯 하나만** (그 튜블릿 256 토큰만 mask) 물으면 다른 미래 토큰 없이 "시간 k 뒤의 세상" 을 predictor 가 어떻게 그리는지 본다. RoPE 시간 위치를 통째로 밀면 (문맥·질의 모두 +s) **절대 위치 효과** 도 가를 수 있다.

**가설.** H4a (조회): 예측 변위가 k 에 비례하지 않고 약 2~3 칸에서 포화 · H4b (진화): k·v 에 비례 · H4c (위치 인공물): 절벽이 절대 튜블릿 위치에 묶여 s 를 밀면 같이 움직인다.

**공식.** `p^(k) = predictor(z, ci, ti = 튜블릿 C+k 만)`, k = 0..7 (v2) / 0..23 (v3, 64 프레임 stride 1 이면 튜블릿 32 개).
A_k, S_k (H2 와 같은 식) + h 템플릿 argmax 로 읽은 변위 d̂(k) vs 진실 d(k). 시간 이동: ci, ti 에 s·256 을 더해 (s = 0, 4, 8, 16) 같은 질의.

**비용.** predictor 만 반복 (문맥 encoder 1 회) — clip 1,000 개 × k 8 × s 4 ≈ 10 분 @ 1 GPU.

**못 하는 주장.** 단일 슬롯 질의는 학습 때 없던 마스크 모양이다 (사전학습 마스크는 공간 블록 × 시간 전체). 한 슬롯만 물어도 k=0 에서 원래 p 와 같은지를 먼저 확인한다 (분포 밖 정도의 대조).

## H5. 되먹임 — frozen predictor 를 자기회귀로 돌리면 상태가 진화하나

**왜.** 기제 R: 미래 토큰끼리 상태를 안 넘긴다 (`mask→mask` −1.4). 그렇다면 **추론 때 되먹임을 강제**하면? 두 결과 모두 논문이 선다:
되먹임이 지속을 늘리면 → "predictor 는 짧은 한 걸음 전이는 갖고 있고, 구조가 그것을 잇지 않는다" (쓰는 방식이 병목, frozen 개선 경로).
안 늘리면 → "한 걸음 전이 자체가 상태를 진화시키지 않는다" (학습된 계산이 병목 — 사용자 가설의 가장 강한 형태).

**공식.**
```
어댑터   A(y) = s̄ · LN(y) + m̄       (s̄, m̄ = 실제 z 토큰의 토큰별 std·평균의 평균 — 스칼라 2 개; LN(z) → z 는 토큰별 스칼라 두 개로 정확히 되돌려진다)
자기회귀  Z_0 = z (문맥 8 튜블릿);  p_j = predictor(Z_j, 질의 = 튜블릿 8+j);  Z_{j+1} = [Z_j ; A(p_j)]
교사강제  Z_{j+1} = [Z_j ; z_true(8+j)]      (실제 관측을 붙임 = 상한)
어댑터 검증  [Z_j ; A(LN(z_true(8+j)))] 가 교사강제와 같은 예측을 내는가 (어댑터 손실)
```
지표는 H2 의 A_j, S_j 와 h 템플릿 적중, 한 번에 예측 (one-shot) 과 나란히.

**비용.** clip 500 × 8 걸음 × 3 팔 ≈ 15 분 @ 1 GPU (걸음마다 predictor 1 회, 문맥 최대 16 튜블릿).

**못 하는 주장.** 되먹인 입력은 분포 밖이다 (p 는 수축돼 있다). 그래서 어댑터 검증 팔 (진짜 관측을 같은 어댑터로 넣은 것) 과의 차이만 predictor 의 몫으로 읽는다.

## H6. 외부 벤치마크 다리 — IntPhys 1 의 88.89 는 짧은 조회로 설명되나

**왜.** 논문의 동기는 IntPhys 1 88.89 → IntPhys 2 붕괴다. 우리 기제 (마지막 관측 근처만 그림) 가 맞다면 IntPhys 1 의 점수는
**사건이 문맥 끝 바로 뒤에 올 때만** 나와야 한다 (Garrido 격자가 창을 고르는 이유). 이게 보이면 "벤치마크 정답률 ≠ 상태 진화" 가 **외부 데이터에서** 선다 (use case: 평가 방법론 · 벤치마크 갭).

**공식 (GPU 불필요 — `per_window.json` 에 창마다 surprise 가 이미 있다).**
```
창 w = (시작 s, 문맥 C, skip 2, 32 장),  문맥 끝 raw 프레임 e_w = s + 2·C
사건 시차   τ_w = magic_tick − e_w               (raw 프레임; 1 튜블릿 = 4 raw 프레임)
창별 신호   Δ_w = S_imp,w − S_pos,w               (matched pair)
→ τ 구간별 평균 Δ 와 부호 정확도; 가림 (obj_vis) · 운동 (정지/이동) 으로 층화
```
**예측.** 조회면 Δ>0 이 τ ∈ [0, ~3 튜블릿] 에만 몰린다. 진화면 창 안의 먼 τ 에서도 Δ>0.
**못 하는 주장.** 180 쌍 · 방향별 n 5~7 — 칸 하나를 읽지 않고 τ 곡선의 모양만 읽는다. magic_tick 의 정확한 의미 (사건 시작 프레임) 는 먼저 영상으로 확인한다.
