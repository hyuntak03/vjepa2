## 1. 왜

~~P2 는 절벽 위치가 "마지막 관측 자리에서 약 2.6 칸 + 약 2 걸음" 이라는 **기술** 을 줬다.~~
→ P2 정정판 (VERIFY §P2) 은 위치 적중 판독의 절벽 거리를 **D0 2.6 [2.3, 3.2] + k 1.9 [1.5, 2.3]·δ** 로 **기술** 한다. 단서가 셋 붙는다.
- 사후에 고른 모형이고 판독에 따라 달라진다.
- D0 에는 판독 허용폭 약 1.5 칸이 들어 있다.
- 반경을 뜻하지 않는다. "진실을 3 튜블릿 따라가다 멈춤" 예측기가 이 식을 더 잘 맞춘다 (R² 0.991).

M4 의 질문은 이것이다. **미래 질의가 문맥 물체 토큰을 조회하는 범위가 칸 단위의 고정 반경처럼 움직이는가.**

사전 예측은 둘이었다.
- (a) 진실 칸 질의가 물체 궤적에 싣는 attention 이 **변위 거리 (칸)** 를 따라 균등으로 떨어지고, 그 모양이 stride 와 거의 무관하다.
- (b) 미래→문맥 조회를 반경 r 로 막으면 **d > r** 에서만 적중이 무너진다.

**판정.**
- (a) **미충족.** 떨어지는 모양이 stride 와 슬롯에 따라 다르고, 균등이 아니라 ring 귀무에 닿는 거리도 stride 마다 다르다.
- (b) **부분 충족.** d > r 에서는 무너진다. 그러나 r = d 에서도 손실이 있고, 원래대로 돌아오려면 r ≥ d+2 가 필요하다.

~~기전 가설: 미래 질의 토큰은 공간적으로 가까운 문맥 토큰을 조회하고, 물체의 과거 자리가 그 도달 범위 밖이면 물체를 가져올 길이 없다.~~ **철회** ("길이 없다" 는 불가능 주장이다). → 가설을 이렇게 고친다. 미래 물체 토큰은 문맥 물체 토큰에 대한 직접 조회를 필요로 한다. 그 조회가 닿는 범위는 거리와 슬롯에 따라 준다.

## 2. 설계

**팔.**
- s1_C16: raw [16,64), 문맥 8 / 미래 16
- s2_C16: raw [0,64), 8 / 8
- s4_C8: raw [0,64), 4 / 4

자유 운동 6 법칙의 가능 clip 588 개 (외형 1/4, 궤적 84 × 7) 를 쓴다. GPU fp32 + autocast fp16 이다.

**(a) attention.**
- query 는 슬롯 t 의 **진실 물체 칸** 미래 토큰이다. 층별로 head 평균 softmax 를 저장한다.
- key 질량은 넷이다.
  - 물체의 문맥 궤적 3×3 (자기 기둥과 겹치는 key 는 뺐다)
  - 마지막 관측 물체 3×3
  - 자기 3×3 기둥
  - 문맥 전체
- 정정: **균등 = 층 평균 문맥 질량 × (실제 key 수 / 문맥 key 수)**. 실제 key 수는 Σ_u |3×3(c_u) − 3×3(query)| 이고 가장자리에서 잘린 칸을 반영한다. 원판 분모 9·nc 는 근사였다. 원판 코드 주석에는 "상한", 문서에는 "key 수" 라고 적혀 코드와 달랐다.

**(b) knockout.**
- 미래 query → 문맥 key 를 Chebyshev 반경 r ∈ {1,2,3,5,8} 칸 밖이면 전 층에서 막는다. 미래↔미래와 문맥↔문맥은 연다.
- 적중 = 템플릿 argmax 가 진실 칸에서 1 칸 안.

**거리.** 원판 변위 d 는 **Euclid** 였고 knockout 반경 r 은 **Chebyshev** 였다. 정정판은 표를 **Chebyshev d** (0/1/2/3/4–5/6+) 로 다시 나눈다. 대응은 이렇다: Euclid 2–3 = Cheb 2, 3–4 = Cheb 3, 4–6 = Cheb 3–5, 6+ = Cheb ≥ 5.

**(정정판) r=∞ 위치 귀무 (읽기 규칙 2).**
- P2 의 `loc_tru` argmax 를 같은 clip 에서 가져왔다. M4 의 r=∞ 적중과 588 clip × 28 슬롯-팔 **100 % 일치** 한다.
- 귀무는 같은 법칙 · 다른 궤적 **전부** 의 진실 칸에 같은 판정을 걸어 기대값을 낸다. P2 는 무작위 한 개를 썼다.
- **knockout 팔은 argmax 를 저장하지 않아서 막았을 때의 귀무를 알 수 없다.** 막은 팔에서는 r=∞ 귀무를 참고선으로만 쓴다.

**(정정판) ring 귀무 (CPU fp32 부분집합, 궤적당 1 clip).**
- query 행 전체 attention 을 다시 뽑는다.
- obj key 마다, 같은 튜블릿 · 같은 Chebyshev 거리에 있는 비물체 key 의 평균 밀도를 기대값으로 쓴다. obj key 수로 가중한다.
- 여기서 obj 는 **화면 안 문맥 튜블릿만** 쓴다. `objall` 은 GPU 정의다.
- 같은 판에서 두 가지를 더 쟀다.
  - **P-query**: p 가 외형 템플릿으로 물체를 둔 칸의 질의
  - **head 별** obj−ring. 짝수 clip 에서 가장 큰 (층, head) 를 고르고 홀수 clip 에서 평가한다.

**알려진 원자료 한계.**
- GPU `obj_traj` 는 화면 밖 문맥 튜블릿을 가장자리 칸으로 잘라 넣는다. s2·s4 clip 의 **78.6 %** 가 해당한다 (평균 2.42/8, 1.38/4 튜블릿). s1 은 0 % 다. 문맥 마지막 튜블릿과 미래 튜블릿은 모두 화면 안이다.
- CPU 부분집합에서 화면 밖 튜블릿이 있는 행만 보면, 화면 안만 쓴 obj 가 s2 4.94 vs `objall` 3.75, s4 6.00 vs 4.18 이다. 곧 GPU 표의 s2·s4 ×U 는 **24–30 % 낮게** 잡혀 있고, stride 차이는 **과소평가** 된 방향이다.

CI 는 모두 궤적 군집 bootstrap 이다 (GPU 588 clip = 궤적 84 × 7. CPU 부분집합은 궤적당 1 clip 이라 clip 군집 = 궤적 군집).

> - 필요성만 보였다. 충분성과 "상태가 없다" 는 재지 않았다.
> - 조회는 Cheb d ≤ 3 에서 물체 선택적이다 (거리 맞춤 귀무 대비 +2.3 ~ +11.7 ×U, CPU 부분집합).
> - 조회가 닿는 거리는 칸 수로 고정되어 있지 않다. 슬롯이 늦을수록, stride 가 작을수록 짧다 (s4 flat_a 는 Cheb 4–5 에서 적중 .98).
> - 표적: 적중·템플릿 모두 표준 양방향 h.

**못 하는 주장** (결론과 같은 비중).
- **충분성.** 반경 안이면 반드시 가져온다는 것은 재지 않았다. **상태 부재** 도 마찬가지다. knockout 은 "문맥 조회가 필요하다" 만 보인다. 어디를 조회할지는 슬롯에 따라 달라지므로 "상태가 전혀 없다" 는 이 자료로 말할 수 없다.
- **attention 은 상관 지표다.** 적중/실패 조건부 차이는 원인과 결과를 가르지 못한다. 실패하면 진실 칸 토큰이 물체가 아니다.
- **거리와 슬롯이 강하게 상관한다** (0.89–0.92). 같은 d 의 늦은 슬롯은 느린 궤적이라 속도와 교락된다. 속도 분위를 맞춘 비교는 하지 않았다 (원자료로 가능).
- **ring 귀무 · P-query · head 별은 CPU fp32 부분집합** (궤적당 1 clip) 이다. GPU 전 clip 판은 재추출 뒤에 나온다.
- **head 별 결론은 선택 뒤 평가 한 번뿐이다** (짝수 clip 선택 → 홀수 clip 평가). GPU 원자료는 head 평균만 저장했다.
- **knockout 은 분포 밖 개입이다** (문헌 경고: zero-ablation 과대평가). r = d 에서도 −0.06 ~ −0.28 손실이 있다. 막은 팔은 argmax 가 없어서 막았을 때 물체가 옛 자리로 복사되는지 알 수 없다. 막은 팔의 귀무도 모른다.
- 원판 못 하는 주장 가운데 고친 것 (보존):
  - ~~head 평균이다 — 특정 head 가 먼 조회를 맡을 가능성은 배제 안 됨 (층별 최대도 d 6+ 에서 0.02–0.04).~~ → CPU 부분집합에서 head 별로 쟀다. 먼 물체 궤적을 고르는 head 가 있다 (§3-6).
  - ~~여기서는 막는 대상이 "먼 문맥 key" 이고 d ≤ r 에서 원래 적중이 그대로 나와 (예: s1 d 1–2 r=2 .97 = ∞ .98) 개입 자체의 손상은 작다.~~ → 그 예는 r = d+1 이다. r = d 에서는 손실이 있다 (위 항목).
  - "왜 공간 국소적인가 (RoPE 공간 성분, 사전학습 tube 마스크에서 같은 자리의 다른 시각을 조회하도록 배웠을 가능성) 는 가설이다" → 아래 discussion 문단으로 옮겼다.
- **s2·s4 의 GPU ×U 는 화면 밖 문맥 튜블릿이 섞여 약 24–30 % 낮다.** stride 차의 크기는 하한이다.
- **s4 는 nc = 4 라 균등 정규화가 다르다.** 그래서 s4 대 s1·s2 의 ×U 직접 비교는 하지 않는다 (ring 대비만 쓴다).
- "절벽" 을 첫 교차점으로 읽지 않는다. 먼 슬롯에서 되살아나는 경우가 있다 (VERIFY C13).

**discussion 한 문단 (가설, 검증 안 됨).** 조회가 공간적으로 가까운 key 에 몰리는 이유로 두 후보가 있다. 하나는 RoPE 의 공간 성분이고, 다른 하나는 사전학습에서 같은 자리의 다른 시각을 조회하도록 배웠을 가능성이다. 둘 다 이 자료로 가를 수 없다. 목적함수를 원인으로 걸지 않는다.
