# R4 적대 검증 — 왜 안 옮겨지나 (측정) · 어떻게 학습해야 전이되나 (진단 학습) (2026-10-30, 검토 [R])

> **질문** — [X1] 의 attention 경로 측정 (E37–E39b) 과 [X2] 의 진단 PFT 네 run (E40–E44) 의 결론이 산출물 재계산 · 코드 읽기 · 사후 검사 뒤에도 서나?
> **답** — 수치는 모두 다시 셌고 맞다. 해석은 다섯 군데를 좁힌다. (1) 학습 seed 가 데이터 순서에 닿지 않는다. 그래서 T0 두 seed 는 같은 클립을 같은 순서로 봤고, 잡음 폭 0–1.8 pt 는 과소평가다. (2) T1 의 이득은 T0 대비로만 선다. 릴리즈 대비로는 구분되지 않는다. IntPhys 1 이득은 영속 쌍이 아니라 주로 모양 불변 쌍에서 나왔다. (3) 경로와 행동의 block 수준 연관은 릴리즈의 경로 세기로도 거의 같은 크기로 나온다. 즉 장면 기하가 만든다. (4) 릴리즈 키우기에서 자리가 참 자리로 옮겨지는 것은 정답 자리에 query 를 둔 설계 탓에 생긴다. (5) v11 에서 VOBench PFT 의 자리는 학습 없는 기준선과 "구분 안 됨" 이 아니라 그보다 20–27 pt 낮다.
> **다음** — 학습 없이 할 남은 실험은 세 답을 바꿀 여지가 작다 → **멈춘다**. 남은 것은 사용자 결정이다. 순서는 표본기 seed 고치기 → T1 을 seed 여럿으로 · 두 손잡이 분리.

## 0. 어떻게 검토했나

- **결과 파일 · 원배열에서 다시 셌다** [측정]
  - E39 행렬 다섯 열 × 11 행: 원배열 (clip 별 surprise) 에서 쌍 정답 · 릴리즈 대비 G · 복사 대비 · B 방향을 다시 만들었다. 모든 칸이 소수 첫째 자리까지 같다.
  - E37 · E37b: 원배열에서 고리 비 · 거울 비 · 경로 세기를 독립 코드로 다시 셌다. 모두 같다.
  - E38 · E38b · E39b: 결과 파일 값을 확인했다.
  - X2 표 (E40–E43): 원배열에서 주 칸 정확도 · T0 대비 · 릴리즈 대비 · 복사 대비 CI · 예측 오차 비를 다시 셌다. 모두 같다. 단 T1 − 릴리즈 IntPhys 1 의 CI 하한은 bootstrap 표본에 따라 0.0 (X2) · −1.7 (검토) 로 0 근처에서 흔들린다.
  - 끝 자리 지표 (λ · β) 와 Garrido 점검은 결과 파일에서 확인했다.
- **코드와 학습 기록을 읽었다**: attention 가로채기 · 대조 상자 정의 · 막기 마스크 · 판독기 절차 · 자리 지도 · 학습 config 넷 · 학습 로더의 seed 경로 · 학습 step 별 손실 기록.
- **새 사후 검사** (학습 · GPU 없음, BOARD 에 판정 규칙을 먼저 적음):
  - N1 = 막은 p 로 판독기를 다시 맞추기.
  - N4 · N4b · N4c = 경로 세기와 사라짐 정답의 block 수준 연관, 층을 맞춘 판, 릴리즈 경로 세기 대조.
  - N6 = 두 통과 (X1 · X2) 의 IntPhys 쌍 판정 일치.
- ⚠️ **사전 등록 전에 돌린 것** — X2 판의 쌍 단위 전이 수 (T1 이 새로 맞힌 쌍 중 릴리즈도 맞힌 쌍) 를 재계산 중에 먼저 돌렸다. BOARD 에 그렇게 적었다. 판정을 뒤집는 데는 쓰지 않고 해석을 좁히는 데만 쓴다.
- 커밋 · 새 학습 없음. 기존 파일은 읽기만 했다.

## 2. 왜 late 에서 물체 꼴이 다시 나타날 자리로 안 옮겨지나 (E37 · E38 · N1)

### 2-1. 왜

X1 의 답은 두 겹이다. 첫째, 릴리즈의 다시 나타날 자리 query 는 과거 물체 자리를 안 본다. 둘째, 그 간선은 '무엇' 만 나르고 사라짐 정답 · 자리는 다른 경로가 정한다. 두 번째 주장은 두 곳이 약할 수 있다 [이론].
- 막기 하락이 깨끗한 p 로 맞춘 판독기로 잰 값이다. 이 조사의 Q1 이 보였듯 판독기는 형식이 바뀌면 정보가 있어도 떨어진다.
- 키우기의 자리 이동이 설계 때문에 생겼을 수 있다.

### 2-2. 어떻게

- N1: 막은 p 의 train block 으로 같은 절차의 판독기를 다시 맞추고 test block 에 걸었다. 관문은 깨끗한 p 로 E38 값 재현이다.
- 키우기는 코드로 확인했다. query 는 정답 미래 자리 3×3 이고, 대조는 key 상자만 세로로 5 칸 옮긴다.

### 2-3. 결과

**N1** [측정, 과제당 train 15 block · test 15 block (30 clip). X1 문서의 "train block 30 개 정도" 는 clip 수다]

| 과제 | 깨끗한 PFT | 깨끗 판독기 → 막은 p | **막은 p 로 다시 맞춤** | 대조 막기 다시 맞춤 | 릴리즈 |
|---|---:|---:|---:|---:|---:|
| primitive 모양 | 85.6 | 57.9 | **65.3 [52, 77]** | 85.6 | 43.6 |
| primitive 색 | 63.6 | 40.9 | **42.9 [28, 58]** | 62.6 | 29.3 |
| realistic 색 | 65.2 | 41.9 | **46.5 [31, 62]** | 65.2 | 36.9 |
| realistic 모양 | 99.5 | 94.1 | 85.3 [75, 94] | 99.5 | 61.3 |

- 관문 통과: 깨끗한 값 넷이 E38 과 같다.
- 판정 (사전 등록): 대상 과제 셋 모두에서 다시 맞춘 하락이 원 하락의 73–91 % → **"정보 감소가 선다"**.

**키우기 설계** [이론 + 측정]
- 물체 팔에서는 정답 자리 query 가 물체가 있는 문맥 상자를 보게 되고, 빈 장면 팔에서는 같은 자리의 빈 배경을 보게 된다. 그러니 두 팔의 차이는 바로 그 query 자리에 생긴다. 존재 대비 최대 자리가 참 자리로 옮겨지는 것은 정답 자리를 query 로 골랐기 때문이다.
- 그 증거가 둘 있다 [측정]. 키운 릴리즈의 v11 자리 (91.8 %) 가 깨끗한 PFT (76.6 %) 보다 높다. [L] 의 E38c 에서는 β ≥ 16 에서 대조 키우기도 자리 100 % 가 된다.
- 끌어온 내용의 방향은 실제 미래 물체 차와 안 맞는다 (E38c: 참 상자에서 cos 0.24–0.46, PFT 0.86) [측정, [L]].

### 2-4. 해석

- [측정] **릴리즈의 다시 나타날 자리 query 는 과거 물체 상자를 같은 거리의 다른 상자만큼만 본다** (고리 비 1.06). 보일 때는 균등의 2.8 배로 본다. PFT 는 이 경로를 6–8 배로 켠다.
- [측정] **PFT 에서 그 직접 간선을 끊으면 다시 나타날 자리의 정체 정보가 실제로 줄어든다** (다시 맞춰도 PFT 이득의 2/3 이상이 안 돌아온다, 과제 셋). 그러나 사라짐 정답 (100 → 100) 과 존재 대비 자리 (99.5 → 97.5) 는 그대로다.
- [측정 + 이전 라운드] 사라짐 정답에 대해 지금 말할 수 있는 것:
  - 참 자리의 국소 내용이 **필요하지는 않다**: 물체 칸을 안 바꿔도 93 % (R2 E23), 간선을 끊어도 100 %.
  - 맞는 물체 토큰을 넣으면 **오른다** (R1 E7, 캐시판 72 %).
  - attention 으로 끌어온 과거 내용은 방향이 틀려 **부족하다** (최대 +10 [3, 18]).
- [추측] 그래서 "꼴이 안 옮겨지는 이유" 의 한 부분은 query 가 과거 물체를 안 가져오는 것이다. PFT 는 가져온 내용을 그 자리 · 그 시점의 꼴로 바꾸는 쪽도 함께 바꿨다. 사라짐 정답을 실제로 정하는 경로 (어느 토큰 · 층) 는 아직 모른다.
- 단서: 직접 간선만 끊었다 (문맥 안에서 섞인 물체 정보는 남는다). 판독기는 선형이다. VOBench 30 · 15 block 과 v11 224 block 뿐이다. attention 은 bf16 이다.

## 6. 세 질문의 답 (사용자 보고용)

**왜 late 에서 물체 꼴이 다시 나타날 자리로 안 옮겨지나** (확신 중간)
- 릴리즈에서 다시 나타날 자리의 미래 출력은 문맥에서 물체가 보이던 자리를 같은 거리의 다른 자리만큼만 본다 (비 1.06). 보일 때는 균등의 2.8 배로 본다. PFT 는 이 경로를 6–8 배로 켠다.
- PFT 에서 그 경로를 끊으면 다시 나타날 자리의 정체 정보가 실제로 줄어든다. 판독기를 다시 맞춰도 PFT 이득의 2/3 이상이 안 돌아온다. 그러나 사라짐 정답과 존재 대비 자리는 그대로다.
- 릴리즈에서 그 경로를 억지로 키우면 끌어온 내용이 실제 미래 물체와 방향이 다르다. 사라짐은 최대 +10 pt 만 오른다.
- 그러니 "가져오지 않는다" 가 한 원인이고, 가져온 것을 그 자리의 꼴로 바꾸는 쪽도 필요하다.
- 남은 것: 사라짐 정답을 정하는 경로는 모른다. 직접 간선만 끊었다. VOBench · v11 합성 판뿐이다.

**전이가 되려면 학습을 어떻게 바꿔야 하나** (아직 처방 아님, 확신 낮음)
- 이번 진단 run 가운데 단서는 T1 (보폭 2 · 3 반반 + 잘라 옮기기) 하나다. VOBench late 정답을 100 % 유지하면서 IntPhys late 판에서 T0 보다 +10–12 pt (IntPhys 1) · +4 pt (IntPhys 2) 높았다. 처음 보는 생성기의 예측 오차는 1–2 % 줄었다.
- 그러나 학습 전 릴리즈 대비로는 +8.3 [−1.7, 18.3] · +3.3 [−2.5, 10.0] 로 구분되지 않는다. IntPhys 1 이득은 영속이 아니라 모양 불변 쌍에서 왔다. 표준 Garrido 칸에서는 릴리즈보다 6.7 pt 낮다.
- 학습 seed 가 데이터 순서를 안 바꿔서 잡음 폭을 과소평가했다. 생성기를 섞은 T2 는 더 좁다.
- 지금 말할 수 있는 것: "끝 자리 · 시간 척도를 흩뜨리면 VOBench 레시피의 외부 손해가 줄어든다 (seed 하나)". "전이가 된다" 는 아니다.

**지금까지 학습한 판 중 학습 생성기 밖 late 영속 이득을 낸 것** (확신 중간–높음)
- 자리까지 보여 준 것은 없다.
- 같은 계열 (VOBench → v11 · v11_realistic, v11 → v11_realistic) 은 사라짐 89–99 % 지만, 다시 나타난 물체 자리는 학습 없는 기준선 (100 %) 보다 10–27 pt 낮다. 이 판들은 자리 평가로 추적과 사전을 가르지 못한다.
- IntPhys 2 PFT → v11 은 복사를 넘는 사라짐 점수 (46.9 vs 25.0) 를 냈지만 자리는 릴리즈보다 +11 pt 뿐이다.
- 합성 → IntPhys 는 원 PFT 들에서 0 칸이다. T1 은 T0 대비로만 오르고 영속 쌍이 아니다.

## 7. 다음 요청 (학습 없이 — 세 답을 바꿀 여지 작음, 그래서 멈춤)

1. **IntPhys 1 O1 의 자리 라벨을 화소 차로 만들기** (CPU) — O1 block 의 가능 영상 둘 (물체 있음 · 없음) 의 프레임 차 (±2 단계 이상) 로 물체 마스크를 얻는다. 이것으로 IntPhys 1 영속 칸에 존재 대비 자리 지도와 전형 자리 기준선을 붙인다 (R2 규칙 1). 이후 T1 류 run 의 IntPhys 평가에 필요하다. T1 의 O1 이득은 순 +1 쌍이라 지금 답은 안 바뀐다.
2. **끝 자리가 전형과 다른 자리 판** (GPU 1, R3 다음 요청 1 그대로) — 범위 안 잘라 옮기기 창과 VOBench 보폭 2 판에서 E39b 를 다시 잰다. v11 은 기준선 100 % 라 자리 평가가 안 된다.
3. **사라짐 정답을 정하는 토큰 찾기** (GPU 1–2) — 토큰별 surprise 기여 지도를 저장해, IntPhys 2 PFT · VOBench PFT 의 v11 사라짐 쌍을 뒤집는 칸이 어디인지 본다 (참 자리 · 가림막 · 배경).
4. (선택) 키우기 대조를 "query 를 옮긴 판" 으로 — 존재 대비 자리가 query 를 따라가는지 확인해 §2 의 설계 지적을 수치로 닫는다.

## 9. 단서 (결론과 같은 무게)

- 사후 검사 N1 · N4 · N6 은 사전 등록 뒤 돌렸다. 쌍 전이 수는 그 전에 돌렸다 (기록함).
- N4c 의 "장면 기하" 는 릴리즈 세기와의 연관으로 추론한 것이다. 어떤 기하인지는 안 쟀다.
- N1 은 선형 판독기 · 15 block 이다. 비선형 판독기로 정보가 돌아올 가능성은 남는다.
- 표본기 지적은 코드와 손실 기록 상관에서 나온 것이다. 실제로 뽑힌 클립 번호는 기록이 없어 직접 대조하지 못했다.
- 다시 안 센 것: E38c (리더 탐색) 의 원배열 · 끝 자리 지표 λ · β 의 block 별 계산 (결과 파일 값만 확인) · Garrido 칸의 원 하네스 출력.
