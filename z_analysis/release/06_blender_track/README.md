# ⑥ BlenderTrack — 미래 경로를 외울 수 없는 학습셋 (2026-10-31)

> **질문** — predictor 가 "학습에서 본 궤적 꺼내기" 대신 "문맥의 운동으로 미래 자리 계산하기" 를 배우게 하려면 학습셋이 어때야 하나? 그런 학습셋을 Blender 로 빠르게 만들 수 있나?
> **답** — 눈높이 3D 장면의 모든 요인을 연속 무작위로 뽑아 렌더한다. late 미래 경로가 VOBench 의 21 가지에서 **약 5,800 가지** (설계 2,000 clip, 보폭 3) 로 늘고, late 창을 가진 clip 이 68 % 다. GPU 8 장으로 clip 당 약 1 초, 라벨 투영 오차 0.000 px.
> **다음** — 본 렌더 (학습 4,000 + 검증 400 clip) 가 끝나면 학습 창 표본기와 공간 점유 head 를 붙인다 (학습 실행은 사용자 결정). 그릇 덮기 (containment) 는 v1 에서 넣는다.

## 용어

| 용어 | 뜻 |
|---|---|
| clip | 렌더 한 단위. 30 fps × 180 장 (6 초), 256×256 |
| 설계 | clip 하나의 모든 요인 (카메라 · 물체 · 운동 · 가림막 · 배경) 을 뽑은 것. 렌더 없이 몇 ms 에 만든다 |
| 창 | 학습 · 평가 때 clip 에서 잘라 쓰는 샘플 열. 보폭 s 프레임마다 한 장, 문맥 16 샘플 + 미래 16 샘플 |
| 블록 | 연속 2 샘플 (encoder 의 시간 단위). 창 하나 = 문맥 8 블록 + 미래 8 블록 |
| target | 라벨과 가림 사건이 붙는 물체 하나. 나머지는 방해 물체 · 정지 잡동사니 |
| 가림 사건 | target 이 가려지도록 세운 판. 사건 시각과 가려지는 시간을 먼저 뽑고, 그 구간 target 실루엣을 덮게 판을 짓는다 |
| 서 있는 판 · trapdoor 판 | 서 있는 판 = clip 내내 서 있음. trapdoor 판 = VOBench 처럼 바닥에 누워 있다가 가림 구간에만 일어섬 |
| late 창 | 문맥 마지막 샘플에서 target 이 가려져 있고 (가려진 비율 ≥ 0.9, 화면 밖 포함), 문맥 앞쪽에서 보였고, 미래에서 다시 보이는 창 |
| 미래 경로 | 미래 8 블록마다 target 중심이 든 칸 (16×16 토큰 격자) 의 순서 |
| amodal 칸 · visible 칸 | 64×64 격자 (한 칸 = 화면 4×4 px) 에서, 가려져도 target 이 있는 칸 · 카메라에서 처음 맞는 것이 target 인 칸 |

## 1. 왜 했나

- binding 학습 (`../03_binding_train/`) 의 이득은 **학습에 있던 미래 경로에만** 있었다 (본 경로 사라짐 A +35.2 · 처음 보는 경로 +2.8) [측정].
- VOBench late 의 미래 경로는 21 가지뿐이다. 궤적 묶음으로 나눠도 test late 경로 66.7 % · 끝 칸 100 % 가 학습에 있다 [측정].
- 가설: 경로가 연속으로 흩어진 학습셋에서는 경로를 꺼내 쓰는 풀이가 안 통한다. predictor 가 문맥의 운동에서 자리를 계산하게 되고, 그것이 다른 생성기로 옮겨진다 [추측 — 학습 후 검증].
- 조건 (사용자): 위에서 내려다보는 시점은 안 된다. 사람 눈높이에서 지면을 비스듬히 보는 장면 (IntPhys · VOBench 와 같은 구도).

## 2. 무엇을 어떻게 했나

### 2-1. 장면 (설계 요인, 모두 연속 무작위)

| 요인 | 범위 | VOBench |
|---|---|---|
| 카메라 | 높이 1.2–2.6 m · 아래로 2–14° · 렌즈 18–32 mm (수평 화각 90–59°) | 2.1 m · 3° · 22 mm |
| 바닥 · 배경 | 질감 4 종 (바둑판 · 잡음 · 벽돌 · 나뭇결) × 색 · 축척, 뒷벽 45 %, 하늘 색 · 해 방향 · 세기 | 바닥 + 뒷벽 / 건물 자산 |
| 물체 | 모양 8 종 (구 · 정육면체 · 원뿔 · 원기둥 · 원환 · 피라미드 · 캡슐 · 다이아몬드) × 연속 색 · 거칠기, 출발 깊이에서 화면 지름 18–56 px | 6 종 × 8 색, ~29 px |
| target 운동 | 등속 24 % · 빨라짐/느려짐 (되돌아옴 포함) 18 % · 감속 정지 12 % · 옆 가속 (지면 곡선) 16 % · 던짐 (수직 포물선 + 튕김) 26 % · 정지 4 % | 6 가지 (등속 · 빨라짐 · 느려짐 · 경사 둘 · 정지) |
| 속도 | 화면 폭 0.10–0.50 / 초, 방향은 좌우 ± 깊이 성분 (±35°, 20 % 는 ±70°) | ~0.24 / 초, 좌우 |
| 가림 사건 | target 마다 0–3 개 (10 · 35 · 35 · 20 %), 가려지는 시간 0.15–1.2 초, 판 = 서 있는 판 55 % · trapdoor 45 %, 사건 시각 75 % 는 clip 가운데 30–70 % | 1 개, 2k 샘플 (0.2–0.6 초), trapdoor |
| 무관한 판 | 0–2 개 (판이 있음 ≠ target 이 가려짐) | 없음 |
| 방해 물체 · 잡동사니 | 움직이는 방해 물체 0–2 · 정지 잡동사니 0–3 | 없음 |

- **거절 조건** — target 이 화면 안 ≥ 50 % 프레임 · 보이는 프레임 ≥ 45 % · 판 뒤에 숨은 구간 ≤ 2 초 · 화면 크기 (√가로×세로, 실제 치수) 중앙값 ≥ 18 px (최소 ≥ 11 px). 물체 · 판끼리 바닥에서 부딪히지 않는다.
- 운동은 해석식이다 (물리 엔진 없음). 가운데 시각에 target 이 화면 가로 30–70 % 에 오도록 출발점을 옮긴다. 빠른 물체를 거절로 걸러 느린 쪽으로 치우치지 않게 하려는 것이다.
- 그림자는 켰다 (사실성). 숨은 물체의 자리를 그림자가 알려줄 수 있다 → 4 단서.

### 2-2. 라벨 (프레임마다)

- target 과 방해 물체마다: 위치 (m) · 회전 · 투영 중심 (px) · 투영 상자 · 깊이.
- 64×64 amodal 칸 · visible 칸. 렌더와 같은 장면에서 ray 를 쏴서 낸다.
  - amodal 칸은 그 물체만 따로 맞힌다.
  - visible 칸은 장면 전체에서 처음 맞는 것이 그 물체인 칸이다.
- 판의 각도. 설계 전체도 clip 옆에 저장한다.
- 공간 점유 head 의 목표 (블록 · 토큰마다 target 이 차지하는 비율) 는 amodal 칸을 4×4 로 묶어 바로 얻는다.

### 2-3. 렌더 전 검사 (설계만, 렌더 없이)

- 설계 2,000 clip 에서 보폭 2 · 3 · 4 의 모든 창을 만든다.
  - late 창의 비율 · late 창을 가진 clip 의 비율을 센다.
  - 서로 다른 late 미래 경로 수와 샘플당 이동 (px) 을 센다.
- 가려짐은 설계 근사다 (판과 화면 밖만, 물체끼리 가림은 안 셈). 실제 학습 창은 렌더 라벨로 고른다.

### 2-4. 렌더

- Blender 5.0.1 을 파이썬 모듈로 쓴다. Cycles · OptiX · RTX 3090 에서 16 샘플 + 잡음 제거 (OIDN).
- 장면 바탕은 프로세스마다 한 번 짓고, clip 마다 물체 · 판만 바꾼다.
- Eevee 는 화면 없는 노드에서 GPU 문맥 (EGL) 을 못 잡아 쓸 수 없다.

## 4. 해석

- **미래 경로의 종류는 VOBench 의 약 270 배다** [측정]. 21 가지를 외워서 푸는 길은 막힌다.
- **"test 경로가 학습에 있는 비율" 은 이 학습셋에서는 외우기의 척도가 아니다** [이론].
  - 보폭 3 에서 두 절반 사이 칸 경로 겹침은 79 % 다 [측정].
  - 연속 설계는 경로 공간을 촘촘히 덮는다. 그래서 칸 단위로는 같은 경로가 우연히 많이 나온다.
  - 외우기 대 계산은 학습에 없는 것으로 가른다.
    - 다른 생성기: VOBench · v11 · IntPhys 1 · 2 · 실제 영상.
    - 학습 범위 밖의 운동: 예를 들어 더 빠른 속도 · 학습에 없는 운동 종류를 뺀 판.
- 아직 모른다 [추측]: 이 학습셋으로 학습한 predictor 가 다른 생성기의 late 에서 오르는지.

**단서**
- 겉모습이 단순하다: 단색 물체 · 절차 질감 · 실제 사물 메시 없음. VOBench (UE) · 실제 영상과 렌더러가 다르다. 평가에서는 생성기 단서를 줄이는 쪽이라 장점일 수 있지만, 실제 영상으로 옮겨지는지는 따로 재야 한다.
- 물체끼리 부딪힘 · 그릇 덮기 · 굴러 떨어짐이 없다. 운동은 해석식이다 (v1 에서 containment 추가).
- 그림자가 숨은 물체의 자리를 알려 줄 수 있다. 필요하면 그림자 끄기를 설계 요인으로 넣는다.
- late 판정 · 경로 수는 설계 근사로 셌다 (판 · 화면 밖만). 물체끼리 가림은 렌더 라벨에만 있다.

## 5. 다음 (학습 실행은 사용자 결정)

1. **학습 창 표본기**
   - 보폭 2–4, 문맥 4–12 블록 · 미래 4–8 블록으로 가변이다.
   - late 창을 약 50 % 로 과표집한다. late 창은 렌더 라벨의 visible 칸으로 판정한다.
2. **공간 점유 head**
   - predictor 토큰마다 target 이 차지하는 비율을 선형으로 읽는 head 다.
   - 목표는 블록 · 토큰마다의 amodal 비율이다.
   - binding 항과 함께 쓴다.
3. **평가**
   - 검증 400 clip (seed 1): 같은 생성기 안의 내삽이다.
   - VOBench_v2 late 의 처음 보는 경로 · v11 · IntPhys 1 · 2 late · Rubric 실제 영상: 생성기 밖이다.
4. **v1:** 그릇 덮기 (containment) · 움직이는 가림막을 넣는다.
