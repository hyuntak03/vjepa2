# ⑧ Rubric 에서 PFT 는 왜 안 오르나 — 릴리즈 · VOBench PFT · V3 PFT (2026-11-01)

> **질문** — 합성 영상으로 이어 학습한 predictor (VOBench PFT · V3 PFT) 는 합성 벤치와 다른 생성기 (CLEVRER) 에서는 크게 오르는데, 실제 영상 Rubric 에서는 왜 릴리즈와 같은가?
> **답** — PFT 는 "물체가 다시 나타난다" 는 기대를 **학습셋의 재등장 시간표 모양 그대로** 미래에 넣는다. 그런데 Rubric 에서는 그 기대가 **어느 블록에도 켜지지 않는다**. 재등장 타이밍이 학습과 달라서도 (같은 타이밍이어도 0), 샘플 간격이 달라서도 (간격 2 배에서도 유지) 아니다.
> **다음** — Rubric 물체 자리 토큰만으로 채점해 "켜지지 않음" 을 확정한다. 그 뒤 무엇이 이 기대를 켜는지 (손으로 덮는 사건 · 실제 배경) 를 학습셋 쪽에서 가른다.

## 용어

| 용어 | 뜻 |
|---|---|
| 릴리즈 | 공개 V-JEPA 2 ViT-H predictor. encoder 는 세 모델 모두 릴리즈 그대로 고정 |
| VOBench PFT | 릴리즈 predictor 를 VOBench_v1 학습 절반 (+ gravity) 으로 이어 학습한 판 (30 epoch) |
| V3 PFT | 릴리즈 predictor 를 BlenderTrack v3 전체 학습 목록 (14,272 clip, 절반은 물체 없는 장면) 으로 이어 학습한 판 (2,000 step, seed 1 개) |
| 복사 기준선 | 예측 없이 마지막 문맥 블록을 미래에 그대로 둔 것 |
| 샘플 · 블록 | 샘플 = 모델이 받는 32 장 중 한 장 (문맥 16 + 미래 16). 블록 = 연속 두 샘플. 미래 블록은 8 개 |
| 샘플 간격 | 샘플 하나가 실제로 몇 초인가 (예: 0.1 초) |
| surprise S | 예측 미래와 실제 미래 latent 의 L1 평균. 클수록 놀랍다 |
| quad | 같은 영상에서 만든 네 클립: 있음→있음 · 있음→없음 (사라짐) · 없음→있음 (생겨남) · 없음→없음 |
| 짝 A · B | A = 문맥에 물체 있음 (있음→있음 vs 사라짐). B = 문맥에 물체 없음 (없음→없음 vs 생겨남). 짝 안 두 클립은 문맥이 같다 |
| 쌍 차이 m | S(불가능) − S(가능). 0 보다 크면 정답 |
| 문맥 효과 c | m_A + m_B. 문맥에 물체가 있었다는 사실이 예측을 물체 쪽으로 당기는 정도. S(있음→있음) 대비 % |
| 물체 미래 편향 b | (m_B − m_A) / 2. 문맥과 상관없이 "물체가 있는 미래가 더 놀랍다" 는 정도. S 대비 %. **m_A = c/2 − b 라서 A 를 맞히려면 c > 2b 가 필요하다** |
| H · R | H = 문맥 끝에서 이어서 완전히 가려진 샘플 수. R = 다시 보이기 시작하는 첫 미래 샘플 (0 = 미래 첫 샘플) |
| 물체 기대 E_j | 두 미래가 모두 빈 짝 (사라짐 vs 없음→없음) 에서 S 차를 S 로 나눈 것, 미래 블록 j 마다. 미래가 비었으니 "물체 있던 문맥의 예측이 블록 j 에 넣은 물체 몫" 이다. **PFT − 릴리즈** 로 읽는다 (목표 latent 쪽 공통 모양을 뺀다) |

자료는 Rubric Office 실제 영상 20 개 (quad 20 = 짝 40) 를 violation 시점 앞뒤 균일 16 + 16 장으로 채점한 것이다 (`../04_rubric_office/`). 이 문서의 Rubric 채점에서 릴리즈 전체는 47.5 % 다. 시트 값 52.5 % 와는 거의 동점인 쌍 하나가 뒤집힌 차이다.

## 1. 쌍 차이 분해 — 판정은 모델이 아니라 영상이 정한다

**왜** — Rubric 정답률이 세 모델 모두 50 근처다. PFT 가 아무것도 안 바꾼 것인지, 바꿨는데 판정까지 못 가는 것인지 가르려 했다.

**어떻게** — 쌍 차이를 문맥 효과 c 와 물체 미래 편향 b 로 나눴다. 같은 분해를 PFT 가 잘 되는 v3 test (V3 PFT 학습 도메인) · CLEVRER (다른 생성기) 에도 걸었다.

**결과** [측정]

| 벤치 | 릴리즈 c/S | VOBench PFT c/S | V3 PFT c/S | 복사 c/S | b/S (릴리즈) | A 정답률 (릴리즈 → V3 PFT) |
|---|---:|---:|---:|---:|---:|---|
| v3 test (1,719 quad) | 2.77 % | 5.94 % | **10.21 %** (×3.7) | 1.59 % | 2.63 % | 18.4 → 77.1 |
| CLEVRER (396 quad) | 2.40 % | 4.97 % | **6.48 %** (×2.7) | 1.01 % | 2.20 % | 17.9 → 71.2 |
| **Rubric (20 quad)** | **0.082 %** | 0.091 % | **0.093 %** (×1.13) | 0.069 % | 0.30 % | 25.0 → 30.0 |

- Rubric 의 문맥 효과는 합성의 약 1/30 이다. 편향이 그 4 배라서 A 가 체계적으로 틀린다 (c/(2b) = 0.13–0.14).
- PFT 가 Rubric 문맥 효과를 바꾼 크기: V3 PFT − 릴리즈 +0.07 [−0.13, +0.26] ×10⁻³ (영상 bootstrap). 복사와도 차이가 없다 (+0.01 [−0.59, +0.57]).
- **판정이 거의 모델과 무관하다.** 40 쌍 중 세 모델 판정이 같은 쌍 35, V3 PFT 와 복사가 같은 쌍 36.
- PFT 는 Rubric 의 실제 미래를 오히려 더 못 맞힌다. 가능 미래 S 를 릴리즈와 비교하면 이렇다.

  | | v3 test | CLEVRER | IntPhys 1 late | IntPhys 2 late | Rubric |
  |---|---:|---:|---:|---:|---:|
  | V3 PFT | −9.4 % | −7.2 % | −2.6 % | −1.7 % | **+1.5 %** |
  | VOBench PFT | −0.9 % | −1.2 % | +0.1 % | +0.7 % | **+3.3 %** |

**해석**
- Rubric 에서는 PFT 가 학습한 변화가 문맥 효과로 나타나지 않는다 [측정].
- 판정은 영상마다 정해진 편향을 따른다 [측정].

## 2. 화소 점검 — 인페인팅 흔적 문제는 아니다

**왜** — 불가능 클립은 물체를 인페인팅으로 지운 것이다. 그 흔적이 판정을 정하는지 확인했다.

**어떻게** — 물체 미래와 빈 미래 프레임을 256² 로 늘려 화소 차 (|Δ| > 25) 를 셌다.

**결과** [측정]
- 물체가 다시 보이기 전의 미래 프레임은 20 영상 모두 **화소까지 같다**.
- 다시 보인 뒤 두 미래가 다른 토큰은 0.4–12.9 % (중앙 약 3.5 %) 다. VOBench 의 물체 토큰 비율 3–5 % 와 비슷하다.
- 공 · 손 영상 일부 (lightball 3 · handball 3 · plantcupball2) 는 0.4–2.4 % 로 작다.
- 블록 단위로 보면, 다시 보이기 전 블록의 문맥 효과는 세 모델 모두 0 에 가깝다 (−0.001 ~ +0.063 ×10⁻³). 다시 보인 블록에서만 생긴다 (릴리즈 +0.76 · V3 PFT +0.91).

**해석** — 두 미래의 차이는 다시 보인 물체뿐이다. 그 크기도 합성과 크게 다르지 않다 [측정].

## 3. 재등장 타이밍 분포 — Rubric 은 VOBench 와는 다르고, v3 와는 대부분 겹친다

**왜** — PFT 가 학습셋의 재등장 타이밍을 외워서, 타이밍이 다른 Rubric 에서 안 되는지 보려 했다.

**어떻게** — 다섯 세트를 같은 정의 (H · R, 샘플 단위) 로 셌다.

**결과** [측정]

| 세트 | 샘플 간격 | H 중앙 (범위) | R 중앙 (범위) | 실제 가림 길이 중앙 (범위) |
|---|---:|---|---|---|
| VOBench PFT 학습 (late 108) | 0.10 초 | 2 (1–3) | 2 (1–3), **늘 H 와 같다** | 0.40 초 (0.20–0.60) |
| v3 학습 (물체 있는 7,136) | 0.10 초 | 3 (1–7) | 3 (1–12) | 0.60 초 (0.20–1.90) |
| v3 test (1,719) | 0.10 초 | 3 (1–7) | 4 (1–11) | 0.70 초 (0.20–1.80) |
| CLEVRER (396) | 0.08 초 | 0 (0–4) | 5 (0–10) | 0.40 초 (0.16–0.80) |
| **Rubric (20)** | **0.23 초** | **6 (1–9)** | **6 (1–15)** | **2.82 초 (0.47–5.64)** |

- VOBench 학습셋은 타이밍이 사실상 세 값 (H = R = 1 · 2 · 3) 뿐이다. Rubric 은 R ≤ 3 이 25 % 뿐이고, 그것도 거의 가려지지 않는 lightball 셋이다.
- v3 학습셋은 범위가 넓다. Rubric 20 개 중 16 개가 v3 의 (H, R) 범위 안이다. 범위 밖은 H 8–9 인 넷이다 (bagduck1 · mugduck6 · handball2 · plantcupball2).
- CLEVRER 는 66 % 장면에서 문맥 마지막 샘플에 물체가 아직 일부 보인다 (완전히 가려지는 것은 미래 첫 샘플부터). 진짜 late 인 장면 (가림 시작 ≤ 샘플 13, 35 개) 에서는 PFT 가 오히려 더 잘 된다 (V3 88.6 · VOBench 80.0 · 릴리즈 0.0).

## 4. 같은 타이밍 대조 — 타이밍이 맞아도 Rubric 에서는 이득이 0

**왜** — 3 절에서 V3 PFT 의 학습 타이밍은 Rubric 과 대부분 겹쳤다. 타이밍이 맞는 영상에서 V3 PFT 가 기대만큼 나오는지 봤다.

**어떻게** — Rubric 영상마다 v3 test 에서 같은 타이밍 (H · R 각각 ±1 샘플) 인 block 을 모았다. 그 block 들의 A 정답률을 그 영상의 기대값으로 삼았다. 같은 타이밍이 20 block 이상 있는 영상 16 개로 비교했다.

**결과** [측정]

| 모델 | 같은 타이밍 v3 test 기대 A | Rubric 실제 A |
|---|---:|---:|
| 릴리즈 | 20.5 | 18.8 |
| VOBench PFT | 45.0 | 31.2 |
| **V3 PFT** | **77.6** | **31.2** |
| 복사 | 30.7 | 31.2 |

**해석**
- 릴리즈는 타이밍이 예측하는 그대로 나온다. V3 PFT 의 이득 (+57 pt) 만 Rubric 에서 통째로 사라지고 복사와 같아진다 [측정].
- 그러니 **"Rubric 의 타이밍이 학습과 달라서 안 오른다" 는 기각**한다.
- 다만 이것은 "PFT 가 타이밍을 외웠나" 에 대한 답이 아니다. 그건 6 절에서 본다.

## 5. 샘플 간격 (fps) — 간격을 두 배로 해도 PFT 이득은 남는다

**왜** — PFT 가 옮겨진 세트 (v3 test 0.1 초 · CLEVRER 0.08 초) 와 안 옮겨진 세트 (Rubric 0.23 초 · IntPhys 1 late 0.21 초) 가 샘플 간격으로 갈린다. 간격 (= 샘플당 움직임 크기) 이 원인인지 봤다.

**어떻게**
- 같은 CLEVRER 장면 · 같은 문맥 끝 시점에서 샘플 간격만 0.08 → 0.16 초로 바꿨다.
- 원본 렌더가 장면당 36 장 (0.08 초 간격) 뿐이라 0.16 초로는 32 샘플이 안 나온다. 그래서 **문맥 8 + 미래 8 창** 으로 두 간격을 비교했다.
- 사라짐 · 생겨남 클립은 원본 렌더 (물체 있음 / 빈) 를 다시 보이는 프레임에서 이어 붙여 다시 만들었다. 원 클립과 화소까지 같음을 12 장면 × 4 조건 × 32 장으로 확인했다.
- 두 창 모두에서 미래 안에 다시 보이는 장면 381 개를 장면끼리 짝지어 비교했다.
- 주 지표는 돌리기 전에 정했다: 문맥 효과 비율 (PFT ÷ 릴리즈) 과 사라짐 A 이득 (PFT − 릴리즈).

**결과** [측정]

| | 0.08 초 | 0.16 초 |
|---|---:|---:|
| 문맥 효과 비율, VOBench PFT | 1.49× [1.46, 1.53] | 1.52× [1.49, 1.54] |
| 문맥 효과 비율, V3 PFT | 1.62× [1.57, 1.68] | **1.78×** [1.74, 1.82] |
| 같은 R (= 3) 에서 A 이득, VOBench PFT | +19 pt (32 장면) | +16 pt (124 장면) |
| 같은 R (= 3) 에서 A 이득, V3 PFT | +16 pt | +16 pt |
| 전체 A 이득, V3 PFT | +1.8 pt | +22.6 pt (차 +20.7 [+16.5, +24.9]) |

- 전체 A 이득이 커진 것은 간격 효과가 아니라 **타이밍 효과**다.
  - 간격이 길어지면 같은 실제 시간에 다시 보이는 샘플이 창 앞쪽으로 온다 (R 중앙 5 → 2).
  - 그러면 물체가 보이는 미래 블록이 늘어난다. 릴리즈 (0.8 → 12.9) 와 복사 (3.4 → 16.5) 도 같이 오른다.

**해석** — 간격을 1.6 배 (학습 0.1 초 대비) 까지 늘려도 PFT 의 상대 문맥 효과는 줄지 않는다. 다시 보이는 시점을 맞추면 이득도 같다. **샘플 간격은 0.16 초까지는 원인이 아니다** [측정].

## 6. 물체 기대 곡선 — PFT 는 재등장 시간표를 외웠고, Rubric 에서는 그것조차 켜지지 않는다

**왜** — 4 절은 "타이밍이 달라서 Rubric 이 안 된다" 만 기각했다. PFT 가 무엇을 배웠는지, 즉 재등장 시점을 장면에서 읽는지 학습셋 시간표를 넣는지는 따로 재야 한다.

**어떻게**
- 미래 블록마다 물체 기대 E_j 를 쟀다. 두 미래가 모두 비었으니 실제 재등장과 상관없이, 모델이 언제 물체가 돌아온다고 기대하는지만 드러난다.
- 릴리즈 · 복사에도 있는 공통 모양 (블록 1 · 4 가 높고 블록 5 가 꺼짐) 은 목표 latent 쪽 성질이라 PFT − 릴리즈 로 뺐다.
- 판정 규칙:
  - 실제 다시 보이는 블록과 상관없이 같은 모양이면 → 학습셋 시간표를 넣는 것이다.
  - 실제 다시 보이는 블록을 따라 움직이면 → 장면에서 시점을 읽는 것이다.

**결과 1 — 합성 (v3 test): 모양이 실제 재등장과 무관하게 고정** [측정]

PFT − 릴리즈 의 E_j (%). 열은 미래 블록이다 (블록 하나 = 0.2 초).

| | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| VOBench PFT, 실제 다시 보임 블록 0–1 (819) | +0.39 | +1.52 | +1.19 | +1.98 | +1.61 | +1.67 | +1.29 | +1.98 |
| VOBench PFT, 실제 다시 보임 블록 4 이후 (298) | +0.03 | +0.80 | +0.71 | +1.31 | +0.56 | +0.82 | +0.63 | +1.04 |
| *VOBench 학습셋: 이 블록까지 다시 보인 비율* | *31 %* | *100* | *100* | *100* | *100* | *100* | *100* | *100* |
| V3 PFT, 실제 다시 보임 블록 0–1 | +1.43 | +3.08 | +2.86 | +3.57 | +3.73 | +3.65 | +3.33 | +5.31 |
| V3 PFT, 실제 다시 보임 블록 4 이후 | +0.82 | +1.00 | +0.95 | +1.89 | +2.28 | +3.12 | +3.15 | +5.28 |
| *v3 학습셋: 이 블록까지 다시 보인 비율* | *15 %* | *54* | *71* | *83* | *92* | *100* | *100* | *100* |

- **VOBench PFT 는 물체가 블록 4 이후에야 나타나는 장면에서도 블록 1 부터 물체를 넣는다.** 크기만 작아지고 시작 블록이 같다. 블록 0 값이 평탄 구간의 약 1/4 인 것도 학습셋에서 블록 0 에 다시 보이는 비율 (31 %) 과 맞는다.
- **V3 PFT 는 끝으로 갈수록 커지는 경사이고, 최대는 실제 재등장과 상관없이 늘 블록 7 이다.**
- 일부 예외: V3 PFT 는 늦게 나타나는 장면에서 앞 블록 값이 작아진다 (블록 1: +3.08 → +1.00). 학습 시간표가 넓어 장면을 조금은 읽는다.
- CLEVRER 에서도 같은 꼴이다. V3 PFT 최대는 다시 보임 시점과 상관없이 늘 블록 7, 전체 평균 +1.45 %.

**결과 2 — Rubric: 어느 블록에도 물체를 넣지 않는다** [측정]

PFT − 릴리즈 의 E_j (%), 20 영상, 영상 bootstrap 95 % CI.

| | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 평균 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| VOBench PFT | −0.15 | −0.07 | +0.04 | +0.13 | +0.10 | −0.10 | −0.02 | −0.11 | **−0.02** |
| V3 PFT | −0.13 | −0.10 | +0.00 | +0.02 | −0.11 | −0.24 | −0.10 | −0.24 | **−0.11** |

- 블록별 CI 는 대부분 0 을 포함하고, 일부는 약간 음수다 (V3 블록 5: [−0.38, −0.12]).
- 합성의 같은 지표 평균은 +0.8 ~ +3.4 % 다.
- 다시 보이는 시점별로 나눠도 (5 · 7 · 8 영상) 전부 0 근처다.

**해석**
- **PFT 는 재등장 시점을 장면에서 읽기보다 학습셋의 평균 시간표 모양으로 물체를 넣는다** [측정: 모양이 실제 재등장과 무관 · 추측: 학습셋 시간표와 닮은 것이 그 원인]. 기존 결과 (PFT 는 학습에 있던 미래 경로에서만 이득, 끝 자리 사전 — `../03_binding_train/` · `../../transfer_gap/`) 와 같은 방향이다.
- **Rubric 이 안 오르는 이유는 그 시간표가 틀려서가 아니다.** 원인이 시간표 불일치라면 엉뚱한 블록에서라도 양수가 나와야 하는데, 어느 블록에도 없다. **실제 영상에서는 이 학습 효과 자체가 켜지지 않는다** [측정].

## 정정 기록 (지우지 않는다)

- ⚠️ **철회 — "PFT 는 재등장 타이밍을 외운 게 아니다" (11-01 대화 중).** 4 절이 기각한 것은 "Rubric 타이밍 불일치가 원인" 뿐이었다. 외웠는지는 6 절에서 따로 쟀고, 외운 쪽이다.
- ⚠️ **정정 — CLEVRER 샘플 간격은 0.16 초가 아니라 0.08 초다** (원본 25 fps, 간격 2). 처음에 "간격이 1.6 배인 CLEVRER 도 옮겨졌다" 로 간격 가설을 반박했던 근거는 무효다. 대신 5 절의 시험으로 갈랐다.
- ⚠️ **정정 — CLEVRER 재등장 시점 R 의 정의 버그.** 문맥 끝에 물체가 아직 일부 보이는 장면에서, 가려지기 직전 샘플을 "다시 보임" 으로 셌다. 지금은 원 데이터의 "다시 보이는 샘플" 로 센다 (3 · 5 절).
- ⚠️ **알게 된 것 — CLEVRER 점수가 영상 압축에 흔들린다.** 같은 프레임을 mp4 로 읽을 때 (원 채점 · 시트 값) 와 PNG 로 읽을 때가 다르다.

  | 릴리즈 | 51.3 | 54.5 |
  | VOBench PFT | 77.0 | 67.6 |
  | V3 PFT | 81.5 | 75.1 |

## 단서

- **표본이 작다.** Rubric 독립 단위는 영상 20 개다. 같은 타이밍 대조는 16 영상, 물체 기대 곡선의 시점별 칸은 5–8 영상이다.
- **물체 기대 E_j 는 전체 토큰 평균이다.** Rubric 은 손 움직임 때문에 surprise 가 커서 물체 몫이 더 묽어질 수 있다. 물체 토큰 비율 자체는 합성과 비슷하다 (2 절). 물체 자리 토큰만으로 다시 재야 "켜지지 않음" 이 확정된다.
- **"학습셋 시간표와 닮았다" 는 해석이다.** V3 PFT 의 블록 7 이 튀는 것은 시간표로 설명되지 않는다.
- **간격 시험은 0.16 초까지다.** Rubric 은 0.23 초다. 문맥 8 + 미래 8 창은 표준이 아니고 모든 모델의 점수를 낮춘다 (0.08 초에서 A 1–7 %). 그래서 비율과 같은 R 비교로 읽었다. 생성기 하나다.
- **학습 seed 는 하나다** (V3 PFT).
- Rubric 영상은 4:3 을 정사각으로 늘려 채점했다. 짝 문맥이 화소로 같지 않은 영상이 4 개 있다 (`../04_rubric_office/` 단서).
