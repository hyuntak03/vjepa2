# 지금 문제는 무엇인가 — 근거 카드로 정리 (2026-10-31)

> **질문** — 물체가 문맥 끝에서 가려지면 (late), predictor 는 "물체가 사라진 미래" 를 자연스럽게 본다. 이게 "binding 문제" 인가?
> **답** — binding 은 **증상**에 가깝다. 근거가 가장 많이 가리키는 곳은 **"미래 어디에 둘지"** 다. 이 자리를 마지막 관측에서 가져오는데, late 는 마지막 관측에 물체가 없다.
> **다음** — "어디" 를 토큰 단위로 직접 재는 판독 (카드 밖 실험 ①), 그리고 경로를 외울 수 없는 학습셋 (BlenderTrack) 의 전이 평가 (실험 ②).

---

## 0. 먼저 읽을 것

### 용어

| 용어 | 뜻 |
|---|---|
| late | 문맥 마지막 몇 장에서 물체가 가려진 채 미래로 넘어가는 조건 |
| visible | 문맥 내내 물체가 보이는 조건 (비교 기준) |
| 사라짐 A | 물체가 있던 문맥에서 "있음 미래" 대 "빈 미래" 를 가르는 쌍. 빈 미래를 더 놀랍게 봐야 정답 |
| z · p · h | z = 문맥 encoder 출력 · p = predictor 가 낸 미래 · h = 실제 미래를 목표 encoder 로 본 것 |
| 판독 | 표현에서 물체의 모양 · 색을 맞히는 작은 분류기의 정확도 |
| 이식 | z 로 학습한 판독기를 p 에 그대로 건 정확도. 높으면 "같은 꼴로 실렸다" |
| 복사 | 예측 없이 마지막 문맥을 미래에 그대로 둔 기준선 |
| PFT | 릴리즈 predictor 를 특정 데이터로 이어 학습한 판 (encoder 고정) |

### 확실한 정도 표시

| 표시 | 뜻 |
|---|---|
| 🟢 확실 | 효과가 크고 신뢰구간이 기준선과 안 겹친다. 여러 데이터에서 같거나 사전 등록했다 |
| 🟡 보통 | 효과는 크지만 데이터 하나 · 판독기 하나 · seed 하나다 |
| 🔴 약함 | 신뢰구간이 기준선과 겹치거나, 표본이 작거나, 사후에 고른 분석이다 |

"다시 확인" 칸 — ✅ = 이번 (10-31) 에 산출물에서 숫자를 다시 계산했다 · 📄 = 원 문서의 숫자를 옮겼다 (그 문서는 당시 산출물에서 검증했다).

## 1. 한 장 요약

| 층 | 한 줄 | 근거 카드 | 확실한 정도 |
|---|---|---|---|
| 정보 | encoder 에는 가려진 물체의 정보가 있다 | E1 | 🟢 |
| 무엇 | 예측 미래에 정체가 **약하게, 다른 꼴로** 있다 | E2 | 🟡 |
| 어디 | 그 정체가 다시 나타날 자리에 **모여 있지 않다** | E3 · E4 | 🟡 |
| 어디의 출처 | 미래 자리는 **마지막 관측**이 정한다 | E5 | 🟡 |
| 개입 | 참 자리에 넣으면 크게 오른다 (단, 복사와는 비슷) | E6 | 🟡 |
| attention | 과거 물체 자리를 안 보지만, 그것만 고쳐선 안 풀린다 | E7 | 🟡 |
| 학습 | 고쳐도 **자리를 외워서** 고친다 → 다른 데이터로 안 옮겨진다 | E8 · E9 | 🟢 |
| 채점 | 표준 점수는 물체 자리를 잘 못 본다 | E10 | 🟢 |
| 실제 영상 | 모든 모델이 우연 수준이다 | E11 | 🔴 |

**그래서 지금의 해석** [해석]
1. **어디** — late 에서 미래 자리를 문맥의 운동으로 이어 정하지 못한다. → 뿌리 후보
2. **binding** — 1 이 없으니 정체가 화면에 퍼진다. → 증상
3. **학습** — 1 을 계산하지 않고 학습한 경로를 꺼내 쓴다. → 고치기를 막는 것

## 2. 근거 카드

### E1. encoder 에는 가려진 물체 정보가 있다 — 🟢
- **무엇을 했나:** VOBench_v2 late 가능 영상 1,296 개. 문맥 블록마다 모양 · 색 판독기를 학습하고, 학습에 안 쓴 장면으로 쟀다 (장면 단위 2 겹 분할).
- **결과:** 완전히 가려진 마지막 문맥 블록에서도 모양 82–89 % · 색 76–86 % (우연 16.7 · 12.5).
- **같은 결론의 다른 측정:** 문맥 encoder 출력으로 문맥 끝 속도를 R² 0.996 로 읽는다 (다른 데이터).
- **다시 확인:** ✅ (판독 결과 파일) · 속도는 📄

### E2. 예측 미래에 정체가 약하게, 다른 꼴로 있다 — 🟡
- **무엇을 했나:** E1 과 같은 영상 · 분할. 예측 미래 p 로 판독기를 따로 학습하고 (자기 판독), z 판독기도 p 에 걸었다 (이식).
- **결과:**
  - 자기 판독: 모양 56–66 % · 색 29–50 % → 우연보다 3–4 배 높다. **정체는 있다.**
  - 이식: 모양 22–41 % · 색 7–22 % → 우연에 가깝다. **꼴이 다르다.**
  - 비교: visible 은 가까운 미래 이식이 82 % 다.
- **왜 보통인가:** 판독기 학습 seed 하나. 그리고 이 판독기는 화면 전체를 한꺼번에 읽어서 "어디에 있나" 는 모른다.
- **다시 확인:** ✅

### E3. 정체가 다시 나타날 자리에 모여 있지 않다 — 🟡
- **무엇을 했나:** VOBench late 90 block. 정체 신호를 "다시 나타날 참 자리" 와 그 앞뒤 칸에서 따로 읽어 윤곽을 그렸다.
- **결과:**

  | 표현 | 참 자리에 봉우리? |
  |---|---|
  | 실제 미래 (h) · PFT 판들 | **있다** (주변보다 +10 ~ +60 pt) |
  | 릴리즈 | **없다** (지나온 길 쪽으로 평평, −5 ~ +4 pt) |
  | vast AR · Ariel AR (자연 영상 학습) | **없다** (오히려 7–17 pt 낮음) |

- **덧붙임:** 보이는 먼 미래는 꼴이 아니라 크기 문제다. 정체 대비만 2 배로 키우면 실패의 60–75 % 가 돌아온다.
- **왜 보통인가:** VOBench 한 데이터, 판독기 한 종류.
- **다시 확인:** 📄 (10-30 이식 조사 Q1)

### E4. late 예측 미래에는 물체다운 토큰이 처음부터 없다 — 🟡
- **무엇을 했나:** 위치 판독기 ("자") 를 별도 학습셋에서 만들어 검증하고 (처음 보는 영상 오차 0.87 칸, 1 칸 = 18 px), p 의 미래 블록에 걸었다. v11 가림 2,688 영상.
- **결과:**
  - 문맥 끝에서 가려지면 p 미래에 물체다운 토큰이 남는 블록이 **0 개**다 (가림 없으면 4–5 개).
  - 물체다운 토큰은 마지막 관측 자리에서 2–3 칸 안에서만 유지된다.
- **주의:** 자는 물체가 없어도 값을 낸다. 그래서 attention 질량이 고를 때보다 클 때만 위치를 주장했다.
- **다시 확인:** 📄 (RollOutV2 위치 판독, 09-12 · 09-19)

### E5. 미래 자리는 마지막 관측이 정한다 — 🟡
- **무엇을 했나:** VOBench 단순 도형, 등속 직선 · 전부 보임, 165 영상. 문맥 8 블록 중 **마지막 블록만** 화소에서 바꿨다 (멈춤 · 되돌아감 · 두 배). 같은 조작을 그 바로 앞 블록에도 했다. 미래 위치는 검증된 자로 읽었다 (중심 오차 1.0–1.3 칸).
- **결과:**
  - 마지막 블록을 바꾸면 미래 궤적이 그 블록을 따른다 (따름 지수 0.63–0.88, 1 = 완전히 따름).
  - 바로 앞 블록만 바꾸면 AR 계열은 거의 안 변한다 (0.06 칸 이하). 릴리즈는 0.6–1.2 칸 변하지만, 마지막 블록 효과가 2–3 배 크다.
- **왜 보통인가:** 전부 보이는 영상에서 잰 것이다. late 에서 직접 잰 것이 아니다.
- **다시 확인:** 📄 (10-13 설계 진단)

### E6. 참 자리에 물체를 넣으면 크게 오른다 — 🟡
- **무엇을 했나:** VOBench_v1 late 60 장면. 문맥에서 마지막으로 보인 물체 토큰을 찾아 예측 미래의 어떤 자리에 넣은 뒤 다시 채점했다.
- **결과 (사라짐 A 정답률, 95 % 신뢰구간):**

  | 판 | 정답률 |
  |---|---|
  | 릴리즈 (넣지 않음) | 8 [2, 15] |
  | 복사 기준선 | 57 [43, 70] |
  | 추정 내용 → **참 자리** | **63 [52, 75]** |
  | 라벨 내용 → 참 자리 (상한) | 72 [60, 82] |
  | 추정 내용 → **추정 운동으로 옮긴 자리** | 25–30 |

- **읽기:** 자리를 맞히면 릴리즈보다 크게 오른다. 운동으로 자리를 추정하면 2–3 칸 틀리고 효과가 대부분 사라진다.
- **왜 보통인가:** 참 자리 63 은 복사 57 과 신뢰구간이 겹친다. 한 데이터 · 60 장면이다.
- **다시 확인:** ✅ (이번 세션에 만든 결과 파일)

### E7. attention 은 과거 물체 자리를 안 보지만, 그것만의 문제는 아니다 — 🟡
- **무엇을 했나:** late 에서 미래 query 가 과거 물체 자리를 보는 세기를 쟀다. 그 attention 을 막아 보고 (인과), 키워 보았다.
- **결과:**
  - 릴리즈: 세기 0.54 (같은 거리 다른 자리와 비슷). 물체가 보일 때는 2.8. PFT 는 8.0.
  - PFT 에서 그 경로를 막으면 정체 운반이 끊긴다 (인과 확인).
  - 릴리즈에서 키우면 사라짐 A 5.0 → 15.0 (+10 [3, 18], 180 block). PFT 는 98.
- **왜 보통인가:** 키우기 세기는 사전 등록 없이 훑었다.
- **다시 확인:** 📄 (10-30 이식 조사 R4)

### E8. 학습으로 고치면 학습한 경로에서만 고쳐진다 — 🟢
- **무엇을 했나:** 릴리즈를 VOBench_v2 의 절반으로 PFT 했다 (L1 만 / + binding 항). test 는 반대쪽 절반이다. 그 뒤 test late 를 "학습에 있던 미래 경로" 와 "처음 보는 경로" 로 나눴다.
- **배경:** VOBench late 의 미래 경로는 21 가지뿐이다. 장면 묶음을 나눠도 test late 경로의 66.7 % · 끝 칸의 100 % 가 학습에 있다.
- **결과 (binding 항 − L1 만, 사라짐 A):** 본 경로 **+35.2** · 처음 보는 경로 **+2.8**. late 전체도 +13.9 대 +1.9.
- **덧붙임:** 사전 등록 시험에서, 느린 판 (보폭 2) 12 block 모두 PFT 가 먼 미래 물체를 학습셋 시간표 자리에 뒀다 (참 자리가 아님). 다만 화면에 고정된 자리인지, 학습 범위 끝에서 멈춘 것인지는 미결이다.
- **왜 확실한가:** 두 가지 독립 측정 (경로 나누기 · 사전 등록 시험) 이 같은 쪽이다.
- **단서:** binding 학습은 seed 하나다.
- **다시 확인:** ✅ (경로 나누기) · 📄 (사전 등록 시험)

### E9. 그래서 다른 데이터로는 안 옮겨진다 — 🟢
- **무엇을 했나:** E8 의 학습판을 다른 생성기 · 실제 영상에서 쟀다.
- **결과 (사라짐 A 또는 쌍 정답률):**

  | 데이터 | 시간표가 VOBench 와 같나 | 릴리즈 → PFT |
  |---|---|---|
  | v11 · v11 실물 메시 | 같다 (같은 UE 파이프라인 · 프레임 체계) | 1.8 → 84 · 5.8 → 90 |
  | IntPhys 1 late (60 쌍) | 다르다 | 55 → 53–62 (구분 안 됨) |
  | IntPhys 2 late (120 쌍) | 다르다 | 59 → 60–62 (구분 안 됨) |
  | Rubric 실제 영상 (40 쌍) | 다르다 | 52.5 → 50–55 (구분 안 됨) |

- **다시 확인:** ✅

### E10. 표준 점수는 물체 자리를 잘 못 본다 — 🟢
- **무엇을 했나:** 물체 칸은 하나도 안 바꾸고, 나머지 칸만 PFT 예측으로 바꿔 채점했다.
- **결과:** 사라짐 A 가 **93 %** 가 나온다. 물체 칸은 전체 토큰의 3–5 % 다.
- **읽기:** 사라짐 점수가 높다고 물체를 옮겼다는 뜻이 아니다. vast AR 이 IntPhys 1 late 점수는 좋은데 (81 vs 릴리즈 58) 자리 봉우리는 없는 것 (E3) 도 이것으로 설명된다.
- **다시 확인:** 📄 (10-30 이식 조사 Q2) · vast AR 점수는 ✅ (시트 대조)

### E11. 실제 영상에서는 모든 모델이 우연 수준이다 — 🔴
- **무엇을 했나:** TCOW Rubric Office 20 영상 (짝 40). 위반 시점 앞뒤로 16 장씩 균일하게 뽑아 채점했다.
- **결과:** 전체 50–62 % (우연 50). 방향은 합성 late 와 같다 (사라짐 25–35 %, 생겨남 70–95 %). 릴리즈 · PFT 다섯 판 · vast AR 모두 같다.
- **왜 약한가:** 영상 20 개다. 절반이 손 · 그릇 덮기라 VOBench 와 사건이 다르다. 미래 16 장 중 물체가 다시 보이는 장이 1–15 장뿐이라 점수 감도도 낮다.
- **다시 확인:** ✅

## 3. 아직 모르는 것

1. **p 의 참 미래 자리에 "물체 있음" 신호가 있나.** "어디" 를 토큰 단위로 직접 잰 적이 없다 (E3 은 정체 지도, E4 는 다른 데이터).
2. **참 자리 토큰에서 정체가 읽히나.** E2 의 판독기는 화면 전체를 읽는다.
3. **경로를 외울 수 없는 데이터로 학습하면 옮겨지나.** E8 · E9 의 원인이 데이터인지, 목적 · 구조인지 가른다.

## 4. 이것을 가르는 실험

| 실험 | 무엇을 가르나 | 상태 |
|---|---|---|
| ① 토큰 단위 판독 (어디 · 무엇) | "어디가 뿌리" (참 자리에 물체 신호도 정체도 없음) 대 "binding 만 문제" (물체 신호는 있는데 정체가 없음) | 계획 (학습 없음, 기존 추출본) |
| ② BlenderTrack 학습 → 다른 벤치 평가 | 옮겨지면 데이터 문제, 안 옮겨지면 목적 · 구조 문제 | 학습 중 (17:20 종료), VOBench 평가 대기열 |
| ③ Rubric 을 물체 자리 · 다시 보이는 블록만으로 채점 | E11 이 "효과 없음" 인지 "감도 부족" 인지 | 계획 |

## 5. 다시 세우지 말 것 (기각 · 정정)

| 설명 | 왜 아닌가 |
|---|---|
| "p 에 정보가 없다" | 자기 판독 56–66 % (E2). v11 등가속 · 가림에서는 98 % |
| "encoder 가 속도를 약하게 담는다" | R² 0.996 (E1) |
| "attention 만 고치면 된다" | 키워도 5 → 15 % (E7) |
| "PFT 가 겉모습 · 가림 길이를 외웠다" | 아니다. 외운 것은 미래 자리 시간표다 (E8) |
| "문맥 끝 블록을 통째로 빼는 학습" | 남은 블록이 새 마지막 관측이 되고 그 블록은 깨끗하다. late 를 못 겨눈다 |
| "binding 학습은 처음 보는 궤적에서 오른다" | 본 경로에서만 오른다 (E8) |
| "vast AR 은 자리를 배웠다" | 점수는 좋지만 자리 봉우리가 없다 (E3 · E10) |

## 6. 단서

- 🟡 카드 대부분은 VOBench 한 생성기에서 나왔다.
- 목적함수 (전체 토큰 평균 L1 에서 물체 몫이 작음) 를 원인으로 걸지 않는다. 재학습 없이 검증이 안 된다.
- vast AR 비교에는 문맥 encoder 가 다르다는 교란이 있다.
