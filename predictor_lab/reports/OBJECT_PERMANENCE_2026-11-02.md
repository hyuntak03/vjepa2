# 물체 영속 (object permanence) 학습 결과 모음 — 2026-11-02

> **질문** 가려진 물체가 다시 나오는 미래를 예측하도록 예측기를 이어 학습할 때, 어떤 합성 학습 데이터가 다른 벤치마크 (특히 **움직이는 물체**) 로 옮겨 가나?
> **답** 장면마다 운동이 하나인 v3 는 VOBench 움직이는 물체 사라짐을 0 % 에서 못 올렸다. **같은 장면에서 속도만 바꾼 v4** 가 처음 올렸다 (VOBench v2: 8–11 % → 66–73 %). 그러나 IntPhys 1 · 2 와 실제 영상으로는 거의 옮겨 가지 않는다.
> **다음** 속도 · 가속도를 넓힌 v5 (학습 영상 약 47.5K) 렌더 중 → 학습 한 팔 → 같은 표로 채점.

## 0. 먼저 읽기

**정답률** = 문맥이 같은 두 영상 (가능한 미래 / 불가능한 미래) 짝에서, 예측기가 불가능한 쪽을 더 놀랍게 본 비율 (%).
"놀람" = 예측한 미래와 실제 미래 (encoder 표현) 의 차이 (미래 8 블록 평균). 같으면 0.5 로 센다. **우연 = 50 %.**

| 용어 | 뜻 |
|---|---|
| 사라짐 (A) | 문맥 끝에 가려진 물체가 미래에 **안 나오는** 불가능 영상과 그 짝. 이 문서의 핵심 칸 |
| 나타남 (B) | 문맥에 없던 물체가 미래에 **나오는** 불가능 영상과 그 짝. 대부분 모델이 이미 100 % 근처라 덜 중요 |
| 물체 움직임 / 정지 | 가려지는 물체가 움직이고 있었나 / 제자리였나 |
| late | 물체가 문맥 **끝** 에서 가려진다 (마지막 관측에 물체가 안 보임) |
| 이어 학습 (PFT) | 공개된 V-JEPA 2 예측기에서 시작해 예측기만 더 학습. encoder 는 고정 |
| 장면 / 묶음 | 장면 = 카메라 · 배경 · 가림막 · 물체 · 운동을 다 정한 3D 장면 하나. 묶음 = 한 장면에서 **운동만** 바꾼 영상들 (v4 · v5) |
| 복사 | 예측 없이 문맥 마지막 표현을 미래로 그대로 쓰는 기준선 |
| 근거 표시 | [측정] 산출물에서 다시 셈 · [이론] 설계 · 계산 · [추측] 확인 안 한 해석 |

|---|---|---|---|
| V-JEPA 2 | 공개 예측기 그대로 | — | — |

## 2. 실험 1 — v3: 축을 바꿔도 움직이는 물체는 안 옮겨 갔다

**왜** 어떤 장면 요인 (카메라 · 가림 종류 · 물체 종류 …) 이 전이를 만드는지 보려고.

**어떻게** BlenderTrack v3 = 상황 (축 수준 조합) 42 개 × 상황마다 장면 192 개. 장면 하나 = 운동 하나 (속도도 장면마다 한 번 뽑음).
축마다 한 수준만 고른 장면 1,600 개 (영상 3,200) 로 학습하고, 같은 축의 다른 수준과 바깥 벤치에서 시험했다. 모두 2,000 step · 배치 24 · seed 1 개.

**결과 1 — 바깥 벤치** [측정] (VOBench **v1** late 사라짐 · 움직임 30 쌍)

| 학습 | VOBench 움직임 사라짐 | 정지 사라짐 (6) |
|---|---|---|
| V-JEPA 2 | 0 % | 83 % |
| v3 축 15 팔 (물체 종류 · 카메라 · 가림 종류 · 가림 움직임 · 물체 움직임 · 장소 · 가림 길이 …) | 0–3 % | 67–100 % |
| v3 전부 (영상 14,272) | 0 % | 100 % |
| trapdoor 만 | 13 % | 100 % |

**결과 2 — v3 안에서 축끼리 전이** (사라짐 · 움직이는 물체, 전이율 = 그 학습의 오름폭 ÷ 시험 수준으로 직접 학습한 오름폭) [측정]

| 축 | A 로 학습 → B 에서 시험 | B → A |
|---|---|---|
| 물체 종류 (primitive ↔ realistic) | 93 % | 95 % |
| 카메라 (정면 ↔ 측면) | 84 % | 80 % |
| 카메라 (정면 ↔ 위) | 51 % | 68 % |
| 가림 종류 (가림막 ↔ 다른 물체) | 88 % | 66 % |
| 가림 길이 (짧게 ↔ 길게) | 82 % | 65 % |
| 가림 움직임 (서 있음 ↔ 움직임) | 50 % | 54 % |
| 물체 움직임 (움직임 → 정지 / 정지 → 움직임) | 89 % | **35 %** |
| 장소 (평면 ↔ 빗면) | **27 %** | **15 %** |

**해석**
- 생김새 축 (물체 종류 · 카메라) 은 잘 옮겨 가고, **운동 꼴 축 (평면 ↔ 빗면, 정지 → 움직임)** 은 거의 안 옮겨 간다 [측정].
- v3 에서 예측기는 속도를 쓰지 않았다. 같은 영상의 속도를 절반으로 바꿔도 예측 자리가 따라가지 않았다 (속도 따라감 0.00) [측정].
- 이유 [이론 + 측정]: v3 는 가려지는 시간을 먼저 정하고 가림막 폭을 속도에 맞춰 키웠다. 그래서 다시 나오는 때 · 자리가 속도와 상관없이 "정해진 즈음, 가림막 반대쪽 끝" 이었다. 비슷한 장면의 평균 경로로 맞히는 쪽이 오차가 작았다 (1.06 칸 vs 속도로 곧게 이어 계산 2.27 칸).

## 3. 실험 2 — v4: 같은 장면, 다른 속도

**왜** 장면만으로는 답이 안 정해지게 하면 예측기가 속도를 읽을 것이다 [이론].

**어떻게** 장면 하나를 고정하고 속도만 4 단계 (가장 느린 : 가장 빠른 = 1 : 2) 로 바꿔 렌더한 묶음 + 같은 장면의 빈 장면.
모든 단계가 같은 자리를 같은 순간에 지나 가려진다. 1 차 = 평면 1,137 묶음, 2 차 = 평면 + 빗면 (빗면 1,113 묶음 추가, 영상 11,250).

**결과** [측정]

| 학습 | VOBench v1 움직임 사라짐 (30) | 평면 18 쌍 (등속 · 가속 · 감속) | 빗면 12 쌍 (내려감 · 올라감) | 속도 따라감 (VOBench) |
|---|---|---|---|---|
| V-JEPA 2 | 0 % | 0 % | 0 % | 0.00 |
| v3 전부 | 0 % | 0 % | 0 % | −0.65 |
| v4 평면 2,000 step | 46.7 % | 72 % | 8 % | 0.37 |
| v4 평면 6,000 step | 43.3 % | 72 % | 0 % | 0.50 |
| **v4 평면 + 빗면 4,000 step** | **63.3 %** | **89 %** (16/18) | **25 %** (3/12) | 0.40 |
| VOBench 이어 학습 (도메인 안) | 100 % | 100 % | 100 % | 0.07 |

- 운동 꼴별 (6 쌍씩): 평면 등속 6/6 · 감속 6/6 · 가속 4/6 · 빗면 내려감 2/6 · 올라감 1/6 (v4 평면 + 빗면).
- 같은 장면 · 다른 속도 시험 (Blender, 학습에 없던 장면 305 묶음): 속도 바꿔치기 (미래를 다른 속도 영상으로 이은 불가능 영상) 정답 93.4 % (v3 전부 72.3), 제 속도 고르기 83.0 % (우연 25).
- 픽셀로 그려 보면 (VOBench 평면 등속): v3 전부는 판을 계속 세워 두고 물체를 지운다. v4 는 판이 눕는 것과 물체를 실제 자리 근처에 그린다 (조금 앞서 감).

**해석**
- **양이 아니라 구조였다** [측정]. v3 전부 (14,272 영상) 0 %, v4 (11,250 영상) 63 %.
- 배운 범위는 학습에 있던 운동 꼴까지다 [측정 + 추측]. 빗면은 v4 2 차에서 넣었지만 VOBench 빗면은 25 % 다. v4 빗면은 완만해서 (내려감 2–5°) 가속이 VOBench 의 절반쯤이다 [추측].
- 단서: 대조 팔 (영상 수가 같고 장면마다 속도 하나) 은 사용자 지시로 뺐다. 이득이 "같은 장면 안 속도 변화" 때문인지 v4 의 다른 점 (물체를 VOBench 크기로 작게) 때문인지는 가르지 않았다.

## 4. 실험 3 — v5: 속도 · 가속도를 넓히고 양을 4 배로 (진행 중)

**왜** v4 는 평면 가속을 본 적이 없고 빗면 가속이 약하다. 가속도도 "같은 장면에서 그것만 바뀌는" 예를 줘야 재사용되는 변수가 된다 [이론].

**어떻게** (사용자 결정 3 가지: 평면 가속 넣음 · "창 끝 전에 완전히 다시 보임" 기준 유지 · 이름 v5_motion_control)

| 묶음 | 같은 장면에서 바뀌는 것 | 학습 묶음 | 학습 영상 |
|---|---|---|---|
| 속도 묶음 | 속도 5 단계 (1 : 3 → 2.5 → 2 중 가능한 가장 넓은 값) + 평면 trapdoor 는 정지 단계 | 4,393 | 27,038 |
| 가속도 묶음 | 가려질 때 속도 같고 가속도 4 단계 (평면 = 보이지 않는 힘으로 감속 · 가속, 빗면 = 경사 각도) | 2,039 | 12,532 |
| 격자 묶음 | 속도 3 × 가속도 3 | 748 | 7,926 |
| **합계** | | **7,180** | **47,496** (검사 뒤 45K 안팎 예상) |

- 물체: primitive 7 모양 (공 · 상자 · 원기둥 · 원뿔 · 도넛 · 캡슐 · 피라미드) · realistic 7 물건, 빗면은 공만. primitive 23,914 · realistic 23,582 영상.
- 화면 속도 약 2.5–12 px/샘플 (v4 3.2–9.4). 평면 가속은 문맥 동안 속도가 40–80 % 바뀌는 크기.
- 모자란 곳: 빗면 × 판 · 벽 (공이 판 뒤에서 되돌아 나오는 때가 창 안에 맞지 않음). 정면 격자는 0 묶음.
- 시험 565 묶음 (영상 3,796). 2026-11-02 16:25 기준 렌더 32 % · 18:35 쯤 묶기까지 끝 예상.

**판정 기준 (미리 적음)**: VOBench 빗면 움직임 사라짐 25 % → 50 % 이상, 평면은 유지, IntPhys · 실제 영상은 기대하지 않음.

## 5. 지금까지의 결론

1. 예측기의 핵심 실패는 **문맥 끝에 가려진 움직이는 물체** 다. 정지 물체 · 나타남은 대부분 이미 된다 [측정].
2. 전이를 만든 건 데이터 양이나 장면 축이 아니라 **"같은 장면에서 운동만 바뀌는" 구조** 였다 [측정].
3. 그 전이는 합성 (언리얼 VOBench · 움직이는 가림막) 까지이고, IntPhys 1 · 2 · 실제 영상에서는 이어 학습 셋 모두 V-JEPA 2 수준이다 [측정].
4. 자연 영상으로 처음부터 학습한 AR 은 VOBench · IntPhys 1 사라짐을 잘 잡지만 나타남이 약하다 — 다른 길로 같은 칸을 푼다 [측정 + 추측].
