## 2. `v3_l2_error_hhead/` — 같은 그림, **h 로 학습한 자로 p 를 읽은 것** (`p@h`)

p 는 LN(target encoder) = h 를 맞추도록 학습됐으니 같은 공간이다. 문턱 · 좌표 치우침은 h 의 것. 초록 선은 1 과 같이 z.

C16/P32 에서 (값은 `z_research/scripts/figures/plot_v3_l2_error.py --head h` 산출, 2026-09-24):
- **t0~t4 는 x 오차 3~8 px** — p 자기 자 (8~11 px) 보다 오히려 작다. 마지막 관측 자리 근처에서는 h 자도 p 의 물체를 짚는다
- **그 뒤 x 오차가 직선으로 커진다** — 읽은 위치가 문맥 끝에서 약 45~50 px (2.5~3 칸) 에서 멈추고 진실은 계속 간다
  (flat_v: 읽은 x 이동 −47 ~ −58 px vs 진실 −74 ~ −123 px, t8~t14)
- ⚠️ **"p 가 물체를 멈춘다" 로 읽지 말 것** — 같은 때 h 자의 attention 봉우리 (top1) 가 0.15 → 0.02~0.03 으로 무너진다
  (h 자를 h 에 걸면 0.12~0.22 유지). 멈춘 값은 attention 이 퍼진 **자의 기본값**이다 (CLAUDE.md §6 "슬롯 4 이후 멈춘다" 기각과 같은 함정).
  맞는 문장: **마지막 관측 자리에서 약 3 칸을 넘으면 p 의 물체가 encoder 로 배운 자에게 물체로 안 보인다** — RollOutV2 의 "물체다운 토큰은 2~3 칸 안" 과 같은 크기
- flat·wall 의 **y 오차 ~20 px 는 t0 부터 일정**한 치우침이다 (h 로 잰 보정이 p 에 안 맞음) — 시간 효과가 아니다
- 빨간 점이 적다 — h 자는 attention 이 퍼져도 p 에서 '있다' 를 더 자주 낸다 (flat_v t10: p 자기 자 8 % vs h 자 42 %). **여기의 '있다' 는 1 보다 덜 믿는다**

## 4. `v3_signed_error/` · `v3_signed_error_hhead/` — 축마다 **앞섬 (+) / 뒤처짐 (−)** (행 = x · y)

```
s_a(t) = 그 튜블릿에서 GT 가 축 a 로 움직이는 방향 (±1, clip 마다)
         그 축으로 1 px/튜블릿 미만이면 마지막으로 움직이던 방향 (wall 의 x = 문맥 방향)
         그 축으로 한 번도 안 움직였으면 (flat·wall 의 y) y 는 위 = +  — 패널에 "no GT y-motion: + = above" 로 표시
오차_a = (p̂_a(t) − GT_a(t)) · s_a(t)     + = 그 축의 GT 운동 방향으로 앞섬,  − = 뒤처짐
```
운동 방향을 부호에 녹였으므로 방향별로 쪼개지 않는다 (사용자 정의 2026-09-24). 세로 범위는 줄마다 값의 95 % 가 들어가게 (최소 1 칸 남짓),
밖으로 나간 점은 가장자리에 ▲▼.

C16/P16, p 자기 자 (t0 → t7, `values.json`):

| 시나리오 | GT 운동 | x | y | 읽기 |
|---|---|---|---|---|
| `flat_d` | ← 감속 | 초반 **+8 ~ +16** → −1 | ≈ 0 | 앞섬 (본 속도로 계속) |
| `ramp_d` | → ↑ 오르막 감속 | 초반 **+14 ~ +16** → −12 | ≈ 0 | 앞섰다가 뒤처짐 |
| `flat_v` | ← 등속 | +2 ~ +10 → −10 | ≈ 0 | 거의 맞다가 조금 뒤처짐 |
| `flat_a` | ← 가속 | → **−14 ~ −20** | ≈ 0 | 뒤처짐 |
| `ramp_a` | ← ↓ 내리막 가속 | → −14 ~ −17 | **−7 ~ −11** | 덜 가고 덜 내려감 |
| `arc` | ← 포물선 | → −8 ~ −10 | → **−12 ~ −21** | 덜 떨어짐 |
| `ledge` | ← 낙하 | **−10 ~ −37** (t0 부터) | → **−14 ~ −22** | 덜 떨어짐 (⚠️ x 는 z 도 −5 ~ −13 — 선반 근처 자 치우침) |
| `wall` | ← 후 **멈춤** | **+9 ~ +23** | ≈ 0 | 멈춘 물체보다 앞섬 = 본 방향으로 계속 감 |

감속 → 앞섬, 가속 → 뒤처짐, 낙하·포물선 → 덜 떨어짐, 벽 → 계속 감 — **문맥 운동을 그대로 연장**한 쪽의 어긋남이다.
⚠️ 등속 `flat_v` 도 후반 −10 이라 공통 지연 (또는 자의 기본값 끌림) 이 섞였다 — 읽을 것은 시나리오 사이의 **순서**다.
⚠️ y 가 "no GT y-motion" 인 패널 (flat·wall) 은 앞/뒤가 아니라 위/아래다.

⚠️ **정의 변천 (2026-09-24, 같은 날)** — ① x 에만 GT 수평 부호 → ② 화면 기준 x̂ − x · y − ŷ + 운동 화살표 (`_superseded/screen_sign/`)
→ ③ GT 운동 방향 벡터에 투영한 한 줄 (`_superseded/along_1row/`, "x·y 를 같이 보여야" · "세로 스케일이 크다" 로 교체) → ④ 지금 판.
① 판 README 는 wall 을 "벽에서 되튄다" 고 적었으나 **틀렸다** — wall 의 GT 는 사건 뒤 속도 0 으로 **멈춘다** (0 을 → 로 표시한 버그).

## 5. `v3_trajectory/` — 위치–시간 · 속도–시간 (행 = 시나리오 × x·y, 열 = 위치 · 속도)

`fig_C{c}_P{p}.png` 16 장. 위치 = 마지막으로 본 자리 (문맥 끝 튜블릿) 에서 옮긴 양, 속도 = 튜블릿 사이 이동 (px/튜블릿). **y 는 위 = +**.
검정 = GT (문맥 구간 포함) · 주황 = p (p 자기 자) · 초록 = z (자 검사). p · z 는 '있다' 고 한 clip 만 평균. 빨간 점 = clip 절반 넘게 p '없다' (그 칸의 p 선은 끊음).

C16/P32 에서 보이는 것 (그림으로 읽은 것, 수치 표는 아직 없음):
- **자유 운동 (flat · ramp · arc) 의 x 위치는 t9 까지 GT 를 거의 겹쳐 따라간다** — 물체를 잃기 전까지는 제자리를 짚는다
- **`ledge` 의 y: GT 는 t2 부터 떨어지는데 (−55 px 까지) p 는 t7 까지 0 근처에 머문다** — 떨어지지 않는다. 같은 칸의 z 는 GT 를 따라 떨어진다 (자는 낙하를 읽는다)
- **`wall` 의 x: GT 는 t1 에 멈추는데 (−8 px) p 는 t4~t5 에 −22 px 까지 간다** — 멈춘 자리를 지나 본 방향으로 계속 가다가 물체를 잃는다
- `arc` 의 y: p 도 내려가지만 GT 보다 덜 내려간다
- ⚠️ p 의 속도가 튜블릿마다 **톱니처럼** 오르내린다 (±5 px/튜블릿). z 도 약하게 그렇다 — 읽기 잡음인지 짝/홀 튜블릿 성질인지 안 갈랐다. 속도는 몇 칸을 묶어 추세로 읽는다
- ⚠️ 물체가 흐려지는 후반의 속도 0 은 멈춤이 아니라 자의 기본값일 수 있다 (CLAUDE.md §6)

## 6. `v11_presence/` — IntPhysGen v11: 가림 타이밍별로 p 의 미래에 물체가 있나 (1)

`fig_v11_presence.png` — **열 = 조건 (visible k=0 · mid 가림 k=2~4 · last 가림 k=2~4), 선 = 운동 (static · flat · ramp)** (사용자 지시로 전치),
윗줄 = **있음 / 없음 (이진: 그 튜블릿에서 clip 과반이 p 를 '있다' 로 읽으면 있음)**, 아랫줄 = 위치 L2 (px, '있다' 고 한 clip 평균, 과반이 '없다' 면 0 + 빨간 점).
v11 표준 창 (문맥 16 · 미래 16 샘플 = 8 튜블릿). **미래 튜블릿 0~7 전부, 빼는 규칙 없음** (가려진 칸 · 가장자리 칸 · 화면 밖 칸 포함, 사용자 지시 2026-09-24).
clip 수: 조건 × 운동마다 visible 1,568 · mid 1,176 · last 1,176. 비율과 L2 는 `values.json`.

p 가 '있다' 고 읽은 비율 (t0 → t7):

| 운동 | visible | mid (k=2~4) | **last (k=2~4)** |
|---|---|---|---|
| static | 0.97 ~ 1.00 | 0.97 ~ 1.00 | 0.73 ~ 1.00 |
| flat | 0.99 → 0.47 ~ 0.83 (t3~) | 0.73 ~ 0.98 | **0.00 · 0.24 · 0.34 · 0.23 · 0.35** → 0.66 · 0.97 · 0.75 |
| ramp | 0.85 ~ 1.00 (t7 0.59) | 0.69 ~ 0.99 | **0.00 · 0.13 · 0.17 · 0.28 · 0.07 · 0.24** → 0.92 · 0.37 |

- **문맥 끝에 가려진 움직이는 물체 (last flat · ramp) 는 p 의 미래에 거의 없다** — t0~t4 (flat) · t0~t5 (ramp) 가 전부 '없음'. 물체가 다시 보이는 칸 (k=2 면 t1 부터) 도 마찬가지
- 멈춘 물체 (static) 는 가려져도 대부분 남는다 — 마지막으로 본 바로 그 자리에서 다시 나타난다
- ⚠️ **last 가 flat t5~t7 · ramp t6 에 '있음' 으로 바뀌는 것은 물체가 아니다** — 그 칸의 위치 오차가 93~132 px 이고, last 가림의 **빈 장면**에서도 p 가 t6 에 73 % '있다' 를 낸다
  (`../exp_results/v11/V11_READOUT.md`). 가림막 장면의 후반 오탐이다
- ⚠️ **후반 튜블릿 (flat t5~ · ramp t6~) 은 움직이는 물체가 화면 가장자리에 붙거나 밖으로 나간다** — 자는 가장자리 36 px 안에서 거의 못 읽고 (h 로 확인: 18~36 px 에서 34 %, 18 px 안 0 %),
  화면 밖 진실 위치는 자가 낼 수 없다. 그래서 그 칸의 '있음/없음' 과 커지는 L2 (visible flat t6 '없음', mid 의 140~167 px) 는 자 탓일 수 있다. 읽을 곳은 **t0~t4** 다
- ⚠️ mid 가림은 물체를 들고 있지만 (0.73~0.99) 위치가 t2 부터 1 칸을 넘어 벗어난다 (flat 32 · ramp 49 px) — 원인은 안 갈랐다
- ⚠️ 자 검사 (h 에 같은 자) 는 그림에서 뺐다 (읽기 어렵다는 사용자 의견). 요지: 가려진 물체를 h 도 33 % '있다' 로 읽는다 (가림 편향) → 가려진 칸 (last t0) 의 값은 자 탓일 수 있다
- 이전 판 (보이는 칸 · 가장자리 36 px 안쪽만 센 판, k=1 포함, 점선 = h) 은 `_superseded/` — 사용자 지시로 교체 (2026-09-24)

- **풀링 벡터의 분산은 장면이 지배한다** — env × 조건 × k 칸 평균이 75~81 %, shape 3~4 %, color 0.5 %. 그래서 raw CKA (0.97~0.996) · PCA · t-SNE 섬은 "장면 배치가 같다" 말고는 알려 주지 않는다 (t-SNE 섬 = env)

- **클래스 배치는 p 만 다르다** — 장면 칸 평균을 빼고 교차 적합한 클래스 평균 부분공간 공유 몫: encoder 셋 (z · h_ctx · h_fut) 끼리 **0.89~0.96**, p 와 나머지 **0.77~0.83**. **visible 에서 이미** 그렇다 — 가림이 만든 것이 아니다
- **visible → late 이식 실패는 네 표현 모두에서 일어난다** (raw 선형 probe shape 39~49 %) — late 장면에는 가림막이 있다. 장면 칸 중심을 맞추면 대부분 돌아오고 그때 p 가 가장 낮다 (shape 81.4 vs 88~95)

## 9. 지금까지의 결론 (v3 + v11)

**결론** — V-JEPA 2 predictor 는 **문맥 끝의 운동 상태 (방향 · 속도) 를 연장**하지만, 문맥에 없던 변화 (가속 · 중력 · 벽 · 선반) 와 **문맥 끝에 가려진 물체의 재등장**은 미래에 넣지 않는다.
그 미래 표현에는 **물체의 정체는 남아 있지만 '여기 물체가 있다' 는 형태로는 없고**, encoder 들과 **다른 자리 (직교 사상 하나로 옮겨지는)** 에 놓인다.

**근거**
- v3 (§4·§5): 감속 → 앞섬 (flat_d +8 ~ +16 px), 가속 → 뒤처짐 (flat_a −14 ~ −20), 낙하·포물선 → 덜 떨어짐 (ledge y −14 ~ −22, 같은 칸 z 는 따라 떨어진다), 벽 → 멈춘 자리를 지나 계속 감 (+9 ~ +23)
- v11 있음 (§6): 문맥 끝에 가려진 **움직이는** 물체는 다시 보여도 p 의 미래에 거의 없다 (flat t0~t4 '있다' 0~35 %, ramp t0~t5 0~28 %). 멈춘 물체는 남는다 (0.73~1.00)
- v11 정체 (§7): context encoder 는 **가려진 프레임 토큰에도** 정체를 싣고 (95.7 / 93.9), p 의 미래에도 late 에서 정체가 끝까지 있다 (97.3 / 97.2, 튜블릿별 94~97 %)
- v11 자리 (§7·§8): encoder 머리는 p 에 그대로 안 통하고 (h 대조군도 같다 → z ≠ h 공간 탓이 아니다), 같은 조건 짝의 직교 사상으로 95~99 % 로 돌아온다. p 의 클래스 배치가 encoder 와 다른 것은 visible 에서 이미 있다

**사용자 가설 판정**
- (a) "encoder 는 가려진 프레임에서도 물체 정보가 읽힌다" — **맞다** (95.7 / 93.9). 단 16 프레임 attention 으로 앞 프레임에서 옮겨 온 것일 수 있다
- (b)(c) "predictor 는 물체 정보를 없애지만, 빈 물체를 만들어도 shape · color 는 읽힌다" — **맞다.** 위치 자는 '없음', 정체 probe 는 97 %
- (d) "encoder 와 다르게 표현해서 이식이 안 된다" — **맞다, 다만 더 정확히는**: 다름의 대부분은 직교 사상 + 이동으로 옮겨지는 차이이고, 그 차이는 가림이 없어도 있다. 가림 조건에서는 사상이 한 번 더 바뀐다
- (e) v3 "1차 운동은 연장, 사건·가속은 반영 안 함, 중력을 잘 모른다" — **맞다** (arc · ledge 에서 덜 떨어짐, flat_a · ramp_a 뒤처짐)
- **"predictor 는 world knowledge 를 모른다"** — 이 문장은 **넓다.** 방어되는 문장: "**predictor 는 관측된 마지막 상태를 1차로 연장할 뿐, 문맥에 없던 상태 변화 (가속 · 상호작용 · 가려진 물체의 재등장) 를 미래 표현에 넣지 않는다.**"
  능력 정의로는 읽기 ✅ · 지속 ❌ (8~10 튜블릿 뒤 소실) · 전이 ◐ (방향·속도 O, 가속·사건 X) · 영속 ❌ (정체는 남지만 존재로는 안 남음)

**단서 · 미결**
- 전부 **학습된 자 (위치 · 있음) 와 선형 probe** 로 읽었다. 자는 가림 음성을 배운 적이 없고, 물체가 흐려지면 기본값으로 끌린다 — 뒤처짐의 절대값은 주장하지 않고 **시나리오 사이의 순서**만 읽는다
