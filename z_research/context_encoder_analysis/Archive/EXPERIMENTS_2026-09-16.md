## 0. 공통 용어 (한 번만)

| 기호 | 뜻 |
|---|---|
| 프레임·튜블릿·슬롯 | 영상 100 프레임(16 fps) 에서 stride 3 으로 32 장을 뽑는다. 앞 16 장 = **문맥**, 뒤 16 장 = **미래**. 모델은 2 장씩 묶어 **튜블릿** 으로 처리 → 문맥 튜블릿 0–7, 미래 튜블릿 8–15. predictor 출력의 미래 8 개를 **슬롯 0–7** 이라 부른다 (슬롯 i = 튜블릿 8+i). 튜블릿 하나 = 0.375 s |
| 토큰 | 튜블릿 하나는 16×16 = 256 개 토큰 (1280 차원). 화면 한 칸 = 16 px (288 렌더에서는 18 px) |
| `z` | context encoder 가 **문맥 16 장만** 보고 낸 토큰 (`ctx_masked`) = **predictor 의 실제 입력** |
| `p` | predictor 가 z 를 받아 낸 **미래 8 튜블릿** 토큰 |
| `h` | target encoder 가 **32 장 전부** 보고 낸 토큰. 채점의 정답 쪽 |
| 채점 (surprise) | `mean |p − LN(h)|`. 같은 문맥의 가능/불가능 두 미래 중 불가능 쪽이 더 멀면 정답 (matched pair, chance 50 %) |
| 경계 토큰 | 문맥 마지막 튜블릿(7번) 의 토큰. predictor attention 이 여기에 몰린다 |
| readout / 자 | 토큰에서 라벨(모양·색·위치·속도)을 읽는 작은 선형 모델. 이 세트는 전부 **닫힌 형식 ridge** (최적화 없음, 결정론) 이고 block 단위로 train/test 를 가른다 |
| late / early / mid | v11 가림 타이밍. **late** = 문맥 끝 k 장 + 미래 앞 k 장이 가려짐 (경계에 걸림). early/mid = 문맥 안에서만 가려지고 경계 전에 다시 보임 |

데이터 두 종류: **IntPhysGen v11** (물체 7 모양 × 8 색, 정지/등속/경사 × 가림 유무·타이밍, 21,504 matched pair) 과 **RollOut_v2** (운동 법칙 7 시나리오, 속도가 clip 마다 다름: flat_v 등속, flat_a 등가속, ramp_a 경사, arc 포물선, fall 낙하+바운스, ledge 선반 끝, wall 벽).

## 1. 실험 1 — 시간 정렬 행렬: "p 의 미래 슬롯은 실제 어느 시점과 닮았나"

**왜.** 사용자 가설 "predictor 는 마지막 관측 상태를 spanning 한다" 를 자(학습된 readout) 없이 검증하려고. 자는 물체가 없어도 기본값 위치를 내서 하루를 잘못 읽은 전례가 있다. 파라미터 0 이고 채점기와 같은 거리로 재면 그 반박이 사라진다.

**세팅.**
- clip 마다 진실 궤적의 3×3 토큰 창을 16 튜블릿에 걸쳐 합친 집합 S 를 만든다 (배경 토큰은 시간에 따라 안 변해 행렬을 평평하게 만들기 때문).
- `D[i][j] = mean_{S} |p_i − LN(h_j)|`, i = p 슬롯 0–7, j = h 튜블릿 0–15 (문맥 시점 포함 — "경계를 복사한다" 면 j=7 열에 붙는다).
- 행마다 최솟값 위치 j* 와 대비(골의 깊이). 대비가 다른 clip 의 h 로 만든 null 의 95 백분위를 넘어야 "일치".
- 대조군: 32 장을 다 본 encoder(z, `isolated_ctx`) 로 같은 행렬 → 반드시 대각선이어야 도구가 산 것.
- 데이터: RollOut_v2 가능 clip 중 미래 이동 ≥ 2 칸, 시나리오당 60 (fall 56, wall 0); v11 k=0 flat/ramp vanish pos_a 224 씩.
- 2 차 (gated 판): 배경 토큰에도 "몇 번째 튜블릿" 서명이 있다는 걸 알게 돼, **물체 창 대비 − 배경 창 대비** 를 gate 로 다시 잼 (null A: 다른 clip 의 h, null B: 같은 clip 안 궤적 이동). 시점별 3×3 (S_j) 판도 추가.

**결과.**
| | 대조군 z–h | p 슬롯 0–3 j* (일치 clip) | 물체 특이 gate 통과 슬롯 (null A / B) |
|---|---|---|---|
| v2 flat_v (0.5 칸/튜블릿) | 기울기 1.000, 정수 argmin 100 % | 8.06 / 8.94 / 10.08 / 10.91 | [0] / [0–4] |
| v2 flat_a | 1.000 | 8.0 / 8.9 / 10.0 / 10.8 | [0,1] / [0–2] |
| v2 ramp_a · arc · ledge | ≈1.000 | 8.1 / 9.0 / 10.1 / 10.9 (ledge 슬롯 3 은 5.4) | [0] / [0,1] |
| v2 fall | 0.998 | 슬롯 0 만 (7.3) | [] / [] |
| v11 flat k=0 (1.0 칸) | 1.000 | 8.02 / 8.94 / 10.06 / 10.88 | [0,1,4] / [0–3] |
| v11 ramp k=0 (1.3 칸) | 1.000 | 8.04 / 8.88 / 10.06 / 10.87 | [0–6, 단 슬롯 3–6 의 j*≈10] / [0,1] |

- 배경 토큰만으로도 argmin 은 슬롯 5 까지 ±1 안 대각선 (flat_v 100 %) → **argmin 대각선 자체는 물체 증거가 아니다.**
- 슬롯 4 부터 물체 창 대비가 배경 수준으로 떨어지고, 슬롯 5 부터 argmin 도 흩어진다.

**해석.** (i) 해상도는 문제가 아니다 — 0.5 칸에서도 대조군이 정확히 대각선. **v2 를 다시 만들 이유가 아니다.** (ii) p 는 경계를 복사하지 않는다 (j=7 에 안 붙음). (iii) 물체 특이 시간 정렬이 살아 있는 길이는 **등속 평면 3–4 슬롯, 가속·수직·선반 ≤ 1–2 슬롯**. (iv) v11 ramp 에서 슬롯 3–6 이 j*≈10 과 닮은 것은 물체가 "옛 자리(슬롯 2 위치)에 남아 있다" 는 서명일 수 있다 — **"없어진다" 와 "옛 자리에 남는다" 는 아직 못 갈랐다** (진실 자리에서만 쟀기 때문).
**단서.** null A 는 같은 궤적 기하를 쓰는 시나리오(ramp_a·arc·ledge·v11)에서 퇴화 → 그 셀은 null B 로 읽는다. 옛 자리 검사(슬롯 4–7 에서 t≈10 위치 창의 질량·r 검사)가 다음 단계.
**산출물.** `time_alignment/time_alignment.md` (행렬 전수), `ctxenc_time_alignment_gated/RESULTS.md` (Verdict 절). 스크립트 `ctxenc_time_alignment.py`, `ctxenc_time_alignment_gated.py`.

## 2. 실험 2 — 경계 토큰에 운동 상태(속도·가속)가 있는가 (E1)

**왜.** predictor 는 경계 토큰을 조회한다 (knockout·attention). 그렇다면 쓸 수 있는 운동 정보는 경계 토큰에 든 만큼이다. 튜블릿은 2 장을 보니 속도는 토큰 하나에 들어갈 수 있고, 가속은 시점 3 개가 필요하다. "속도 O / 가속 X" 면 등속만 잘 잇는 관찰(실험 1)이 입력 쪽에서 설명된다.

**세팅.** RollOut_v2 가능 clip, 시나리오당 300. 표현 `z` (predictor 입력) 튜블릿 7 의 진실 물체 3×3 평균 (F1, 1280-d); 비교로 튜블릿 6+7 (F2), 문맥 8 튜블릿 전부 (F3), **물체에서 ≥4 칸 떨어진 배경 3×3 (F1_bg)**, h 튜블릿 7, p 슬롯 0. 라벨 = 위치 차분 (칸/튜블릿). ridge 5-fold (block). 지름길 baseline: 위치만(POS7)·시나리오 id·셔플. 파라미터 없는 판: 같은 위치(±0.3 칸) clip 쌍에서 속도가 비슷한 쌍 vs 다른 쌍의 토큰 코사인.
- 시나리오 안에서 위치가 속도를 결정하는 곳(ramp_a·arc·ledge: POS7 R² ≈ 1.0) 은 속도 검정에 못 쓴다. flat_v·flat_a·fall 만 유효.

**결과** (시나리오 내 fit, OOF R²):
| | F1 (물체 창) | F1_bg (배경 창) | h | p 슬롯 0 | POS7 지름길 |
|---|---|---|---|---|---|
| flat_v vx | **0.988** | 0.871 | 0.989 | 0.992 | −0.02 |
| flat_a vx | 0.985 | 0.842 | 0.985 | 0.990 | 0.01 |
| fall vy | 0.987 | 0.872 | 0.990 | 0.988 | 0.18 |
파라미터 없는 판 (flat_v, 3,163 vs 12,777 쌍): 속도 비슷 +0.50 / 다름 −0.18 (물체 창), 배경 창 +0.09 / −0.04 — 둘 다 CI 안 겹침.

**해석.** 속도는 경계 튜블릿에 있고 p 로도 넘어간다. 단 **배경 창에서도 0.87 로 읽힌다** → "물체 토큰에 국소적" 이라고는 못 한다 (실험 5 가 이걸 푼다: 배경 쪽 "속도" 는 다른 부분공간). **가속**: flat_a 는 v0=0 이라 a ∝ v (분리 불가), ramp_a 의 a 두 수준은 경사각 = 장면 단서(POS67 0.99), arc 는 a 변이 없음 → **이 데이터로는 못 잰다.**
**단서.** 처음 n=30 판은 배경 창 0.39 로 나와 "국소적" 이라 썼다가 n=300 에서 철회 (`n30/` 에 남김).
**산출물.** `ctxenc_boundary_kinematics/RESULTS.md`.

### 2-1. 가속 교차 쌍 (실험 2 의 후속)

**왜.** 새 렌더 없이 가속을 갈라 보려고: flat_v (a=0, v 7 수준) 와 flat_a (v0=0, a 7 수준) 는 같은 장면·같은 anchor 라서, 두 시나리오에서 위치·속도가 같은 clip 쌍은 **가속 이력만** 다르다.
**세팅.** 각 784 clip, |Δpos7| ≤ 0.3 칸 & |Δv7| ≤ 0.05 로 쌍을 맞춤; 위치·속도를 회귀로 제거한 뒤 "가속 있음" 이진 readout; **둘 다 정지 (v=0, a=0) 인 대조 쌍** 포함.
**결과.** 위치·속도 맞춘 집합에서 has_a bacc 1.00 (F1) — 그런데 **배경 창도 0.997 이고, 둘 다 정지인 대조 쌍도 갈린다 (AUC 0.20)**.
**해석.** 두 시나리오는 운동과 무관한 렌더·장면 단서로 구분된다 → 이 검정은 무효. **가속은 한 시나리오 설정 안에서 (v0 × a) 를 교차한 새 세트로만 잰다** (사용자 결정: 만든다). 교훈: 시나리오 간 비교는 전부 이 단서를 의심할 것.
**산출물.** `ctxenc_accel_crosspair/results.json`.

## 3. 실험 3 — 가려진 프레임의 경계 토큰에 물체의 모양·색이 남아 있는가 (E2·E3)

**왜.** 실험 1 에서 late 가림이면 p 에 물체가 처음부터 없다. predictor 가 경계를 조회하니까, **경계 토큰(가림막 뒤)에 물체 상태가 남아 있는지** 가 "이어가기" 의 재료 문제다. 동시에 "가림막이 장면에 있는 것 자체가 코드를 옮기는가(spurious)" 를 갈라 보려고 early 조건(가림막은 있지만 물체는 경계에서 보임)을 같이 둔다.

**세팅.** v11_full 가능 clip, 셀 = (조건, k), 셀당 100 block (165–184 clip). 조건: static / moving_flat / (v2 에서 ramp) × visible k=0 / late k=1..4 / early k=4. 표현 `z` (predictor 입력) 와 `h`. 튜블릿 7 의 특징 4 종: **B7** 진실 물체 위치 3×3 평균 (late 에서는 가림막 자리) / **B7all** 256 토큰 평균 / **C** 문맥 2048 토큰 평균 / **BG** 먼 배경 3×3. 라벨 shape 7 (chance 14.3) · color 8 (12.5). ridge 분류, block split, 셔플 대조. v2 에서 9 토큰 이어붙임(B7cat), 가림막 토큰 제외 평균(C_noocc), 역방향 이식, bootstrap CI 추가.
fit: self(같은 셀) / **visible→late** / **visible→early** / early→late / (v2) late→early, late→visible.

**결과** (shape, z):
| fit | B7 static / moving | B7all | C | 뜻 |
|---|---|---|---|---|
| self visible | 88 / 99 | 85 / 99 | 91 / 99 | 보이면 어디서나 읽힘 |
| self late k=2..4 | 72–76 / 49–72 | 65–75 / 89–90 | 80–90 / 94–97 | 가려져도 **어떤** 코드는 있음 (배경 창도 30–54) |
| **visible→late** | **20 / 16** (concat 도 21/20) | 21–25 / 16–19 | 18–24 | 보이던 코드로는 chance |
| **visible→early** | **76 / 94** | 55 / 64 | 42 / 48 | 가림막만 있으면 국소 코드는 그대로 |
| late→early (v2) | 36 / 41 (ramp 73) | — | — | 가려진 자리 코드는 부분적 정체성 코드 |
h 는 가려진 창에서 z 보다 높지 않다 (static k3/k4 53/59 vs 72/74).

**해석.** (i) 가려진 자리의 경계 토큰에 **보이던 때의 모양·색 코드는 안 남는다** (선형 하한). 남는 건 다른 코드이고 부분적으로 정체성을 담는다 (ramp 73). 정보 자체는 문맥 앞쪽에 있다 (C 94–98). 미래에 물체가 다시 나오는 걸 본 h 도 그 자리를 안 채운다 (amodal 완성 없음). (ii) 가림막 존재만으로는 국소 코드가 안 옮겨진다 (76/94). (iii) 문맥 전체 평균(C)은 가림막이 들어오는 순간 무너진다 (91→42) — 가림막 토큰 혼입(구성 효과)이 일부이지만 (C_noocc 47) 전부는 아니다.
**단서.** 위치는 안 읽었다 (v11 은 경계 위치 분산이 없어 자리 prior 를 외움). 토큰별 지도(256 토큰 각각에 visible readout 적용)는 미실행. attentive 판 미실행. "채점기가 보는 것 = 토큰 평균" 등치는 틀렸다 (채점기는 토큰별 거리를 평균).
**산출물.** `ctxenc_boundary_identity_occlusion/RESULTS.md` (576 fit), `ctxenc_boundary_identity_v2/RESULTS.md`.

## 4. 실험 4 — p 와 h 는 같은 공간에 있나, 정렬하면 채점이 오르나 (E4)

**왜.** 채점은 |p − h| 인데 h 에서 배운 readout 이 p 에서 안 통한다(가림 없이도 57–95). p 가 h 와 다른 좌표계에 있으면 채점 실패의 일부는 predictor 능력이 아니라 **자리** 문제이고, 정렬 사상 하나로 고칠 수 있다 (CLAUDE.md §10 4 번 계획). 그걸 잰다.

**세팅.** v11_full, 조건 9 (static/flat/ramp × visible/late/early), 조건당 120 block × 256 랜덤 토큰. (a) top-k PCA 부분공간의 주각 겹침 (split-half 상한, 랜덤 하한), (b) 같은 clip·같은 토큰의 CKA, (c) visible 가능 clip 으로 Procrustes/ridge W: p→h 를 맞추고 → **held-out block 의 matched pair 를 W(p) 로 다시 채점** (조건당 288 block, bootstrap 1000). 대조군: 다른 clip 의 h 로 맞춘 W, z→h W.

**결과.**
- p 는 저차원: participation ratio 16–19 (z/h 62–66), top-16 이 분산 72–78 % (h 41 %). p–h top-16 겹침 0.62–0.67 (split-half 0.93–0.99), **가림 유무 무관**. p 의 주 방향 90 % 는 h 의 top-256 안.
- 토큰 L1 로는 W 가 격차의 ≤ 9 % 만 줄인다 (z→h 대조군도 31 %).
- **채점 재계산 (ridge W, Δ정확도 [CI])**: visible 88.9→91.9 (+3.0 [2.1, 4.0]) · **late 61.2→64.4 (+3.2 [1.8, 4.8]; 가족별 W 66.7)** · early 81.1→87.8 (+6.7). margin ≈ 2 배. 대조군은 late 에서 0.

**해석.** 정렬 사상은 **효과가 있지만 작다** — late +3~6 은 predictor 재학습 (+25~30) 의 1/5. 처음에 "토큰 L1 ≤ 9 % → 기각" 이라 썼던 것은 철회 (margin 이 base 의 1 % 라 작은 이동도 순위를 바꾼다). p↔h 차이는 "회전" 이 아니라 **저차원·부분 겹침** 이고 가림이 만든 게 아니다.
**단서.** 재계산은 probing 캐시(bf16) 라 근접 tie 가 뒤집혀 raw 정확도가 fp32 채점기와 다르다 (static late 63.4 vs 58.2). Δ 는 같은 토큰 위 쌍 차이라 그보다 믿을 만하나 정식 수치는 fp32 재추출 후.
**산출물.** `ctxenc_subspace_overlap/RESULTS.md`, `ctxenc_subspace_v2/RESULTS.md` §0–2.

## 5. 실험 5 — 상태 재료들의 부분공간은 서로 얽혀 있나 (운동 편)

**왜.** 사용자 질문: 필요한 state 들(위치·속도·가속·장면)이 encoder 안에서 분리된 부분공간인가, 아니면 가림막·시각 같은 nuisance 와 얽혀 있나. 얽혀 있으면 새 predictor 가 상태만 골라 진화시키기 어렵다. 그리고 실험 2 의 "배경 창에서도 속도가 읽힌다" 가 같은 코드인지 다른 코드인지.

**세팅.** RollOut_v2 시나리오당 300. 표현 z 튜블릿 7 물체 창 / 배경 창, p 슬롯 0, h, z32. 인자마다 ridge readout 의 가중치 span = 그 인자의 **부분공간** (위치 2-d, 속도 2-d, 속도 잔차, 가속 2-d, 시나리오 5-d, 시각(튜블릿 index) 7-d, 물체/배경 1-d). 부분공간 쌍의 주각 겹침 (mean cos²), split-half 상한, 랜덤 하한. 부가: 각 부분공간이 |p−h| 채점 거리에서 차지하는 몫.

**결과** (z 물체 창, 겹침 / 랜덤 / split-half 천장):
| 쌍 | 겹침 | 랜덤 | 천장 |
|---|---|---|---|
| 위치 ~ 속도 | 0.019 | 0.002 | 0.39 |
| 속도 ~ 시각 서명 | 0.004 | 0.005 | 0.47 |
| 시나리오 ~ 시각 | 0.001 | 0.005 | 0.84 |
| 위치 ~ 시나리오 | 0.09–0.15 | 0.004 | 0.70 |
| **물체 창 속도 ~ 배경 창 속도** | **0.043** | 0.002 | 0.29 |

**해석.** 경계 토큰 안에서 위치·속도·시각·장면은 **거의 직교** (얽힘 없음). 위치와 시나리오만 약하게 얽힘. 배경 창에서 읽히는 "속도" 는 물체 창의 속도와 **다른 부분공간** → 다른 코드(장면·카메라 단서). 실험 2 의 "국소적이지 않다" 는 "배경에도 속도를 맞히는 다른 코드가 있다" 로 정정.
**단서.** 선형 부분공간만; 가속 부분공간은 시나리오 id 와 섞여 있어 읽지 않는다. v11 쪽(정체성·가림막·시각 서명) 판은 스크립트만 있고 미실행 (`ctxenc_state_subspaces_v11.py`).
**산출물.** `ctxenc_state_subspaces_kinematics/RESULTS.md`.

## 6. 기존 run 을 다시 읽은 것 (새 실험 아님)

### 6-1. predictor 만 이어 학습하면 회복되나 (`z_training/runs`)
**왜.** encoder 에 재료가 있다면 encoder 를 두고 predictor 만 바꿔도 가림 채점이 올라야 한다.
**세팅.** 릴리즈 ViT-H predictor 를 `temporal_prefix` 마스크(문맥 16 → 미래 16, 채점과 같은 배치) 로 v11 train 절반(가능만) 에서 10 epoch 이어 학습; held-out 절반 10,752 쌍 채점. 교차 대조: IntPhys1 train 으로 같은 레시피 40 epoch.
**결과.** late 가림 57.4 / 59.4 / 59.6 → **87.1 / 84.0 / 87.4** (static/flat/ramp, 896 쌍씩), 전체 75.8 → 91.4. 단 visible 셀도 +4~13 오르고, IntPhys1 은 88.9 → 77.2. IntPhys1 로 학습한 쪽은 v11 static late 만 +12.5, moving late −2.7/+0.9.
**해석 (09-16 갱신).** post-FT p 에 위치 자를 직접 걸어 봤다 (`predictor_training/predictor_IntPhysGenV11_PFT/`): v11 안에서는 물체를 8 슬롯 내내 제 자리에 두고 가림 뒤 재출현까지 맞추지만, RollOut_v2 에서는 v11 속도(2 배)를 강요하고 경사·벽을 무시한다. → **회복은 실제 물체 배치지만, 배운 것은 v11 궤적 prior** 다.

### 6-2. 가려진 문맥 튜블릿을 못 읽게 하면 (`knockout_hidden`)
**세팅.** predictor 의 미래 토큰 → 가려진 문맥 튜블릿 attention 을 끊고 채점 (조건당 1,792 쌍).
**결과.** static late **+15.4** (대조군 −0.6): 평소엔 가림막 토큰을 읽어 빈 장면을 앞으로 복사하고 있었다. moving late −2.0 / −2.6 은 대조군 범위(−6.8…+3.6) 안이라 해석 불가.
**해석.** "predictor 가 앞 프레임을 읽는가" 의 직접 검정은 시간 범위 knockout (`mask→ctx@t0-5` vs `@t6-7`) 인데 GPU 가 필요해 미실행.

### 6-3. 이 세트가 가져다 쓴 이전 결과
- 위치 자 (RollOutV2): ledge 부유·wall 통과·v11 late 에 물체 토큰 없음 — 단 ledge 는 낙하/부유 분리가 슬롯 3 부터라 지평과 못 가르고, wall 은 정지 창에도 질량 0.33/0.21 이 있는 혼합. `RollOutV2/figures/v5/summary/POSITION_READOUT_2026-09-12.md`.
- attention knockout: `mask→ctx` −37.5 / `mask→mask` −1.4 (채점 기준; 예측 자체는 mask→mask 를 끊으면 40 % 움직임). `IntPhysGenV11_occlusion_timing_ablation/README.md`.

## 7. 지금 시점의 답 (한 문단)

predictor 는 경계 토큰에서 마지막 관측 상태(위치·속도)를 읽어 **토큰마다 짧게 외삽**한다 — 재귀 없이, 등속 평면 3–4 튜블릿, 가속·수직 ≤1–2. 그 재료(정체성·위치·속도·장면)는 경계 토큰에 서로 직교하게 들어 있다. **가려진 물체**의 코드는 경계 토큰에 보이던 형태로는 없고(정보는 문맥 앞쪽), predictor 는 앞을 읽는 대신 가림막을 복사한다. 가속은 지금 데이터로 못 잰다(새 세트). p 는 h 와 다른 저차원 공간에 있고 전역 정렬로 채점이 조금 오른다(late +3~6). predictor 만 재학습하면 크게 오르지만(+25) 무엇을 배웠는지는 미결. 남은 검정: 옛 자리 검사(캐시), 토큰별 지도(캐시), 시간 범위 knockout(GPU), post-FT p 시간 정렬(GPU), (v0×a) 세트(렌더), v11 부분공간(캐시).
