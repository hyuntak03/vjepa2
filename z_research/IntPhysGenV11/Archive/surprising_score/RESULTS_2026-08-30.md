## 1. 무엇을 어떻게 쟀나

### 채점 규칙

```
surprise(clip) = mean | predictor(context) − LN(target_encoder(clip))[future] |
정답           ⟺  surprise(impossible) > surprise(possible)
chance         =  50%
```

- `distance: l1`, `loss_exp: 1.0`, `target_layer_norm: true`(affine-free, target 에만), `mask_index: 0`
- `mask_index: 0` 이 critical — 릴리즈 체크포인트에서 학습된 mask token 은 `[0]` 하나뿐이다
- `scoring.pairing: matched` — block 의 가능×불가능 조합 4개 중 **context 가 픽셀 단위로 같은 2쌍만** 쓴다.
  그래야 predictor 출력 `p` 가 두 조건에 동일해지고, 채점이 "p 가 어느 미래에 가까운가" 로 환원된다.
  ⚠️ `pairing` 기본값은 `cross` 다. 안 쓰면 전수 4쌍 채점이 조용히 돌아간다.

### 프레임

```
raw 100 프레임 (0..99)   stride 3   splice 48
context    16장   raw  0, 3, ..., 45
predictor  16장   raw 48, 51, ..., 93
target enc 32장 전부
```

디스크에는 34장이 있다 (`0,3,…,96,99`). 96·99 는 예측 창 밖이라 읽지 않는다.

### 모델

dual_encoder: true   context_encoder_key: encoder   target_encoder_key: target_encoder
predictor: {embed_dim 384, depth 12, num_heads 12, num_mask_tokens 10}
dtype: float32   autocast: float16          ← 공식 Garrido 재현 관례
use_rope: true   uniform_power: false
```

### 지표

한 쌍 `{A,B}` 는 **양방향**으로 렌더된다 (`A→B` 와 `B→A`). 두 방향은 같은 두 후보 미래를
역할만 바꿔 쓴다. 그래서:

```
sensitivity = (acc(A→B) + acc(B→A)) / 2 − 50      편향을 제거한 탐지력
bias        = |acc(A→B) − acc(B→A)| / 2           한쪽으로 쏠린 정도
```

**고정된 편향만 작동하면 두 방향의 합이 100 이 되어 sensitivity 가 0 이 된다.**
정확도는 둘이 섞인 값이라 단독으로 읽으면 안 된다. 실측 예 (vanish, k=4, 전 조건 합):

```
빈 → 물체 나타남   95.2%
물체 → 사라짐      13.7%
                  ─────
        acc        54.5%      sensitivity  +4.5      bias  40.8
```

sensitivity/bias 는 **양방향이 다 있는 쌍**마다 계산해 평균한다. `n pair-type` 이 그 쌍 개수다.

## 3. 관찰

### (1) 가림 길이는 무관하다

`sensitivity`, 조건을 합친 값:

```
             k=0    k=1   k=2   k=3   k=4
permanence   50.0   11.3   7.4   6.9   4.5
shape        34.3    5.0   5.2   6.2   5.2
colour       31.6   13.1  12.9  13.5  20.8
```

가림막이 생기는 순간 절벽처럼 떨어지고 **그 뒤로는 평평하다.** shape 은 k=1 과 k=4 가 5.0 vs 5.2 다.
가려지는 시간을 4배로 늘려도 아무 일도 일어나지 않는다.

→ CLAUDE.md §10-5 의 "가림 길이 통제 세트: L1 이 IntPhys 수준까지 오르는가" 는 **아니오**.

### (2) 가속이 shape 을 깎는다 — 가림이 없을 때만

`Moving`, 가림 없음:

| violation | ramp(가속) | flat(등속) | 차이 |
|---|---:|---:|---:|
| permanence | 100.00 | 100.00 | 0.0 |
| **shape** | **69.05** | **89.88** | **+20.8** |
| colour | 76.79 | 86.01 | +9.2 |

가림이 있으면 그 차이가 거의 사라진다 (shape 52.4 vs 57.7, permanence 둘 다 정확히 50 근처).

→ **예측을 불확정하게 만드는 것이면 무엇이든 signal 을 지운다.** 가림은 그중 가장 강한 사례다.
⚠️ 이 대비는 "등속 vs 등가속도" 이고 쐐기 유무는 조작의 구현이다 (CLAUDE.md §8-5).

⚠️ **정정 (2026-08-30)** — "가림이 있으면 차이가 사라진다" 를 **"가림 하에서는 가속이 무관하다"
로 읽으면 안 된다.** 가림 조건의 ramp 54.46 / flat 56.85 는 둘 다 chance 근처라 **바닥 효과**와
구분되지 않는다. 정확한 서술은 **"가림 하에서는 둘 다 이미 바닥이어서 가속의 효과를 잴 수 없다"**
이다. 근거: `HYPOTHESIS_SCALAR_ORDER_2026-08-30.md` §1-(5).

### (3) permanence 의 bias 가 k 와 함께 커진다

```
        k=0   k=1   k=2   k=3   k=4
bias     0.0  31.0  29.5  33.5  40.8
sens    50.0  11.3   7.4   6.9   4.5
```

**가림이 길수록 "물체가 있는 미래" 로 더 확실히 쏠린다.** sensitivity 는 줄고 bias 는 는다.
k 가 무관하다는 (1) 과 결이 다른 관찰이므로 함께 인용할 것 — **탐지력은 k 에 무관하지만
편향의 크기는 k 와 함께 커진다.**

### (4) colour 만 k=4 에서 튄다

`sensitivity` 가 k=1~3 에서 13 근처인데 k=4 에서 **20.8** 로 오르고 bias 는 13 → 7 로 떨어진다.
다른 두 위반과 반대 방향이다. 셀당 n=504 라 우연으로 보기 어렵다. **설명 미상.**
경쟁 가설 둘 — (a) 가림막이 넓어지면 배경 토큰 구성이 바뀌어 색 스칼라의 분리가 좋아진다,
(b) k 가 커지면 미래 반쪽의 남은 가시 프레임 구성이 달라진다. 색 `s` 를 k 별로 따로 적합해
`std(s)` 가 k 와 함께 커지는지 보면 갈린다 (`HYPOTHESIS_SCALAR_ORDER_2026-08-30.md` §5 E5).
**갈리기 전까지는 설명 미상으로 남긴다.**

### (5) static_occlusion 의 vanish 가 이동 조건과 다르다

```
static_occlusion       vanish  acc 70.54  sens +20.54  bias  3.57
moving_occlusion       vanish  acc 50.00  sens  +0.00  bias 50.00
moving_occlusion_flat  vanish  acc 52.01  sens  +2.01  bias 47.99

정지 조건에서만 permanence 탐지가 살아남는다(+20.5). 이동 조건 둘은 **완전 상쇄**다.

- ⚠️ **후속 문서 있음** — 표 E/F 의 방향 편향이 전이별 21개(색 28개)가 아니라 **1차원 외형 순서**
  라는 가설과 그 검증 계획: `HYPOTHESIS_SCALAR_ORDER_2026-08-30.md`.
  `moving_visible` k=0 에서 shape **21/21**, color **28/28** 이 하나의 전순서와 모순 없이 일치한다
  (재계산 없이 아래 표에서 직독 가능).

- 셀당 n 은 조건×k×violation 기준 **vanish 89~90 / shape 134 / color 134** 쌍이다.
  방향별로 쪼개면 vanish 는 방향당 ~45, shape 은 쌍당 6~7, color 는 쌍당 4~5 다.
  **쌍 단위 수치는 단독 인용 금지** — 합=100 패턴이 여러 쌍에서 반복된다는 집합적 증거로 쓸 것.
- `moving_visible` 과 `moving_occlusion` 은 ramp, `*_flat` 은 평지다. `static` 은 평지.
- 방향 정의: vanish 는 `role`(imp_vanish/imp_appear), shape/color 는 `pre → post`.
- 모델 하나(ViT-H)뿐이다. ViT-L 미실행.

# 제2부 — attentive probing 전수 기록 (2026-08-30)

같은 v11 클립·같은 토큰 위에서 잰 표현 분석이다. 제1부(채점)와 **데이터·모델이 같고**
프로토콜만 다르다. 채점이 못 맞히는 조건에서 표현에 정보가 남아 있는지를 본다.

## 6. 무엇을 어떻게 쟀나

| 기호 | source | 인코더 | frames |
|---|---|---|---|
| `z` | `contextF__f1to16` | context_encoder (online), 미래 토큰 마스킹 | frames 1-16 |
| `h` | `targetF__f17to32` | target_encoder (EMA), 32프레임 forward | frames 17-32 |
| `p` | `pred__f17to32` | predictor(ctx_masked) | frames 17-32 |

세 지점 모두 `(2048, 1280)` = `(16 / tubelet 2) x (256/16)^2`. 직접 비교된다.

`num_probe_blocks: 1` = cross-attention 하나 = V-JEPA attentive pooler 그대로.
depth 4 는 v10 실측에서 **더 나빴다** (p self 94.69 vs 96.35).

**불가능 변이를 넣지 않는 이유** — `contextF` 는 미래 토큰을 transformer 이전에 떨궈
`imp_ab` 가 `pos_a` 와 비트 단위로 같아지고, `pred` 도 입력이 context 뿐이라 같다.
`targetF` 는 라벨이 `_pre` 인데 렌더는 `_post` 라 인코더가 정확할수록 0점이 된다.

## 11. 관찰

### (1) 정보는 세 지점 전부에 있다. 채점만 못 읽는다

같은 클립·같은 토큰에서 잰 두 측정:

| condition | shape p self | shape 채점 sens | colour p self | colour 채점 sens |
|---|---:|---:|---:|---:|
| sta+VIS | 100.00 | 44.05 | 100.00 | 31.85 |
| sta+OCC | 85.13 | 4.76 | 87.55 | 5.36 |
| flat+VIS | 100.00 | 39.88 | 100.00 | 36.01 |
| flat+OCC | 98.48 | 6.85 | 98.98 | 18.45 |
| ramp+VIS | 100.00 | 19.05 | 100.00 | 26.79 |
| ramp+OCC | 98.46 | 4.46 | 99.49 | 21.43 |

`ramp+OCC` 에서 shape 채점 sensitivity 는 **4.46**, vanish 는 **0.00**(완전 상쇄)인데
같은 조건의 `p` self 는 **98.46%** 다. → **"정보가 없어서 못 맞힌다" 가 아니다.**
그림: `figures/probing/by_condition/fig_information_vs_scoring`.

⚠️ v8 과 다르다. v8 가림 조건 `p` self 는 shape 82.0 / colour **54.5** 였고 v11 은
98.5 / 99.0 이다. v8 은 8종 중 4쌍만 썼고 실루엣이 폭과 교락돼 있었다 — v11 은
21쌍 전수에 실루엣을 렌더 픽셀 기준으로 등화했다. **어느 쪽이 원인인지 안 갈렸다.**

### (2) 비가림으로 배운 readout 이 같은 팔의 가림에서 안 통한다

운동이 통제된 §8 의 `VIS→OCC` 3팔 평균:

```
shape       z  64.8   h  75.7   p  27.3     chance 14.3
colour      z  97.4   h  99.2   p  17.3     chance 12.5
background  z 100.0   h 100.0   p 100.0     chance 25.0
```
colour 가 가장 깨끗하다 — 인코더 낙차는 0.0~2.5pt 인데 `p` 만 100 → 15~21 이다.
`h` 도 가려진 미래를 본 인코더인데 안 무너지므로, 차이는 **파이프라인에서 predictor
단계에 국한된다.** `env` 는 세 지점 전부 100.0 이라 predictor 출력 전체가 흔들리는
것이 아님을 보인다.

⚠️ shape 은 인코더도 흔들린다 (z 3팔 평균 64.8, `Constant velocity` 는 42.4).
**"인코더는 가림에 무관하다" 는 colour 와 env 로만 주장할 수 있다.**

### (3) 그 실패는 k 에 비례하고 끝에는 단일 클래스로 붕괴한다

self 는 k 에 평평한데(§10-a) `VIS→OCC` 는 k 와 함께 떨어진다(§10-b).
`Accelerating` 팔의 `p`:

```
shape   acc   k1= 45.0  k2= 40.9  k3= 22.2  k4= 15.5
        고유클래스 k1= 5  k2= 5  k3= 5  k4= 5
colour  acc   k1= 25.8  k2= 13.1  k3= 14.4  k4= 11.3
        고유클래스 k1= 7  k2= 5  k3= 1  k4= 1
```
→ **가림 길이는 정보를 지우지 않는다.** 같은 조건 안에서는 k 와 무관하게 읽히고,
비가림을 기준으로 재면 k 에 비례해 멀어진다. 채점이 조건 안에서만 비교하므로
제1부의 "k 는 무관하다" 와 어긋나지 않는다.

### (4) `env` 대조군 — predictor 출력 전체가 망가지는 것이 아니다

`env` 는 대각선 18칸, 팔 안 이식 18칸, k 분해 36칸이 **전부 100.0** 이다.
같은 head 구조·같은 n_train(781)·같은 조건 쌍에서 배경은 완벽히 옮겨간다.

⚠️ 다만 배경은 2048 토큰 전체에 깔려 있어 query 가 어디를 보든 읽힌다.
**그래서 이 대조군은 "물체 정체성도 옮겨가야 한다" 를 뒷받침하지 않는다** — §12-(2).

### (5) `static_occlusion` 만 대각선에서도 낮다 — 미해결

가림 세 조건 중 `sta+OCC` 만 `p` self 가 85.13 / 87.55 이고 나머지 둘은 98.5 / 99.0 이다.
그런데 **채점에서는 `sta+OCC` 만 vanish 탐지가 살아남는다**(sens +20.54, 이동 둘은 0.00/+2.01).
표현에서는 가장 나쁜데 채점에서는 가장 좋다. 설명 미상.
그리고 이 두 head 가 수렴이 안 된 셋 중 둘이라(train_acc 0.931 / 0.954)
**표현 탓인지 최적화 탓인지 아직 안 갈렸다** — §13.

## 12. 정정 — 한 번 썼다가 철회한 해석 (기록)

| 쓰지 말 것 | 왜 틀렸나 |
|---|---|
| **"팔을 가로지르는 이식 실패가 표현이 조건별이라는 증거"** | 기대값이다. attentive probe 의 query 는 어느 토큰을 볼지를 배우는데 정지와 이동은 물체가 점유하는 토큰이 다르다. 정지↔이동 비대칭(정지→이동 70.1 vs 이동→정지 17.3)도 같은 이유로 설명된다 — 정지 물체의 자리는 이동 궤적이 훑는 띠 안에 들어갈 수 있지만 그 역은 아니다. **§8 의 팔 안 비교만 쓸 것.** |
| **"`env` 가 100% 이식되므로 head 용량·표본 문제가 아니다"** | 반만 맞다. 배경은 2048 토큰 전체에 깔려 있어 query 가 어디를 보든 읽히는 **자명한 경우**다. 물체 정체성이 옮겨가야 할 이유를 세워주지 않는다. |
| **"가림이 표현을 회전시킨다 / 옮긴다"** | 각도도 부분공간 겹침도 클래스 중심 이동도 잰 적이 없다. 게다가 probe 가 선형이 아니라 attentive pooling + 선형이라 실패가 **클래스를 가르는 방향**에서 온 건지 **어느 토큰을 모으느냐**에서 온 건지 구분되지 않는다. 쓸 수 있는 문장: "비가림으로 학습한 head 가 같은 팔의 가림 조건에서 못 읽는다." |
| **"z 와 h 가 같다"** | 둘 다 천장이다 (train_acc 1.000 이 18/18). 차이를 잴 해상도가 없다. |
| **pooled(`fit_groups_sweep=[null]`) 대조군을 돌린다** | 철회. 이식 실패가 기대값이면 pooled 는 "데이터가 다양하면 head 가 잘 된다" 는 자명한 답만 낸다. |

## 13. 단서

- **`train_acc` 가 1.000 이 아닌 head 는 3개뿐이고 전부 `p` 다:**
  `color p static_occlusion` **0.931**
  `shape p static_occlusion` **0.954**
  `shape p moving_occlusion` **0.978**
  나머지 51개는 정확히 1.000 으로 포화다. **대조로 읽을 수 있는 것은
  `p` 줄과 이식뿐이다** (CLAUDE.md §7-3). 낮게 나온 세 칸이 표현 탓인지 35 epoch
  미수렴 탓인지 아직 안 갈렸다 — `attn_probe.yaml` 의 `attn_100` 프리셋으로
  그 조건만 다시 돌리면 캐시 적중이라 몇 분에 갈린다.
- head 당 `n_train` 781~787. 클래스당 shape ~112, colour ~98, env ~196.
  `stratify_by: condition` 이라 **조건은 균등하지만 클래스는 아니다.**
- k 별 셀은 방향당 n=172~211 이다. **k 별 요철을 단독 인용하지 말 것** — 이항 SE 가 ~3pp 다.
- **fold 없음 / seed 1개.** `GPUS=1` 로 돌려 head 학습은 결정론적이다.
- **h→p 이식(정렬손실)은 안 쟀다.** config 의 `eval` 이 `[self]` 뿐이다. v8 의 핵심 지표(48.0/49.9, 가림에서 14.8=chance)와 비교하려면 다시 돌려야 한다.
- **`p` 가 문맥 잔상인지 안 갈렸다.** `p = predictor(context)` 라 정보의 출처는 정의상 문맥이고, 물체는 모든 조건의 context 구간에 보인다. 그래서 §11-(1) 의 "정보가 있다" 가 **"predictor 가 미래로 옮겼다"** 인지 **"문맥이 묻어나왔다"** 인지 구분되지 않는다. `z_research/scripts/analysis/is_p_just_context.py` 가 이 질문을 묻는다 (캐시만, GPU 불필요).
- 교란 — occluded 조건에만 가림막이 장면에 추가로 있다. 설계 의도이며 분리 대상이 아니다 (CLAUDE.md §8-5).
