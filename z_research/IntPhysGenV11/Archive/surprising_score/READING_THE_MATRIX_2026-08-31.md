# predictor 는 무엇을 만드는가 — 예제로 (2026-08-31)

`fig_predictor_vote` · `fig_vote_grid_*` · `fig_precision_recall_*` 를 처음 보는 사람용.
결론과 전수 표는 [`VOTE_GRID_2026-08-31.md`](VOTE_GRID_2026-08-31.md).
아래는 전부 **등가속 + 가림, shape** 이다.

---

## 재는 방식

문맥일치 쌍이라 두 clip 의 앞 16프레임이 픽셀 단위로 같다.
따라서 predictor 출력 `p` 는 두 clip 사이에 **비트 단위로 동일**하고, 채점은 이것만 본다:

```
문맥: 물체가 굴러가다 가림막 뒤로 들어감
그 다음 나올 수 있는 것 둘 —  진짜 그 물체  /  다른 물체

p 가 둘 중 어느 쪽에 더 가까운가
```

그래서 **"predictor 가 cube 를 만들었다" 는 항상 "무엇과 견줘서" 가 붙는다.**
아래 표의 각 줄이 그 하나다. 각 줄은 16회씩이고, 한 물체당 6줄 = 96회다.

---

## context 에 cube 가 오면

| 견준 대상 | cube 를 만듦 | 그쪽을 만듦 |
|---|---:|---:|
| sphere | **100.0%** | 0.0 |
| torus | **100.0%** | 0.0 |
| capsule | 93.8% | 6.2 |
| cone | 93.8% | 6.2 |
| pyramid | 87.5% | 12.5 |
| **cylinder** | **43.8%** | **56.2** |
| **합계** | **86.5%** | |

**cube 는 대체로 cube 로 나온다.** 딱 한 곳에서 샌다 — **cylinder 와 견주면 진다.**

## context 에 torus 가 오면

| 견준 대상 | torus 를 만듦 | 그쪽을 만듦 |
|---|---:|---:|
| cone | 12.5% | 87.5 |
| pyramid | 6.2% | 93.8 |
| capsule | 0.0% | **100.0** |
| cube | 0.0% | **100.0** |
| cylinder | 0.0% | **100.0** |
| sphere | 0.0% | **100.0** |
| **합계** | **3.1%** | |

**torus 는 거의 torus 로 안 나온다.** 여섯 중 넷에서는 **한 번도** 안 나온다.

## context 에 sphere 가 오면

| 견준 대상 | sphere 를 만듦 | 그쪽을 만듦 |
|---|---:|---:|
| torus | 93.8% | 6.2 |
| cone | 43.8% | 56.2 |
| pyramid | 43.8% | 56.2 |
| capsule | 18.8% | 81.2 |
| cylinder | 12.5% | 87.5 |
| cube | 6.2% | 93.8 |
| **합계** | **36.5%** | |

**sphere 는 torus 한테만 이긴다.** 나머지 다섯에는 다 진다.

---

## 세 물체를 나란히 놓으면

```
cube    86.5   ->  cylinder 한테만 진다
sphere  36.5   ->  torus 한테만 이긴다
torus    3.1   ->  아무한테도 못 이긴다
```

그리고 이게 **한 줄로 늘어선다.** 일곱 물체 전부:

```
cylinder 90 > cube 86 > pyramid 59 > capsule 58 > cone 48 > sphere 36 > torus 3
```

**어느 물체와 견주는지가 아니라 이 줄에서의 자리가 결과를 정한다.**
42개 방향 중 40개가 이 순서 하나로 설명된다.

**혼동이 아니다.** 헷갈린다면 양방향이 반반이어야 한다. 실제로는:

```
context = cylinder,  torus 와 견줌   ->  cylinder 100%
context = torus,  cylinder 와 견줌   ->  cylinder 100%
```

**어느 쪽에서 출발하든 cylinder 가 나온다.**

---

## 그런데 "잘 만든다" 가 좋은 게 아니다

cylinder 는 자기가 문맥일 때 96번 중 **86번** cylinder 로 나온다. 아주 잘한다.
그런데 **cylinder 가 아닌데도 cylinder 가 나온 경우가 81번** 있다 (위 표들의 오른쪽 열).

```
cylinder 가 나온 경우 = 86 (맞음) + 81 (틀림) = 167
                                  86 / 167 = 51.5%
```

**cylinder 가 나왔다는 사실은 거의 아무 정보도 주지 않는다.** 동전 던지기와 같다.

반대로 torus 는 96번 중 3번만 나오지만(3.1%), 잘못 나온 적은 **1번**뿐이다 → 75.0%.

| | cylinder | torus |
|---|---:|---:|
| 자기일 때 만들어진다 (**recall**) | 89.6 | 3.1 |
| 만들어졌을 때 진짜다 (**precision**) | **51.5** | **75.0** |
| (chance) | 50 | 50 |

---

## 그래서 무엇을 아는가

| 만약 | 행렬 | recall | precision |
|---|---|---|---|
| 정말 잘한다면 | 대각만 진함 | 전부 100 | 전부 100 |
| 그냥 헷갈린다면 | 양쪽이 얼룩짐 | 전부 ~50 | 전부 ~50 |
| **한쪽으로 쏠린다면** | **하삼각만 진함** | **크게 벌어짐** | **전부 ~50** |

실측:

```
recall      3.1 ......................................... 89.6    폭 86
precision            51.5 ....... 75.0                            폭 24
```

**recall 은 86점 벌어지는데 precision 은 24점뿐이고, 잘 만들어지는 물체들이 정확히 50 에 앉아 있다.**

→ **어떤 모양을 더 잘 아는 게 아니라, 어떤 모양을 더 많이 만든다.**

---

## 대조군 — 정지 · 비가림

같은 계산을 정지·비가림에서 하면 폭이 사라진다:

```
recall     90.6 ..... 96.9      폭  6
precision  86.1 ..... 97.8      폭 12
```

일곱 물체가 전부 우상단에 몰린다. **쏠림이 없다.**
즉 위의 쏠림은 표현이 원래 그런 게 아니라 **조건이 만든 것**이다.

그리고 등가속은 **가림이 없어도 이미** 벌어져 있다 (recall 폭 57, precision 폭 40).

---

## 색은 같은 문장으로 쓰면 안 된다

| | recall 폭 | precision 폭 |
|---|---:|---:|
| shape, 등가속+가림 | 86 | 24 |
| color, 등가속+가림 | 39 | 13 |

색은 줄이 훨씬 흐리고, **정지+가림에는 아예 없다**
(상삼각 47.6 ≈ 하삼각 46.4, 순서와 어긋난 칸 30/56).
**색은 "순서대로 진다" 가 아니라 "그냥 진다".**

## 자주 하는 오해

| 오해 | 실제 |
|---|---|
| "predictor 가 cylinder 를 만든다" | 최다 목적지 열 질량이 21~40% (균등 16.7%). **줄의 위쪽으로 흘러내리는 것**이지 특정 물체로 가는 게 아니다. torus 는 여섯 모두에게 거의 고르게 진다 |
| "cylinder 를 잘 예측한다" | recall 만 높다. precision 51.5 는 chance. **너무 많이 만든다** |
| "torus 를 못 만든다" | probe 는 `p` 에서 torus 를 **100%** 로 읽는다. 정보는 있고 거리가 못 읽는 것이다 |
| "가림이 표현을 망가뜨린다" | 배경 probe 는 72칸 전부 100.0 |
| "하삼각만 진한 건 정렬 탓" | 정렬은 대각선이 단조가 되는 것만 보장한다. `k=0` 정지·등속은 어긋난 칸이 **21/42**(반반)로 흩어져 있다 |
| 칸 하나를 읽음 | `(조건, k)` 로 쪼개면 비대각이 **한 방향당 16회 → 4회**가 된다. 행 단위로만 읽는다 |

## 재현

```bash
python z_research/scripts/figures/plot_v11_surprise.py \
  --report z_research/IntPhysGenV11/exp_results/report.json \
  --outdir z_research/IntPhysGenV11/figures/surprise --which vote votegrid pr
```

위 표들은 `report.json` 의 `scoring.cells[].pairs` (`fwd`/`rev` × `n_fwd`/`n_rev`) 를
`condition=moving_occlusion, violation_type=shape` 로 합산해 얻었다.
한 줄 16회 = k 1..4 × 4블록, 한 물체당 6줄 = 96회.
recall/precision 정의는 `plot_v11_surprise.py::fig_precision_recall` 주석에 있다.
