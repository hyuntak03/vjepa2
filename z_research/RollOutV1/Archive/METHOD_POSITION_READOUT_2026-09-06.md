## 1. 무엇을 묻는가

predictor 출력 `p` 는 미래 T 개 슬롯의 latent 다. 질문은 하나다:

> **슬롯 t 의 표현이 "물체가 그 시점에 어디 있을지" 를 담고 있는가.**

담고 있으면 슬롯마다 읽은 위치가 진전하고, 그 기울기가 속도가 된다.
담고 있지 않고 문맥 요약을 복사만 했다면 기울기가 0 이 된다.

**이 방법이 답하지 못하는 것** (§8-A 참조): "predictor 가 물체를 그 자리에 그렸는가",
"상태를 적분해 나르는가". 전자는 readout 이 어느 토큰에서 오는지 안 봤기 때문이고,
후자는 등속에서 1차 외삽으로도 정답이 나오기 때문이다.

| 그 변환이 **선형**임을 보장하는 상수들 | `obj_depth_cm` 1410, 카메라·fov 전부 고유값 1 | 깊이가 변하면 cm→픽셀이 비선형 |
| 지름길을 막는 **설계상의 직교** | 속도 11 × anchor 3 이 33셀 균등 | "마지막 프레임 복사" 차단 (§7) |

## 3. 파이프라인

```
문맥 C 프레임 ─encoder→predictor→ p = (T·S, D)              미래는 모델에 안 보여줌
                                    │  S = (img/patch)² = 256 공간토큰
                                    │  T = 미래프레임 / tubelet = 8 슬롯
                                    ↓  공간 S 개를 평균
                                  (T, D) = (8, 1280)
                                    ↓  클립·슬롯을 **구분 없이** 행으로 쌓음
        X (N_train·T, D) = (29568, 1280),   y (29568,)      ← train 절반만
                                    ↓  최소제곱 (표준화 없음, SVD)
                                  w (D+1,) = (1281,)
                                    ↓  얼려서 held-out 클립에 적용
                                x̂ (N_val, T)
                                    ↓  T 점에 직선 적합
                                  b̂  → 진짜 v 와 비교
```

같은 절차를 **`h`(target encoder 의 미래 절반)** 에도 돌린다. `h` 는 실제 미래를 본
인코더라 **도구 천장**이고, `p` 는 그 천장 대비로 읽는다.

### 캐시 레이아웃 (`features.cache_dir/<tag>/`)

| base | 토큰 수 | 내용 |
|---|---:|---|
| `ctx_masked` | `T·S` = 2048 | 문맥 인코더 출력 `LN(z)`. 미래 토큰을 transformer **이전에** 떨궈 만든 것 |
| `target` | `2T·S` = 4096 | target encoder 가 **32프레임 전부**를 한 번에 본 것. 앞 절반 = 문맥, 뒤 절반 = `h` |
| `predictor` | `T·S` = 2048 | `p` |

```python
p     = P[i].reshape(T, S, D).mean(1)          # (8, 1280)
h     = H[i, T*S:].reshape(T, S, D).mean(1)    # (8, 1280)  ← 미래 절반만
h_ctx = H[i, :T*S].reshape(T, S, D).mean(1)    # ⚠️ §8-J — 미래를 봤다. 쓰지 말 것
```

## 4. 라벨

**픽셀에서 물체를 찾지 않는다.** 렌더 메타데이터의 해석식으로 만든다.

```
x_cm(raw f) = anchor + v · (f − anchor_frame) / fps
x_norm      = x_cm / frame_half_width_cm            # 정규화 이미지 좌표 [-1, +1]

슬롯 t 가 덮는 raw 프레임 = {F0 + stride·2t,  F0 + stride·(2t+1)}
  RollOut_v1: stride 3, F0 = 48  →  {48+6t, 51+6t}
  두 프레임 평균이므로 (f − 45) 의 평균 = 4.5 + 6t
```

### 라벨 검증은 **두 단계** 다 해야 한다

1. **메타데이터 정합** — 공식이 `x_predict_first_cm` / `x_predict_last_cm` 을 재현하는가
   → RollOut_v1 전수 `max|Δ| = 0`
2. **픽셀 정합** — 그 좌표가 **실제 화면의 물체를 가리키는가**
   → 움직이는 클립 60개 × 5프레임에서 시간중앙값 배경 차분으로 물체 열을 잡아 회귀

   ```
   픽셀 = −0.9855 · 라벨 + 0.0040      R² = 0.99676     잔차 0.14 격자칸
   ```

   **world +x 가 화면 왼쪽이다.** 1번만 하고 2번을 빠뜨리면 이 부호를 못 잡는다 (§8-F).

## 5. 프로브

```python
def fit_lstsq(X, y):
    Xb = np.hstack([X, np.ones((len(X), 1))])        # bias 열
    return np.linalg.lstsq(Xb, y, rcond=None)[0]     # SVD, rcond 로 작은 특이값 절단
```

- **표준화하지 않는다.** OLS 는 특징 스케일에 불변이라(가역 아핀 재매개화) self 에서는
  결과가 같고, 이식에서는 학습 소스의 `mu/sd` 를 다른 소스에 씌워 교란을 만든다
- **29,568 식 × 1,281 미지수** — 23배 과결정
- **닫힌 해**라 epoch·lr·수렴·시드가 없다. 결정론적
- split 은 조건(속도×anchor) 층화 50/50

### ★ 이 측정의 유일한 방어선

> **`w` 하나를 T 슬롯 전부에 공유한다. `w` 는 지금 몇 번 슬롯인지 모른다.**

`p` 가 문맥 요약을 T 슬롯에 복사만 했다면 슬롯이 전부 같은 값이 되고, 같은 `w` 가 같은 값을
T 번 내놓아 **기울기가 0** 이 된다. 실측으로 확인했다 — 8칸을 인위적으로 동일하게 만들면
β 가 `+0.0000` 이 된다.

**슬롯별로 `w` 를 따로 학습하면 이 성질이 통째로 깨진다. 절대 하지 말 것.**

## 6. 지표

| 지표 | 정의 | 무엇에 민감 |
|---|---|---|
| **위치 R² (클립내부)** | 클립마다 T 칸 평균을 뺀 뒤 `x̂` vs 정답 | T 점이 **각각** 제자리인가 |
| **속도 R²** | T 칸에 직선 적합 → `b̂`, 그 `b̂` vs 진짜 `v` | 적합한 **기울기 값**이 맞나 |

### 둘의 관계 — 직교 분해

등속이면 클립 내부의 정답이 **정확히 직선**이고, 최소제곱 잔차는 `t − t̄` 와 직교하므로:

```
‖예측 − 정답‖²  =  (b̂ − 진짜기울기)² · ‖t−t̄‖²   +   ‖잔차‖²
                    └─ 속도 R² 가 보는 것 ─┘      └─ 속도 R² 는 버린다 ─┘
```

따라서 **항상 `속도 R² ≥ 위치 R²`** 이고 그 차이가 직선 주변 흔들림이다
(실측 `h` 0.036, `p` 0.057). "선형성" 은 별개의 셋째 지표가 아니라 위치 R² 안에 들어 있다.

### 속도 환산

```
b̂ 는 "슬롯당 정규화 x" 단위.
슬롯 간격 = stride · tubelet_size raw프레임 = 6 프레임 = 6/16 = 0.375 s
cm/s = b̂ × frame_half_width_cm / 0.375 = b̂ × 2050.9
```

## 7. 대조군 · null (전부 필수)

| 이름 | 기대 | 배제하는 것 | RollOut_v1 실측 |
|---|---|---|---|
| **`h→h`** | 높게 | 도구 무력 | 위치 0.952 / 속도 0.988 |
| **`v = 0` 셀** | `b̂ ≈ 0` | 프로브가 무조건 진전을 만들어냄 | `h` +0.1 / `p` −1.7 cm/s |
| **슬롯 순서 셔플** | β = 0 | 위치가 슬롯에 안 묶여 있음 | **−0.0002** |
| **T칸 동일** (복사기 모사) | β = 0 | §5 방어선이 실제로 작동하는지 | **+0.0000** |
| **라벨 클립간 셔플** | β = 0 | 우연한 상관 | **+0.0012** |
| **설계상 속도 ⊥ anchor** | — | "마지막 프레임 복사" | (데이터 수준) |

### time-index 누수 배제 논리

등속이면 `위치 = v·t` 라, `p_t` 에 "몇 번째 슬롯인가" 가 남아 있으면 probe 가 물체가 아니라
`t` 를 읽어도 속도가 맞을 수 있다. 배제는 두 줄이다:

- `t` 만 읽으면 모든 클립에서 같은 T 개 값 → `b̂` 가 **상수** → **β = 0** (실측 +0.947)
- 클립 평균을 뺀 라벨이 `v·(t−t̄)` 인데 `v` 가 대칭이라 상수 기울기는 아무것도 설명 못 함
  → **클립내부 위치 R² ≈ 0** (실측 0.911)

## 8. 함정 — 전부 실제로 밟은 것

### A. `(1, D)` 로 전부 평균해 속도를 직접 회귀하면 안 된다

`v` 는 **문맥에 이미 있고** `p = predictor(context)` 다. 슬롯을 평균해 버리면 슬롯별 차이가
사라져서 **복사기가 통과한다.** 실측:

| | β | R² |
|---|---:|---:|
| `(1,D)` 전체평균 → `v` 회귀 | +0.993 | 0.9931 |
| **위 상태에서 T칸을 전부 동일하게 만든 뒤** | **+0.993** | **0.9931** |

숫자가 하나도 안 변한다. **반드시 슬롯별 위치 → 기울기** 로 갈 것.

### B. 전체 위치 R² 를 인용하면 안 된다 — anchor 가 80% 다

```
위치 라벨 분산    전체 100.0%
                 ① 클립 간 (시작 위치)   80.7%
                 ② 클립 내 (움직임)      19.3%   ← 묻는 것
```

anchor 만 맞혀도 전체 R² 가 0.81 은 그냥 나온다. **클립 평균을 뺀 ② 만 본다.**
같은 이유로 **"읽은 위치 vs 진짜 위치" 산점도도 그리지 말 것** — 대각선에 붙는 것의
대부분이 "어디서 시작했는지 안다" 는 뜻이 된다.

### C. 슬롯별 R² 는 가운데가 U 자로 꺼진다 — 지표 결함이지 현상이 아니다

클립 평균을 빼면 중앙 슬롯의 정답이 0 에 가까워져 R² 분모가 붕괴한다. 실측:

```
          t=0     t=1     t=2     t=3     t=4     t=5     t=6     t=7
정답분산  0.0353  0.0180  0.0065  0.0007  0.0007  0.0065  0.0180  0.0353
h         0.979   0.961   0.893   0.162   0.117   0.896   0.952   0.975
p         0.959   0.893   0.810  -0.538  -0.225   0.832   0.914   0.955
```

**슬롯별로는 절대 오차(cm)로 그린다.** 그러면 깨끗하게 단조로 나온다.

### D. 표준화는 self 엔 무의미하고 이식엔 해롭다

OLS 는 스케일 불변이라 self 결과가 같고, 이식에서는 학습 소스의 `mu/sd` 로 다른 소스를
표준화해 "좌표가 다르다" 와 "스케일이 다르다" 를 섞는다. **쓰지 않는다.**

### E. soft-argmax 로 "물체 토큰 찾기" 는 전제가 틀렸다

처음에 격자 위 soft-argmax 로 "어느 토큰이 물체인가" 를 배우게 했다. `α` 를 프레임에 겹쳐 보니
**attention 이 물체 위에 전혀 없고 배경에 흩뿌려져 있는데도 `x̂` 는 정확했다.**
ViT 토큰은 local patch 가 아니라 전역 문맥을 담은 표현이라 배경 토큰도 물체 위치를 안다.
**"물체를 찾는다" 는 전제가 애초에 틀렸다.** 그런데 그건 이 측정의 결함이 아니다 —
묻는 것은 "`p_t` 가 그 시점 위치를 담는가" 이고 분산 저장이어도 답은 같다.
**단순 공간평균으로 갈 것. soft-argmax 로 되돌아가지 말 것.**

### F. 라벨 검증을 메타데이터로만 하면 부호를 놓친다

`max|Δ| = 0` 은 **메타데이터끼리의 정합**이지 "이 좌표가 화면의 물체를 가리키는가" 가 아니다.
픽셀 대조를 안 해서 **world +x 가 화면 왼쪽** 이라는 것을 늦게 발견했다. 회귀 결과에는
영향이 없지만(전역 부호는 `w` 가 흡수), **라벨을 격자 열 번호로 바꿔 쓰는 분석은 전부 틀어진다.**

### G. `--max-clips` 를 정렬 인덱스 앞에서 자르면 조건이 통째로 빠진다

index 가 condition 순으로 정렬돼 있어 앞부분만 자르면 일부 속도(특히 `v=0`)가 val 에서
사라진다. **셀 안에서 잘라야 한다.** 코드에 `val 에 속도 레벨이 다 없다` 가드가 있다.

### H. 프레임 예산·해상도

원본 288px 이 256 으로 **crop 없이 bilinear(antialias off)** 리사이즈되므로 정규화 좌표가
보존된다 (`evals/world_model_analysis/data.py:223-241`). v11 도 288 렌더라 같은 경로다.

### I. sbatch `--wrap` 은 `/bin/sh` 다

`source activate` 가 안 먹는다 (`source: not found`, exit 127). **인터프리터 절대경로**
`/data/hyuntak/anaconda3/envs/vjepa2/bin/python` 로 직접 부를 것.

### J. `target.npy` 의 문맥 절반은 미래를 봤다

target encoder 는 32프레임을 **한 번에** 넣고 돌리는 bidirectional transformer라,
앞 절반 토큰도 뒤 16프레임에 attend 했다. **문맥 쪽 baseline 을 만들 때 쓰면 누수다.**
문맥 전용이 필요하면 `ctx_masked` (미래 토큰을 transformer 이전에 떨군 것)를 쓴다.

### K. 캐시는 노드 로컬이다

RollOut_v1 캐시(145 GiB)는 **vll6 의 `/data2`** 에 있다. vll5 에서는 안 보인다.
`-w vll6` 로 제출할 것. v11 캐시는 반대로 vll5 에 있다.

### 9-2. 등가속이면 라벨이 **2차식**이다

```
flat  (surface = flat) :  x(t) = x0 + v·t              1차 → 기울기 하나
ramp  (surface = ramp) :  x(t) = x0 + v0·t + ½·a·t²    2차 → 기울기가 t 에 따라 변한다
```

→ **`slope()` 를 그대로 쓰면 안 된다.** 선택지 둘:
- (a) 2차 적합으로 `v0` 와 `a` 를 각각 읽는다 (더 정보가 많다)
- (b) `flat` 조건만 쓰고 `ramp` 는 별도로 다룬다

`ramp_acc_cm_s2` 가 2값뿐이라 (a) 가 자연스럽다. **"가속을 읽는가" 가 v11 의 새 질문이 된다.**

### 9-3. 가림 조건에서는 "정답 위치" 가 화면에 없다

물체가 가림막 뒤에 있어도 **물리적 위치는 해석식으로 정의된다.** 그게 이 실험의 요점이다 —
보이지 않는 구간의 위치를 표현이 담고 있는지 묻는 것. 다만 §4 의 **픽셀 검증은 가시 프레임에서만**
할 수 있다.

### 9-4. 위반 변이를 빼야 한다

`vanish` 의 불가능 변이는 물체가 사라져 위치 라벨이 없다. `shape`/`color` 는 위치가 같지만
안전하게 **`probe_type == obj`(가능 + 물체 있음)만** 쓴다 — `attn_probe` 의 `block_types: [obj]` 와 같다.

### 9-5. 그 밖

- **캐시 위치가 vll5** (§8-K). 제출 노드를 바꿀 것
- `condition` 이 6(v11) / 12(v11_full) 종이라 층화 셀 수가 다르다
- v11 에는 **`v = 0` 대조군이 `static` 조건으로 존재**한다 — 그대로 내장 대조군이 된다
- 속도 레벨이 **3개뿐**(0 / 115.85 / 260.12)이라 §7 의 "11 레벨 산점도" 가 3점으로 줄어든다.
  β·R² 의 신뢰도가 떨어지므로 **anchor 대응 축이 있는지 먼저 확인**할 것
