## 한 줄

**predictor 가 지어낸 8개 미래 슬롯에서 물체의 위치와 속도가 읽힌다.
실제 미래를 본 인코더 대비 96~98%. 복사기가 아니다.**

| | 위치 R² (클립내부) | 속도 R² | 위치 오차 | 속도 오차 |
|---|---:|---:|---:|---:|
| `h→h` (도구 천장) | **0.952** | **0.988** | 19.7 cm (물체폭 10%) | 9.1 cm/s (범위 2.8%) |
| `p→p` (핵심) | **0.911** | **0.968** | 29.9 cm (물체폭 16%) | 14.9 cm/s (범위 4.6%) |
| `p / h` | 0.96 | 0.98 | — | — |

전수 7,392 clip, held-out 3,696 clip 채점.
`h` = target encoder 의 미래 절반(실제 미래를 본 것), `p` = predictor 출력(미래를 못 본 것).
**읽어낸 좌표가 항상 물체 안에 떨어진다** (물체 폭 190 cm, 오차 20~30 cm).

## 1. 파이프라인

```
문맥 16프레임 ─encoder→predictor→ p = 8슬롯 × 256칸 × 1280        (미래는 안 보여줌)
                                    ↓ 256칸 공간평균
                                  (8, 1280)
                                    ↓ 클립·슬롯을 전부 행으로 쌓음
        X (3696×8, 1280) = (29568, 1280),  y (29568,)              ← train 절반만
                                    ↓ 최소제곱 (표준화 없음, SVD)
                                  w (1281,)
                                    ↓ 얼려서 held-out 3696 clip 에 적용
                                x̂ (3696, 8)
                                    ↓ 8점에 직선 적합
                                  b̂ → 진짜 v 와 비교
```

**정답 라벨**은 렌더 메타데이터에서 해석적으로 만든다 (픽셀 측정 없음):

```
x_cm(raw f) = flat_anchor_x_cm + flat_v_cm_s · (f − 45)/16     # anchor 는 프레임 45 = 문맥 마지막
x_norm      = x_cm / 769.0909                                  # frame_half_width_cm
슬롯 t 는 raw {48+6t, 51+6t} 두 장 → (f−45) 평균 = 4.5 + 6t
```

### 속도를 뽑는 계산 (8점 → 스칼라 1개)

```
t = 0..7,  tc = t − 3.5
b̂ = Σ x̂_t·tc / Σ tc²                       # x̂ 를 t 에 회귀한 OLS 기울기. 분모는 항상 42
cm/s = b̂ × 769.0909 / (6/16) = b̂ × 2050.9    # 칸 간격 6 raw프레임 = 0.375 s
```

### 이 측정의 유일한 방어선

**`w` 하나를 8슬롯 전부에 공유한다. `w` 는 지금 몇 번 슬롯인지 모른다.**
`p` 가 문맥 요약을 8슬롯에 복사만 했다면 8칸이 같은 값이 되고 기울기가 0 이 된다.
**슬롯별로 따로 학습하면 이 성질이 깨진다 — 하지 말 것.**

⚠️ **GT 속도는 프로브 입력에 들어가지 않는다.** 라벨을 만들 때와 맨 끝에 답을 맞출 때만 쓴다.

## 2. 두 지표

등속이라 클립 내부의 위치 라벨은 **정확히 직선**이다. 두 지표는 같은 신호를 다른 엄격도로 잰다.

| 지표 | 정의 | 무엇에 민감한가 |
|---|---|---|
| **위치 R² (클립내부)** | 클립마다 8칸 평균을 뺀 뒤 `x̂` vs 정답 | 8개 점이 **각각** 제자리인가 |
| **속도 R²** | 8칸에 직선 적합 → `b̂`, 그 `b̂` vs 진짜 `v` | 적합한 **기울기 값**이 맞나 |

정답이 완벽한 직선이고 최소제곱 잔차는 `t−3.5` 와 직교하므로 위치 오차가 교차항 없이 갈린다:

```
‖예측 − 정답‖²  =  (b̂ − 진짜기울기)² · ‖t−3.5‖²   +   ‖잔차‖²
                    └─ 속도 R² 가 보는 것 ─┘        └─ 속도 R² 는 버린다 ─┘
```

따라서 항상 `속도 R² ≥ 위치 R²` 이고 **그 차이가 직선 주변 흔들림의 양**이다
(`h` 0.036, `p` 0.057).

⚠️ **최소제곱은 8점이 직선 위에 있든 없든 기울기를 내놓는다.**

### ⚠️ 위치 R² 는 반드시 "클립내부" 로 볼 것

위치 라벨의 분산은 두 갈래이고 비율이 크게 다르다 (전수 계산):

```
전체 분산                100.0%
 ① 클립 간 (시작 위치)     80.7%   <- anchor 3단계
 ② 클립 내 (움직임)        19.3%   <- 우리가 묻는 것
```

**anchor 만 맞혀도 전체 R² 가 0.81 은 그냥 나온다.** 그래서 클립 평균을 뺀 ② 만 본다.

## 4. null 대조군 — 우연이 아니다

셋 다 β 가 0 으로 죽는다 (`p→p` 실제값 +0.947, R² 0.968):

| null | β | R² |
|---|---:|---:|
| **튜블릿 순서 셔플** (클립마다 8칸을 무작위 치환, 라벨은 그대로) | **−0.0002** | 0.0000 |
| **8칸 동일** (복사기 모사 — 8칸을 클립 평균으로 덮음) | **+0.0000** | 0.0003 |
| **라벨 클립간 셔플** | **+0.0012** | 0.0000 |

**튜블릿 순서 셔플이 결정적이다** — 슬롯 순서만 섞어도 신호가 완전히 사라진다.
위치 정보가 **어느 슬롯이냐에 묶여 있다**는 뜻이다.
"8칸 동일" 이 0 인 것은 §1 방어선이 실제로 작동한다는 증거다.

### time-index 누수도 배제된다

**우려**: 등속이면 `위치 = v·t` 이므로, `p_t` 에 "몇 번째 슬롯인가"(positional embedding 잔상)가
남아 있으면 probe 가 물체가 아니라 **`t` 를 읽어도** 속도가 맞게 나올 수 있다.

**배제**: `t` 만 읽으면 모든 클립에서 같은 8개 값이 나와 `b̂` 가 **상수**가 된다. 그러면
- 클립별 (`b̂`, `v`) 회귀 기울기 **β = 0** 이어야 한다 → 실측 **+0.947**
- 클립내부 위치 R² ≈ 0 이어야 한다 (클립 평균을 뺀 라벨이 `v·(t−3.5)` 인데 `v` 가 ±160 대칭이라
  상수 기울기는 아무것도 설명 못 한다) → 실측 **0.911**

11 속도를 단조롭게 따라가는 §3-3 표가 곧 (예측 속도, GT 속도) 산점도다 (셀당 336 clip).

### 왜 `(1,D)` 로 평균해서 속도를 직접 회귀하면 안 되나

같은 실행에서 확인했다:

| | β | R² |
|---|---:|---:|
| `(1,D)` 전체평균 → `v` 직접 회귀 (`p`) | +0.993 | 0.9931 |
| **위 상태에서 8칸을 전부 동일하게 만든 뒤 다시** | **+0.993** | **0.9931** |

**복사기로 만들어도 숫자가 하나도 안 변한다.** `v` 는 문맥에 이미 있고 `p = predictor(context)`
이므로, 8칸을 평균해 버리면 "미래를 만들었나" 가 아니라 "문맥에 속도가 있나" 만 재게 된다.

## 6. 말할 수 있는 것

✅ **`p` 의 8슬롯은 서로 다르고, 그 차이가 "물체가 시간에 따라 이동한다" 는 형태다.**
   복사기가 아니다 (null 3종 전부 0).

✅ **위치가 슬롯별로 물체 폭 안쪽 정밀도로 읽힌다** (MAE 0.31 격자칸, 물체 폭 ~2칸).

✅ **속도의 방향은 11단계 전부 정확하고, `v=0` 을 정지로 읽는다.**

✅ **오차가 작다** — 위치는 물체 폭의 10~16%, 속도는 범위의 2.8~4.6%.

✅ **time-index 를 읽은 것이 아니다** (§4).

✅ **도구 천장(`h→h`) 대비 96~98%.**

## 말할 수 없는 것

❌ **"상태를 통합해 나른다 / evolution 한다" 는 못 쓴다.** 등속이라 **문맥 마지막 몇 프레임에서
   1차 외삽**하면 정답이다. 이 실험이 죽인 것은 **"복사기다" 라는 가설 하나**이고 그 이상은 아니다.
   가르려면 **문맥 끝에서 물체를 가리는 팔**이 필요하다.

❌ **"가속에서 못 굴린다" 는 이 측정으로 안 쟀다.** v11 의 ramp 조건에서 이 위치 readout 을
   돌린 적이 없다 (v11 채점 정확도는 다른 측정이다).

❌ **"predictor 가 물체를 그 자리에 그렸다" 는 못 쓴다.** readout 이 물체 토큰에서 오는지
   확인되지 않았다. 말할 수 있는 것은 **"`p_t` 안에 그 시점 위치와 선형으로 정렬된 방향이 있다"** 까지다.

❌ **크기 왜곡(중간 과대·양 끝 과소)의 원인을 못 짚는다** (§3-3). 주장으로 쓰지 않는다.
