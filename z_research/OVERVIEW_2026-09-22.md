## 0. 30초 요약

**무엇을 하나.** V-JEPA 2 (frozen ViT-H) 의 latent predictor 가 **관측이 끊긴 구간의 상태를 이어 가는가** 를
통제된 합성 물리 영상으로 잰다. 채점은 하나뿐이다:

```
surprise = mean |predictor(context) − LN(target_encoder(clip))[future]|      (latent L1)
surprise(impossible) > surprise(possible) 이면 정답.  chance 50%.
```

**현재 답 (한 문장).** predictor 는 상태를 이어 가지 않는다. **문맥을 조회할 뿐이다.**
미래 토큰끼리 서로를 참조하지 않고 (`mask→mask` Δ **−1.4** ✓), 문맥 조회가 전부다 (`mask→ctx` Δ **−37.5** ✓).
이 하나의 성질이 관찰된 실패를 전부 설명한다 (§5-2).

**성적표** (state evolution 네 능력, 2026-09-19 사용자 정의):

| 능력 | 판정 | 한 줄 근거 |
|---|:--:|---|
| **1 읽기** — 문맥에서 상태를 꺼내는가 | ✅ | z → 문맥 끝 속도 ridge R² 0.996 / 0.989; `p` self probe shape **98.46** ✓ / env **100** ✓ |
| **2 지속** — 관측에서 멀어져도 남는가 | ❌ | 마지막 관측 자리에서 **2~3 칸 (40~60 px)** 안에서만 유지 |
| **3 전이** — 문맥에 따라 미래를 바꾸는가 | ◐ | 방향·속도는 이어 가고 **가속도는 반영 안 함** (flat_a p 28 ≈ 등속 외삽 28, 진실 49) |
| **4 영속** — 공백을 넘는가 | ❌ | 물체다운 토큰이 남는 슬롯: late **0** < early/mid **3** < 가림 없음 **4~5** |

### 2-1. ① 의 병합 규칙 — 세 조각이 실행 직전에 합쳐진다

```
run.sh <프로토콜> <데이터셋> [모델]   →  harness/resolve.py
   configs/protocols/<프로토콜>.yaml   재는 방식 (프레임 배치 · 채점 규칙 · probe 정의 · dtype)
   configs/protocols/datasets.md       ## <이름> 아래 key: value  (경로 · 인덱스 · 컬럼)
   configs/protocols/models.md         ## <이름> 아래 key: value  (체크포인트 · arch)

병합 — 프로토콜이 이긴다:
   data  = { **datasets.md[<데이터셋>], **프로토콜.data  }
   model = { **models.md[<모델>],       **프로토콜.model }

자동 결정 (TAG= / OUTDIR= 으로 덮음):
   tag        = <데이터셋.cache_tag>_<모델>                 예: v11_vith
   output_dir = <데이터셋.results_root>/<프로토콜>__<데이터셋>_<모델>

출력  <output_dir>/{summary.json, per_block.json, predictions.json, _resolved.yaml}
캐시  <features.cache_dir>/<tag>/{meta.json, target.npy, ctx_masked.npy, predictor.npy, …}
```

**데이터를 바꿀 때 고치는 곳은 `datasets.md` 섹션 하나뿐이다.** yaml 은 건드리지 않는다.
`tag` 에 프로토콜이 **일부러 빠져 있다** — (데이터셋, 모델) 이 같으면 프로토콜이 달라도 같은 캐시를 쓴다.

`resolve.py` 는 **모델 로드 전에** 경로·인덱스 실물, `resolution == img_size`, 프레임 예산을 검사하고 안 맞으면 죽는다.
ViT-H 로딩이 프로세스당 ~2 분이라 그 전에 죽는 게 훨씬 싸다 → **`DRYRUN=1` 을 먼저 쓴다.**

### 3-2. 문서 규칙 (CLAUDE.md §8-3)

- 하단에 반드시 **`## 재현`** 절 — 정확한 명령줄 + config 경로
- **철회·정정을 지우지 않고 문서 안에 남긴다.** `⚠️ 정정 —`, `**철회.**`, `## 폐기한 가설들 (기록)`.
  **"다시 시도하지 말 것" 까지 적는다**
- 대체된 문서는 지우지 않고 맨 위에 blockquote 로 **"대체됨 + 정본 경로"**
- 한 문서 안에서 언어 통일 (심층 분석·종합 노트는 한국어)
- **단서(caveat)를 결론과 같은 비중으로 쓴다** — 이 레포에서 가장 일관되게 지켜진 관례다.
  거의 모든 결과 문서에 "말할 수 있는 것 / 말할 수 없는 것" 절이 있다

### 3-3. 그림 규칙 (§8-4)

- **한글 폰트가 없다. 플롯 라벨은 반드시 영어.** 주석은 한글 OK
- 탐색용 `DejaVu Sans` / 논문용 **`Nimbus Roman`** + `pdf.fonttype 42` + 벡터 PDF, double-column 7.0in
- 패널 라벨 `(a)`–`(d)` 를 각 패널 **아래 가운데**
- **서술 문장은 그림에 넣지 않는다 — 캡션으로 뺀다**
- 색은 검증된 팔레트 slot 1–3 만: `#2a78d6` / `#eb6834` / `#1baf7a`
- **그림 폴더는 스크립트 상단 `FIGDIR` 표가 배정한다.** 표에 없는 이름은 최상위에 떨어진다
  (새 그림이 눈에 띄라고 **일부러**). 파일만 옮기면 다음 실행에서 도로 흩어지므로 표를 같이 고친다
- 대체된 그림은 `_superseded/` 로 내리고 **README 에 왜 물러났는지 적는다**

### 3-4. 새 yaml 을 만들지 않는다 (§3-4)

**기준은 하나 — 재는 방식 자체가 다른가?** (다른 index, 다른 표현 지점, 다른 라벨 의미)
그 밖은 전부 셋으로 처리한다:

| 장치 | 쓸 때 |
|---|---|
| `fit_groups_sweep: auto` | 데이터셋마다 조건 구성이 다를 때 (group 값을 읽어 sweep 자동 생성) |
| `SET="a.b=1 c.d=null"` | 일회성 변형 (epoch, target 하나, sweep 지정) |
| `extends:` | 구조가 진짜 다른 실험 (자식이 이기고 dict 재귀 병합, list 교체, `null` 삭제) |

실제로 `attn_probe_flat`·`attn_probe_e50_staticocc` 를 이렇게 없앴다. **프로토콜은 5 개로 유지된다.**

### 3-5. 인덱스 스키마

**IntPhysGen 공통 14 컬럼**: `video_id, file, file_name, block_id, source_block, variant, plausible,
pair_id, condition, motion, has_occlusion, violation_type, game_name, role`

- `file` 은 **비어 있다** — 프레임은 `frames_root` + `frames_pattern` 으로 **원본 PNG 직독**
  (리사이즈는 `antialias=False` bilinear — 공식과 같은 커널). Jongseo physv3 만 mp4 직독
- `variant` ∈ `pos_a / pos_b / imp_ab / imp_ba`, `plausible` 정확히 반반
- 동반 `context_integrity.json` — **모든 matched pair 의 16 context 프레임 픽셀 단위 전수 감사.
  v6~v8 · 2D · v10 · v11 전부 mismatch 0**
- **v11 은 여기에 `sym_k` (0~4) 가 추가된다.** `condition` 은 6 개이고 k 를 접지 않았다
  (접었으면 `fit_groups_sweep: auto` 가 216 head 를 만든다. 지금은 63)
- **`index_probe.csv`** = 위 + 라벨 컬럼 + **`probe_type`** ∈ `obj` (가능+물체 있음 = **유일한 probing 대상**) / `empty` / `imp`

⚠️ **개입이지 관찰이 아니다.** ⚠️ `ctx→ctx` 가 0 인 것은 "불필요" 와 "인코더와 중복" 을 못 가른다.

### 5-5. 기전 — 신호가 묽어진다

### 5-6. 위치 readout (RollOutV2) — **p 는 마지막 관측에서 2~3 칸 안에서만 물체를 유지한다**

별도 학습셋 (무중력 등속 8,064 clip) 에서 attentive 위치 자 (**3,842 파라미터**) 를 p / z / h 각각에 정하고
`RollOut_v2` (9 시나리오) 와 v11 가림 셀에 **test 로만** 건다. **1 칸 = 18 px = 물체 반폭.**

**자 검증부터 보인다** (사용자 지시 2026-09-12: "decoder 문제 없다를 보여야 predictor 가 만드는 세상에 대해 주장할 수 있지"):

| 검증 | 값 |
|---|---|
| held-out (학습셋 절반) | **0.87 칸** (학습 0.83) |
| encoder 자 대조 | v2 전 시나리오 **≤ 0.61 칸**; v11 가림 타이밍 무관 추적 |
| **파라미터 없는 교차검증** | `r = \|p−h_imp\| / \|p−h_pos\|` (파라미터 0) 와 **슬롯 단위 일치** |
| 기각 | v11 k=0 p 만으로 학습하면 **자리 prior 를 외운다** (오차 3 px 인데 물체 attention 0.1). 재시도 금지 |

**시나리오별 (진행 방향, 가능 clip 784 개씩)**:

| 시나리오 | 진실 변위 px | p | h | 등속 외삽 | p gain (corr) | 물체 질량 s0 / s7 |
|---|---:|---:|---:|---:|---:|---|
| flat_v (등속) | 44.8 | 39.3 | 43.9 | 44.8 | **0.85** (0.98) | 0.75 / 0.37 |
| flat_a (가속) | 49.4 | **28.2** | 48.7 | **28.4** | 0.57 (0.97) | 0.72 / 0.25 |
| flat_d (감속) | 78.4 | 71.0 | 79.8 | 101.3 | **0.26 (0.49)** | 0.75 / 0.17 |
| ramp_a | 68.4 | 38.2 | 69.4 | 47.8 | 0.40 (0.67) | 0.57 / 0.11 |
| ramp_d | 74.6 | 62.2 | 74.4 | 95.0 | **0.26 (0.34)** | 0.67 / 0.15 |

- **가속에서 p 의 평균 변위 = 등속 외삽** (28.2 vs 28.4) — **가속을 이어가지 않는다**
- 감속에서는 진실에 가깝지만 clip 사이 gain 0.26 / corr 0.49 — **clip 마다의 감속량을 따라가지 않는다**
- **자는 감속도 읽는다** (h/z gain 1.00–1.15) → 자의 실패가 아니다

**거리 한계 (2026-09-19, 이 세트의 결론)**:
p 의 물체다운 토큰은 **마지막 관측 자리에서 약 2~3 칸 (40~60 px) 안**에서만 유지된다.
**슬롯보다 거리가 주 변수다** — 자 없는 검사 회귀: 거리 100 px 당 **−0.47**, 슬롯 **−0.28** (자 attention 과 같은 계수).
등속 arc 수평에서도 **53 px 에서 멈춘다** (진실 92) → 등속 외삽이 아니다.

**왜**: z 는 문맥 끝 속도를 담는다 (ridge R² **0.996 / 0.989** → "encoder 가 속도를 약하게 담아서" **기각**).
predictor 는 4~5 칸 떨어진 과거 자리에서 물체를 **가져올 능력은 있는데** (knockout r=3→5 에서 적중 0.38→0.72),
멀면 진실 칸 미래 query 가 물체 궤적을 **균등 수준으로만** 본다 (0.073 → 0.021).

**v11 로 이식**: 물체다운 토큰이 남는 길이 = late **0** 슬롯 < early/mid **3** < 가림막 없음 **4~5**.
**채점 vs 위치는 별개 축** — vanish 채점 early 97.8 / mid 95.8 / late 57.5 인데 위치는 셋 다 3 슬롯 안 소실.

⚠️ **읽는 규칙 (반드시)**: **자는 물체가 없어도 위치를 낸다** — attention 이 퍼지면 토큰 평균 읽기 = **기본값**.
v11 의 기본값 ≈ 마지막 관측 위치, wall 의 기본값 ≈ 정지점. 그래서 **위치 주장은 그 슬롯의 3×3 attention 질량이
균등 (0.035) 을 넘을 때만** 한다. 8 슬롯 평균 지표는 슬롯별 표와 **같이** 읽는다.
**이것 때문에 하루를 잘못 읽었다** — §7 의 철회 두 개가 거기서 나왔다.

### 7-3. 설계 결정 — 다시 교란으로 제기하지 말 것

두 대비는 **의도된 조작**이다. 여러 번 "교란" 으로 제기했다가 매번 같은 답을 받았다.

| 축 | 무엇을 비교하는가 | 함께 바뀌는 것 |
|---|---|---|
| **가림 유무** (`visible` vs `occlusion`) | **물체가 가려지는가** | 가림막이 장면에 있는가 |
| **지면** (`moving_flat` vs `moving`) | **등속 vs 등가속도** | 쐐기가 장면에 있는가 |

물체를 가리려면 가림막이 있어야 하고, 중력으로 가속시키려면 경사면이 있어야 한다. **조작의 구현이지 교란이 아니다.**
- ✅ "물체가 가려지면 무너진다. 가려지는 **시간**은 무관하다" · ✅ "등가속이 등속보다 나쁘다"
- ❌ "가림막이 화면에 있는 것 자체는 영향이 없다" — **안 쟀다**
- ❌ "가속만이 원인이고 장면 구성은 무관하다" — **안 쟀다**

### 7-4. 금지 표현

| 쓰지 말 것 | 왜 |
|---|---|
| "predictor 가 X 를 못 만든다" / "p 에 정보가 없다" | probe 가 98.5 로 읽는다. → **"이어가지 않는다"** |
| "가림이 표현을 망가뜨린다" | `env` 72 칸 전부 100 |
| "표현이 회전했다 / 정렬이 깨졌다" | 실험 4 에서 **"회전" 이 아니라 저차원·부분 겹침**으로 판명 |
| "z 와 h 가 같다" | 천장 (포화) |
| "목적함수 때문이다" | **discussion 한 문단으로만.** 재학습 없이 검증이 안 되는 원인을 축으로 두면 스스로 못 갚는 빚이 된다 |
| "predictor 출력에 정렬 제약이 없다" | JEPA 손실이 `\|p − LN(h)\|` 로 **이미 encoder 출력에 직접 회귀**한다 |
| "IntPhys 2 에서 chance 근처" | V-JEPA 2-h 는 57.51 로 chance 위다 (human 96.4) |
| "직관물리는 창발하지 않았다" | 반박 대상은 **그 측정에 쓰인 readout** 이다 |
| "물리를 이해하지 못한다" | **L1 testbed 전까지 금지.** 지금 데이터는 외삽 능력과 물리 지식을 안 가른다 |
| **α · 보정 · 헤지 계수** | **인용 금지** (사용자 지시가 있을 때까지) |

## 8. 함정 (가장 비쌌던 것들)

### 8-1. 인프라

- **sbatch 자기제출 폭주** — `SLURM_BATCH_SCRIPT` 가 batch job 에서 비어 모든 job 이 제출 분기를 다시 탔다.
  세대마다 ×7 로 **9,924 개**. → **`WMA_RUN=1`** 로 갈린다. 교훈: **SLURM 이 무엇을 넣어 주는지에 기대지 말 것. 표시는 우리가 붙인다**
- **exit 0 on failure** — `mp.Process(...).start()` 후 join 을 안 하면 rank 가 죽어도 0 을 반환하고 `afterok` 가 풀린다
- **DDP split-brain** — `init_distributed` 가 bind 실패를 삼키고 조용히 `world_size=1` 로 폴백해 두 job 이 섞인다
- **캐시는 `video_ids` 완전 일치를 요구한다** — **상위집합·부분집합 재사용이 안 된다.**
  묶어서 뽑을지 나눠서 뽑을지를 **인덱스를 만들 때** 정해야 한다
- **토큰 캐시가 조용히 재사용된다** — `matches()` 는 `video_ids`/토큰수/dtype 만 본다.
  **체크포인트·해상도·autocast·재렌더는 서명에 없다.** 데이터를 다시 만들면 캐시도 반드시 치울 것
- **`features:` 블록 누락** → `cfg["surprise"]` 폴백 → `cache_dir` KeyError. **surprise 채점을 다 끝낸 뒤에 죽는다** (가장 아까운 실패)
- **`data.resolution != model.img_size`** → 작으면 CUDA assert, 크면 **에러 없이 엉뚱한 구간을 잘라 쓴다**
- **prep 과소추출** — `probing.runs` 를 줄이면 캐시에 뽑히는 표현도 줄어든다. **runs 는 두고 `num_epochs` 만 1 로**
- **probing `batch_size` 는 global batch** (DDP 가 rank 당 1/ws 로 나눔). surprise 의 것은 rank 당

### 8-2. 수치·해석

- **DDP probing 은 실행마다 흔들린다.** 결정론이 필요하면 `GPUS=1`. FP16 batching 은 근접 tie 를 뒤집는다
- **bf16 predictor 출력은 batch 구성에 따라 달라진다** (같은 clip, batch 1 vs 4 에서 상대 L1 0.049)
- **CI 폭 0 인 셀은 버그가 아니다** — 100%/0% 상쇄 구조
- **`(조건, k)` 로 쪼개면 비대각이 방향당 n=4 다.** 개별 칸을 읽지 말 것. **그 칸들의 함수도 같은 잡음을 물려받는다**
- **probe head 가 과대용량** (49.3M) → contextF/targetF 는 `train_acc=1.000` 으로 포화.
  **천장에 안 닿은 건 이식 줄뿐이므로 대조는 이식 줄에 한해 읽을 것**
- **팔을 가로지르는 이식 실패는 증거가 아니다** — 기대값이다 (attention query 가 위치 특이적)
- **학습된 readout(자) 은 대상이 없어도 값을 낸다** — 기본값이 데이터의 의미 있는 자리와 겹치면 하루를 잘못 읽는다.
  자로 읽은 값에는 **attention 질량 · 기본값 거리 · 파라미터 없는 교차검증**을 붙인다
- **`summary.json.probing[].evals[].overall` 은 eval 목록 전체 평균이다** — self 는 `per_group` 에서 읽는다 (§5-4)
- **`sed -i` 를 쓰지 않는다** — 2026-08-28 에 `datasets.md` 에서 한 줄을 바꾸려던 `sed` 가 **섹션 4 개를 통째로 지웠다.** 여러 줄짜리 md/yaml 은 Python 으로
- **`.gitignore` 가 `*csv`, `*.json`, `*.png`, `*.pt`, `z_exp/`, `data_gen/`, `checkpoint/` 를 전부 막는다** →
  새로 만든 index·figure 는 **untracked 가 정상**이고 `git checkout` 으로 되돌릴 수 없다.
  2026-08-28 에 `IntPhys-Like_data/` 아래 리포트·figure 가 **git 추적 0 이라 복구 불가능하게 사라졌다**

### 8-3. 필수 검증 루틴

- **byte-identical context 감사** — 전 matched pair 의 16 context 프레임 픽셀 단위 전수 검사 (mismatch 0)
- **`|z(p)|` 단독 채점이 정확히 0.00% (전 쌍 tie)** 로 나오는 것이 파이프라인 정합성 증거
- **수치는 문서가 아니라 `summary.json`/`report.json` 에서 다시 계산해 검증하고, 그렇게 했다고 문서에 명시**

1. **어느 beat 를 세우는가.** 못 대면 그렇게 말한다
2. **결과가 어느 쪽이어도 beat 가 서는가.** 한쪽 결과로만 서면 확증편향이다
3. **이미 답이 있는가** (§7-1 기각표, `SYNTHESIS` §9)
4. **교란이 남는가.** 남으면 그 결과로 **못 하는** 주장을 미리 적는다
5. **재학습이면 ablation 이 함께 설계돼 있는가.** "그냥 더 학습시킨 것 아닌가" 를 무엇이 막는지 먼저 답한다
6. **표본이 결론을 낼 크기인가** (v11: 조건×위반 672 쌍 / k 까지 168 쌍 / 방향당 16 쌍)
7. **corner case 인가, 어느 use case 에 닿는가** — **use case 는 anticipation 이다.** 못 대면 beat 8 에 못 들어간다

> **동의만 하고 돌리는 것이 가장 큰 실패다.** 하루에 GPU 수 시간을 그렇게 태운 적이 있다.
> 반대로 사용자가 이유를 대면 그건 결정이다 — 한 번 말하고 진행한다.
