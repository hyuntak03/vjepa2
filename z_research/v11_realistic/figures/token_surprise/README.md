# token_surprise — 토큰별 surprise 차 GIF (2026-10-07)

**무엇.** 채점 surprise 는 영상마다 `mean_{토큰, 채널} |p − LN(h)|` 하나다. 그 평균을 풀어 미래 토큰 (8 튜블릿 × 16 × 16) 마다
`Δ = |p − h_imp| − |p − h_pos|` (채널 평균) 를 원본 프레임 위에 겹쳤다. **토큰 평균 Δ = 채점 차 s_imp − s_pos** 와 정확히 같은 양이다.
파랑 = Δ > 0 (그 토큰이 불가능 쪽을 더 놀랍게 본다 = 정답 방향) · 주황 = Δ < 0 (틀린 방향).

**그리는 규칙.**
- 한 줄 = matched pair 하나 (문맥이 픽셀 단위로 같아 p 가 같다). 셋째 칸은 두 clip 프레임을 50/50 겹친 위에 Δ.
- 문맥 16 샘플은 덮지 않는다 (채점 토큰이 미래에만 있다). 미래 샘플 2 장 = 튜블릿 하나라 같은 지도.
- 토큰 칸은 그대로 (최근접 확대) — 모델은 288 → 256 전체 리사이즈라 16 × 16 이 화면 전체를 덮는다.
- 색 눈금 vmax = 두 세트 미래 토큰 |Δ| 의 99 분위 (**0.238**, 모든 GIF 공통).
  불투명도 = 0.9 · (|Δ| / vmax)^1.5 — 배경의 작은 Δ 를 옅게 보이게 한 **표시 규칙**이다 (값은 그대로).
- 예시 = 조건마다 쌍 Δ 평균이 그 조건 중앙값에 가장 가까운 block (A 방향 기준, 전형 사례). 골라낸 극단이 아니다.

## 읽은 것 — 쌍 Δ 의 대부분은 물체 토큰이 아니라 배경 토큰에서 온다

- 토큰 하나로 보면 물체 자리가 배경보다 2–3 배 크게 갈린다 (가림 없음 0.12–0.17 vs 0.04–0.08). 그래도 물체 토큰이 3–6 % 뿐이라
  **합은 배경이 정한다** (static_visible A 하나만 예외). 물체가 있느냐 없느냐가 h 를 화면 전체에서 조금씩 바꾸고 (target encoder 는 clip 전체를 본다),
  그 작은 차이들의 합이 채점이 된다. CLAUDE.md §6 "물체 토큰만 보면 됨 → 더 나빠짐" 과 같은 방향이다
- **ledge**: 떨어지는 공 자리에서 주황 (p 가 거기 공을 두지 않는다). 배경 기여 −0.0079 가 물체 기여의 3 배 — 선반 앞면 · 바닥 토큰도 낙하 쪽을 더 멀게 본다
- **static_occlusion**: 물체 자리 |Δ| 가 배경과 같다 (0.042 / 0.043). 수레가 다시 보이는 칸에서 p 가 "물체 있음" 과 "빈 바닥" 에서 **똑같이 멀다** —
  채점이 거의 비기는 것 (쌍 Δ +0.0007) 과 같은 모습. p 가 그 자리에 무엇을 두는지 (예: 문맥 끝의 세워진 가림막) 는 이 지도로 못 가른다
- ⚠️ 물체 토큰을 3×3 이웃으로 잡았다. 물체가 칸보다 작아 (35.6 px ≈ 2 칸) 이웃 정의에 따라 기여 몫이 조금 바뀐다. 결론 (배경이 합을 정함) 은 그 폭 안에서 안 바뀐다고 **가정**했고, 이웃 크기를 바꿔 확인하지는 않았다

## 배경 토큰은 왜 Δ 를 갖나 (2026-10-07) — `background_checks.md`

질문 (사용자): "배경은 픽셀상 그대로인데 왜?" 두 검사 (`z_research/scripts/analysis/token_surprise_background.py`).

**1. 배경 픽셀은 완전히 같지 않다 — 그러나 그게 원인은 아니다.** 미래 토큰의 픽셀 최대 차 (모델 입력 256 해상도, 0–255):
- 완전히 같은 토큰 12–41 % · **1–4 차이 51–84 %** (눈에 안 보이는 렌더 차이 — 조명 · 그림자 · 반사가 물체를 따라 화면 전체에서 조금 바뀐다) ·
  뚜렷한 차이 (> 16) 는 2–7 % 뿐 (물체 + 그림자)
- **픽셀이 완전히 같은 토큰의 |Δ| (0.038–0.078) 가 1–4 차이 토큰 (0.043–0.080) 과 거의 같다.** 픽셀 차가 Δ 를 만드는 게 아니다.
  target encoder 는 clip 전체 (32 장 × 256 칸) 를 attention 으로 섞으므로, 물체가 있느냐 없느냐가 **픽셀이 같은 칸의 h 까지** 바꾼다

**2. 배경 Δ 는 잡음이 아니라 같은 판단의 메아리다.** 쌍마다 배경 기여의 부호가 쌍 전체 부호와 **96.7–100 %** 같다.
틀리는 쌍 (ledge · 등가속 가림 A) 은 물체 토큰과 배경 토큰이 **둘 다 100 % 틀린 방향**, 맞는 쌍은 둘 다 맞는 방향.
물체 토큰이 3–6 % 뿐이라 합은 배경이 정하지만, 방향은 물체 자리와 같다.

**그래서 읽는 법.** 잘 되는 경우 (정지 · 가림 없음) 는 물체 자리가 **크고 맞는 방향으로** 켜지고 (토큰당 |Δ| 0.13–0.17), 배경이 같은 방향으로 따라온다.
실패는 물체 자리가 **틀린 방향으로** 켜지거나 (ledge · 이동 가림 A: 물체 기여 > 0 인 쌍 0–7 %) **아예 안 켜진다** (정지 가림: 물체 |Δ| 0.048 = 배경 0.043).
배경은 따로 원인이 아니라 그 판단을 화면 전체로 퍼뜨린다.
- ⚠️ "물체가 있다/없다가 h 의 배경 칸을 바꾼다" 는 h 쪽 이야기다. p 의 배경 칸이 어느 세계 쪽인지가 Δ 의 부호를 정한다 — 두 쪽을 따로 분리해 재지는 않았다
- ⚠️ 1–4 픽셀 차가 Δ 를 조금 보탤 수 있다 (같은 토큰보다 |Δ| 가 0.001–0.01 크다). 렌더러 차이를 없앤 데이터 (배경 프레임 고정 합성) 로 가르지 않았다
